## 1. MVP 概述

### 1.1 背景

供应商拥有多个品牌和多个洗化品类货源，需要建立自有微信私域交易阵地，并通过外部一级代理扩大私域触达。消费者在微信小程序内完成浏览、下单、履约与售后；一级代理通过独立工作台推广总部商品、查看归属客户与订单、核对佣金并申请提现；总部通过电脑管理后台统一管理商品、价格、库存、收款、发货、售后、代理与财务审核。

本版本不是多商户平台。商品和交易均由总部经营主体统一承接，代理不拥有商品、价格、库存、订单履约或售后处理权。

### 1.2 核心验证目标

1. 私域客户愿意通过供应商自有小程序完成商品浏览和自主下单。
2. 总部能够通过管理后台独立完成商品、库存、订单、履约、售后、代理和提现审核。
3. 一级代理能够使用分享二维码或链接推广商品，并准确查看脱敏的归属客户、归属订单与佣金。
4. 首次确认成功的代理关系能够长期绑定消费者，订单提交记录归因候选，并在支付成功时复核代理状态后冻结代理、佣金比例和佣金基数快照。
5. 系统能够可靠完成库存锁定、模拟支付、退款、佣金入账、退款冲正和线下提现闭环。

### 1.3 北极星指标

北极星指标为“有效支付订单数”：订单至少存在一笔成功支付记录，且当前剩余实付金额大于 0；全额退款订单不计入当前有效支付订单存量。

渠道辅助指标包括：

- 代理归属有效支付订单数；
- 代理归属净销售额；
- 新增绑定客户数；
- 已入账佣金与已支付提现金额。

经营报表按 Asia/Shanghai 自然日或自然月统计，数据库时间统一保存为 UTC。

### 1.4 MVP 原则

- 完整交易和代理佣金闭环优先于复杂营销玩法。
- 总部统一经营权优先于代理自治。
- 单层、可审计的代理归属优先于多级关系链。
- 数据准确、库存一致和账本不可篡改优先于自动化结算。
- 第三方支付、退款、物流和微信正式资质未就绪时，通过 Provider 接口与 Mock 实现保持可演示、可替换。

| 总部管理后台 | 订单、履约、售后 | P0 | 查询、发货、物流维护、售后审核和模拟退款 |

| 总部管理后台 | 提现审核 | P0 | 审核、拒绝、线下打款；付款时二次验证后短时查看/复制完整收款账号；凭证上传和标记已支付 |

### 2.2 首期明确不启用

- 多级代理、二级代理、团队关系和上下级分佣；
- 代理自行招募或管理下级代理；
- 代理进货、批发采购、独立店铺或独立商户结算；
- 代理自定义商品、价格、库存、优惠、发货和售后；
- 代理代客下单或查看完整手机号、完整收货地址；
- 自动向银行卡或微信零钱打款；
- 多级会员价格、会员等级成长、优惠券、积分和新用户优惠；
- 拼团、秒杀、直播、商品视频和 AI 客服；
- 第三方物流实时轨迹和电子面单；
- Excel 导入导出和自定义报表中心；
- 多商户、多仓库、多包裹、拆单与合单；
- 正式微信支付、退款及真实微信授权登录。

### 2.3 首期业务边界

- 三端分别为总部管理后台、一级代理工作台、消费者微信小程序。
- 只有三类人员角色：超级管理员、一级代理、消费者；游客属于登录状态，不是人员角色。
- 代理关系严格单层。超级管理员创建所有一级代理，一级代理没有下级。
- 单商户、单仓库、单包裹、全场包邮。
- 总部统一商品、零售价、库存、收款、发货、售后和退款。
- 一个商品可有多个 SKU；成交价格和库存以 SKU 为准。
- 消费者首次通过有效代理二维码或链接登录后建立长期绑定；已绑定用户访问其他代理链接时不改绑。
- 只有超级管理员可转移消费者代理归属；转移只影响未来订单，历史订单快照和佣金不变。
- 未绑定消费者的订单为直营订单 `DIRECT`，不产生代理佣金。

## 3. 角色与核心任务

| 人员角色 | 系统代码 | 所属端 | 核心目标 | 主要权限 |
|---|---|---|---|---|
| 超级管理员 | `SUPER_ADMIN` | 总部管理后台 | 统一经营商城并管理渠道 | 全部商品、价格、库存、订单、发货、售后、客户、代理、提现、审计和配置 |
| 一级代理 | `AGENT_ADMIN` | 一级代理工作台 | 推广总部商品并核对收益 | 推广授权商品；只读查看本人归属的脱敏客户、订单、佣金；维护本人银行卡；申请提现 |
| 消费者 | `CUSTOMER` | 微信小程序 | 购买商品并跟踪服务 | 浏览、收藏、购物车、地址、订单、支付、物流、售后和只读查看服务代理 |

权限硬边界：一级代理不能登录总部后台；超级管理员不使用代理工作台经营代理业务；消费者不能访问任何经营端。

## 4. 核心用户旅程

### 4.1 代理开通与首次登录

~~~text
超级管理员创建一级代理
  → 设置佣金比例和初始状态
  → 系统生成登录账号、临时密码和唯一邀请码
  → 代理首次登录
  → 强制修改密码
  → 进入工作台并维护银行卡
~~~

### 4.2 代理推广与消费者绑定

~~~text
代理选择授权商品或商城主页
  → 生成带唯一邀请码的二维码/链接
  → 消费者打开小程序
  → 系统暂存最后一个有效代理邀请码，30 分钟内新有效码覆盖旧待确认码
  → 消费者登录
  → 未绑定时展示服务关系确认
  → 确认后长期绑定该一级代理；拒绝则清空待确认码并保持直营
  → 已绑定时忽略新的邀请码并显示当前服务代理
~~~

### 4.3 消费者购买与佣金入账

~~~text
消费者浏览并选择 SKU
  → 提交订单，记录当前有效绑定对应的归因候选
  → Mock 支付成功时再次校验代理 ACTIVE
  → 校验通过：冻结代理ID、佣金比例、佣金基数和预计佣金
  → 校验不通过：订单转为 DIRECT，不产生佣金
  → 订单进入待发货，已冻结佣金记为预计
  → 总部发货，消费者确认收货或总部兜底完成
  → 订单完成
  → 佣金立即进入可提现余额
~~~

### 4.4 退款与佣金冲正

~~~text
完成前退款
  → 按退款商品实付金额减少预计佣金

完成后退款
  → 生成不可篡改的负向佣金流水
  → 可提现余额可能变为负数
  → 负余额期间禁止新提现，后续佣金优先抵扣
~~~

### 4.5 代理提现

~~~text
代理选择已绑定银行卡并提交提现
  → 金额从可提现转入冻结
  → 超级管理员审核
  → 拒绝：冻结金额退回可提现
  → 通过：总部线下银行转账
  → 上传付款凭证并标记已支付
  → 提现完成，保留申请和银行卡快照
~~~

## 5. 核心功能集

### 5.1 消费者小程序

1. 首页展示 Banner、一级分类、热销和新品，分类由总部自由增删改排序。
2. 搜索支持商品名称关键词、品牌和分类筛选。
3. 商品详情展示图片、名称、品牌、介绍、规格、成分、用法、零售价、库存、销量和收藏。
4. 游客可浏览并维护本地购物车；收藏、地址、订单、支付和售后需要登录。
5. 首次有效代理邀请码在登录成功后触发绑定确认；价格、支付和售后主体始终为总部商城。
6. 已绑定用户只能查看当前服务代理，不能自行改绑或解除。
7. 创建订单前重新校验商品状态、价格、地址和库存；成功后锁库存 30 分钟。
8. 订单支持待付款、待发货、运输中、已完成和退款售后状态。
9. 用户可在有效期内发起仅退款或退货退款。

### 5.2 一级代理工作台

1. 账号由超级管理员创建，使用账号密码登录，首次登录必须修改临时密码。
2. 首页展示本人归属净销售额、有效订单、绑定客户、预计佣金、可提现余额、冻结金额和负余额警示。
3. 推广中心默认展示全部当前及未来在售商品；总部切换为自定义授权时仅展示白名单商品，可复制链接、下载或展示二维码。
4. 当前客户列表仅显示仍归属本人的昵称、手机号后四位、城市、绑定时间、订单次数和消费汇总；客户转出后从列表移除，代理只可在历史订单中查看支付时冻结的脱敏快照。
5. 订单列表仅显示本人归属订单，地址只显示城市，不展示详细收货地址。
6. 佣金列表区分预计、可提现、退款冲正和提现冻结相关流水，禁止人工编辑。
7. 代理可维护本人银行卡并提交提现申请；保存后银行卡页面和日志只显示掩码。
8. 代理无权更改商品价格、库存、订单状态、物流、退款、售后或客户归属。

### 5.3 总部管理后台

1. 超级管理员通过账号密码登录并拥有全部经营权限。
2. 看板展示今日、本月、累计净销售额，订单、客户、渠道销售和待办，并通过报告标签提供日销售、月销售、商品销量排行和客户消费排行。
3. 商品管理覆盖品牌、分类、商品、图片、SKU、价格、库存、上下架和推荐。
4. 订单与售后由总部统一处理，代理无履约权限。
5. 超级管理员可创建、编辑、启用或停用一级代理，设置代理专属佣金比例，并在“全部在售商品”和“自定义白名单”两种授权模式间切换。
6. 代理比例变更只影响变更后支付成功并冻结归因的订单，已支付订单继续使用快照比例。
7. 超级管理员可转移消费者代理归属；操作必须二次确认、填写原因并写入审计日志。
8. 提现审核支持通过、拒绝、付款凭证上传和标记已支付；打款由线下银行转账完成。完整收款账号仅在付款环节由超级管理员二次验证后一次性短时查看或复制，全部留痕并在超时后自动遮蔽。
9. 账户与业务规则设置提供最低提现金额和售后申请天数配置；修改只影响后续新申请或后续完成订单，不回写历史事实。

## 6. 关键业务规则

### 6.1 代理归属

- 每个一级代理拥有唯一邀请码；邀请码同时具有独立启停/有效期，代理停用时不可使用。
- 未登录且未绑定用户只暂存最近一个有效邀请码，TTL 为 30 分钟；TTL 内新的有效码覆盖旧待确认码。
- 登录后用户必须明确确认或拒绝：确认成功才创建长期绑定；拒绝立即清空待确认码并保持 `DIRECT`。
- 已有长期绑定的消费者忽略所有新邀请码；消费者无权自行改绑。
- 已绑定用户访问其他代理链接时保持原绑定，不覆盖、不提示改绑。
- 超级管理员转移归属只影响后续创建的订单；历史订单和佣金账本不可回写。
- 代理停用后禁止登录和新绑定。订单提交仅记录归因候选，支付成功时再次复核代理 `ACTIVE`；支付前停用则最终按 `DIRECT` 处理且无佣金。
- 支付成功后才冻结订单代理与佣金快照；支付后停用不影响已冻结的 `EXPECTED`，订单完成时仍正常进入可提现。
- 重新启用只影响未来业务：未被转移的长期绑定恢复归因资格；邀请码仅在自身仍启用且未过期时恢复；停用期间已经按 `DIRECT` 支付的订单不追溯。

### 6.2 佣金

- 超级管理员为每个代理设置佣金比例，范围和精度在技术设计阶段固化，建议 0% 至 100%，保留四位小数。
- 佣金基数为归属订单项的净商品实付金额，不含运费；首期运费为 0。
- 订单提交时记录归因候选；支付成功时复核代理 `ACTIVE` 并冻结代理 ID、当时佣金比例、佣金基数和预计佣金快照。
- 支付成功后佣金进入 `EXPECTED`；确认收货或总部兜底完成后立即转为 `AVAILABLE`。
- 完成前部分退款按退款商品实付金额同比例减少预计佣金；完成前全额退款将 `EXPECTED` 标记为 `CANCELLED`。
- 完成后退款保留原 `AVAILABLE` 记录并追加 `REFUND_DEBIT` 负向佣金流水，不删除、不覆盖原入账记录。
- 负余额阻止新提现；未来佣金先抵扣负余额后再形成可提现余额。

### 6.3 提现

- 提现最低金额默认 100 元，由总部业务规则设置配置；修改仅影响之后提交的申请，首期不收手续费。
- 同一代理同一时间最多存在一笔待审核或已通过待付款的提现申请。
- 提交提现时校验可提现余额、负余额、银行卡和代理状态，并将金额转入冻结。
- 审核拒绝必须填写原因，冻结金额退回可提现余额。
- 审核通过后不可由代理撤回；总部完成线下银行转账后上传付款凭证并标记已支付。
- 提现记录保存银行卡快照；银行卡号加密存储，默认界面、接口响应和日志均掩码显示。
- 只有 `SUPER_ADMIN` 在已通过待付款的提现详情中可二次验证后短时解密并一次性查看/复制完整账号；每次查看、复制和超时遮蔽均记录审计，离开页面或超时立即恢复掩码。

### 6.4 价格、库存、订单与售后

- SKU 零售价是首期唯一成交价，服务端是最终计价来源。
- 金额使用精确十进制保存，API 以十进制字符串返回。
- 可售库存 = 实物库存 - 锁定库存；创建订单锁定，支付后结转，取消或超时释放。
- 订单保存商品、SKU、单价和数量快照；代理归因候选在提交时记录，最终代理与佣金快照在支付成功时冻结。
- 用户可取消待付款订单；已支付订单必须走售后流程。
- 发货必须录入承运商和运单号；确认收货后订单完成。
- 后台兜底完成必须填写原因并记录审计。
- 售后申请期默认 7 个自然日，由总部业务规则设置配置并在订单完成时确定；该期限不延迟佣金入账。
- 退款金额不得超过订单项剩余可退实付金额，佣金按同一订单项退款事实冲正。

## 10. 风险与应对

| 风险 | 影响 | MVP 应对 |
|---|---|---|
| 代理被误解为多级或独立商户 | 范围膨胀、账务复杂 | 文档、页面和权限统一使用“一级代理”，禁止下级和独立经营 |
| 归属候选被错误覆盖或过期 | 渠道争议 | 仅未绑定游客保存最后有效码、TTL 30 分钟、明确确认/拒绝、支付时最终复核 |
| 代理越权访问客户或订单 | 隐私泄露 | 服务端按代理归属过滤，字段脱敏，禁止相信前端筛选条件 |
| 退款后佣金已被提现 | 平台形成应收 | 负向账本、允许负余额、冻结新提现、未来佣金抵扣 |
| 线下打款凭证缺失 | 财务难审计 | 审核与付款分状态，标记已支付必须上传凭证 |
| 代理停用后的存量订单争议 | 佣金口径不一致 | 支付时最终复核；支付后停用不影响已冻结佣金；重启不追溯停用期订单 |
| 付款环节完整卡号泄露 | 财务与隐私风险 | 默认掩码、二次验证、短时一次性查看/复制、自动遮蔽和全量审计 |
| 并发下单导致超卖 | 财务与履约损失 | 事务、条件更新、锁库存、幂等和并发测试 |
| 微信资质未提供 | 无法真实登录和支付 | Provider 隔离，设计阶段和演示环境使用 Mock |

## 11. MVP 完成标准

1. 三端页面和权限与 PRD 页面编号一致。
2. 超级管理员可创建一级代理、设置比例、停用账号并查看审计。
3. 代理首次登录必须改密，且只能查看本人归属的脱敏客户和订单。
4. 未绑定游客的最后有效邀请码按 30 分钟 TTL 覆盖，登录后可确认或拒绝；已绑定用户不会被其他链接覆盖。
5. 订单提交记录归因候选，支付成功复核代理状态后才冻结代理、比例、基数和金额；支付前停用转为直营。
6. 支付后停用不影响已冻结预计佣金；收货后进入可提现，完成前全退取消预计，完成后退款追加 `REFUND_DEBIT`。
7. 负余额阻止提现，后续正向佣金可自动抵扣负余额。
8. 提现可完成提交、审核、二次验证短时查看收款账号、拒绝退回、线下付款、凭证和已支付闭环。
9. 总部可配置代理商品授权模式、最低提现金额和售后申请天数，并保留变更审计。
10. 总部可查看日/月销售报表、商品销量排行和客户消费排行，不依赖 Excel 导出。
11. 总部可完成商品、库存、订单、发货、售后和客户管理，代理无经营或履约写权限。
12. 消费者可完成浏览、购物车/立即购买、Mock 支付、物流、确认收货与两类售后。
13. 代理工作台在 390px、1024px 和 1440px，后台在 1024px 和 1440px，小程序在 375px 和 414px 无关键遮挡或横向溢出。
14. 关键权限、归属、交易、佣金、银行卡与提现操作均可审计。
