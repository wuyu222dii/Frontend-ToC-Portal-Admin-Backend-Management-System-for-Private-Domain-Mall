## 1. 产品概述

### 1.1 产品定位

洗化产品私域商城是由供应商总部统一经营、由一级代理推广、由终端消费者购买的私域交易系统。系统包含：

1. 消费者微信小程序：商品浏览、下单、履约与售后。
2. 一级代理工作台：推广、归属数据查询、佣金核对与提现申请，支持 PC 和移动 H5。
3. 总部管理后台：商品、价格、库存、订单、收款、履约、售后、客户、代理和提现的统一管理。
4. 后端 API 与 MySQL 数据层：提供三端权限、交易、归属和账务事实来源。

系统采用单商户、单仓、总部统一履约模式。一级代理不是商户、供应商或仓库，只是单层推广合作方。

### 1.2 业务问题

1. 消费者缺少可在微信内自主查看多品牌、多品类商品并完成购买的入口。
2. 总部缺少统一维护商品、SKU 库存、订单、发货、客户和售后的经营工具。
3. 一级代理缺少标准推广物料、渠道归属、订单与佣金核对工具。
4. 客户归属、佣金计算、退款冲正和线下提现若依靠人工表格，容易产生争议和账务错误。
5. 客户隐私和渠道数据需要严格按代理隔离，避免越权访问。

### 1.3 产品目标

- 打通消费者从浏览到收货、售后的交易闭环。
- 让总部可独立完成商城和一级代理的日常经营管理。
- 让代理可自助推广并查看本人渠道数据，不获得经营和履约权限。
- 建立 30 分钟归因候选、首次确认绑定、支付时最终归因快照、全代理统一商品佣金规则、不可变佣金流水与可审计提现闭环。
- 为真实微信登录、支付、退款及未来营销能力保留替换边界。

### 1.4 非目标

当前版本不建设多级分销、二级代理、团队佣金、代理进货、代理独立店铺、代理定价、代理库存或自动打款；也不支持代理独立比例、“代理 × SKU”、固定金额、阶梯或限时活动佣金。优惠券、积分、会员等级、多级会员价格、拼团、秒杀、视频、AI 客服、Excel 导出、多仓和多包裹亦不进入当前版本。

## 2. 成功指标

### 2.1 北极星指标

北极星指标为有效支付订单数：存在成功支付且当前剩余实付金额大于 0 的去重订单数。全额退款订单自退款成功后不计入当前有效订单存量，历史趋势由支付与退款事件重算。

### 2.2 经营与渠道指标

| 指标 | 定义 | 展示端 |
|---|---|---|
| 今日净销售额 | 今日成功支付金额减今日成功退款金额 | 总部 |
| 本月净销售额 | 本月成功支付金额减本月成功退款金额 | 总部 |
| 累计净销售额 | 全部成功支付金额减全部成功退款金额 | 总部 |
| 有效支付订单数 | 成功支付且剩余实付大于 0 的订单数 | 总部、代理本人 |
| 商品净销量 | 成功支付数量减成功退款数量 | 总部 |
| 客户总数 | 已创建消费者账户的去重人数 | 总部 |
| 新增绑定客户数 | 周期内首次形成有效代理绑定的消费者数 | 总部、代理本人 |
| 代理归属净销售额 | 有代理快照订单的支付金额减退款金额 | 总部、代理本人 |
| 预计佣金 | 已支付未完成订单的当前佣金预计值 | 总部、代理本人 |
| 可提现余额 | 已入账佣金、冲正和提现冻结/释放后的当前可用余额 | 总部、代理本人 |
| 已支付提现 | `PAID` 提现申请金额合计 | 总部、代理本人 |

所有经营日期按 Asia/Shanghai 计算；数据库时间使用 UTC。金额指标必须可由支付、退款、佣金与钱包流水复算，不允许后台直接修改汇总值。

### 2.3 设计与工程验收基线

- 小程序 375px、414px；代理工作台 390px、1024px、1440px；总部后台 1024px、1440px 无关键遮挡和横向页面溢出。
- 三端页面覆盖加载、空、错误、禁用、成功和权限拒绝状态。
- 最后一件库存并发下单最多成功一单，库存不出现负数。
- 支付、退款、发货、佣金结转、提现审核和付款标记均须幂等。
- 代理不能通过修改请求参数访问其他代理或完整客户隐私。
- 订单提交的归因候选和支付成功逐订单项冻结的代理、佣金规则版本/来源、分类、商品、SKU、比例、佣金基数与金额快照均可追溯，且不可被后续配置覆盖。

## 3. 用户、角色与权限

### 3.1 人员角色定义

| 角色 | 系统代码 | 登录入口 | 核心任务 |
|---|---|---|---|
| 超级管理员 | `SUPER_ADMIN` | 总部管理后台 | 统一经营、配置代理、处理履约售后、审核提现和审计风险 |
| 一级代理/管理员 | `AGENT_ADMIN` | 一级代理工作台 | 推广商品、查看本人渠道数据、核对佣金和申请提现 |
| 用户/消费者 | `CUSTOMER` | 微信小程序 | 浏览、购买、查看履约、收藏、地址与售后 |

角色迁移约定：原方案的总部最高权限统一映射为 `SUPER_ADMIN`；总部内部普通操作角色从当前范围移除。未来总部普通员工必须作为第四角色独立设计，不得复用 `AGENT_ADMIN`。

## 4. 产品范围

### 4.1 当前版本范围内

- 消费者小程序：首页、分类、搜索、商品详情、收藏、购物车、登录、代理绑定确认、地址、订单、Mock 支付、物流、确认收货、售后、个人中心。
- 一级代理工作台：账号登录、首次改密、看板、推广商品与物料、脱敏客户、归属订单、售后进度、佣金账本、钱包、银行卡、提现申请和记录。
- 总部管理后台：登录、看板、日/月销售报表、商品销量排行、客户消费排行、品牌、分类、商品、SKU、图片、Banner、库存、订单、发货、售后、客户、一级代理、客户归属转移、统一佣金规则、业务规则、提现审核、审计。
- 公共业务：单层归属、订单代理快照、全代理统一商品佣金规则、逐订单项佣金预计与入账、退款冲正、负余额、提现冻结与线下付款凭证。

### 4.2 当前版本范围外

- 多级代理、二级代理、下级招募、团队关系、团队佣金；
- 代理进货、批发采购、代理库存、独立店铺、独立收款和独立售后；
- 代理自定义价格、优惠、商品或会员等级；
- 自动打款、微信零钱提现、提现手续费和发票税务自动处理；
- 代理专属比例、“代理 × SKU”佣金、固定金额佣金、销量/金额阶梯佣金和限时活动佣金；
- 正式微信登录、支付、退款；
- 优惠券、积分、新人优惠、会员等级、会员价；
- 拼团、秒杀、直播、商品视频、评价、问答、AI 客服；
- Excel 导入导出、自定义报表、多商户、多仓、多包裹与运费模板。

### 4.3 依赖与上线门禁

- 设计和演示环境使用 Mock 微信登录、支付和退款，生产环境不得出现选择支付结果的 Mock 操作。
- 上线前补齐微信 AppID、AppSecret、商户号、证书与类目资质。
- 上线前完成代理合作协议、佣金税务与结算政策、银行卡处理授权、隐私政策、用户协议和售后规则审核。
- 线下付款操作需确定真实财务责任人、审批制度、付款凭证保留周期与异常追款流程。
- 真实商品、图片版权、配送范围和售后地址必须在上线前提供。

## 6. 核心业务流程

### 6.1 代理开通与账户安全

~~~text
超级管理员创建代理并设置账号与状态
  → 代理统一继承平台商品佣金规则，无独立比例
  → 系统生成唯一账号、临时密码、邀请码
  → 代理使用临时密码登录
  → 强制修改密码
  → 修改成功后签发正常会话并进入概览
  → 代理维护本人银行卡
~~~

约束：临时密码会话只能访问改密和退出；停用代理不得登录；总部重置密码后再次强制改密。

### 6.2 推广与首次绑定

~~~text
代理在 AGT-03 选择商城主页或授权商品
  → 系统生成包含有效邀请码的二维码/链接
  → 未登录且未绑定消费者打开小程序
  → 系统校验邀请码、代理 ACTIVE、邀请码启停和有效期
  → 保存待确认码，TTL 30 分钟；新的有效码覆盖旧候选
  → 消费者浏览并在受保护动作时登录
  → 候选仍有效：展示代理名称与明确的确认/拒绝选择
  → 用户确认：创建长期绑定并返回原操作
  → 用户拒绝：清空待确认码，按直营身份继续购物
~~~

已绑定消费者打开其他代理链接时，系统忽略新邀请码并维持原关系。过期、无效或停用代理的邀请码不能覆盖当前有效待确认码。

### 6.3 浏览、下单与归属快照

~~~text
首页/分类/搜索 → 商品详情 → 选择 SKU
  → 购物车结算或立即购买
  → 登录并选择地址
  → 服务端校验商品、价格、库存和客户绑定
  → 提交订单：ACTIVE 绑定记录代理归因候选；无有效绑定记录 DIRECT 候选
  → 创建待付款订单并锁库存 30 分钟
  → Mock 支付成功时再次复核候选代理 ACTIVE
  → 复核通过：逐订单项按 SKU 覆盖、商品一级分类默认、平台默认顺序解析支付时有效比例
  → 冻结代理及规则版本/来源、一级分类、商品、SKU、比例、基数和预计佣金
  → 复核失败或提交时无候选：最终冻结为 DIRECT，不产生佣金
  → 订单待发货；仅成功冻结的佣金进入 EXPECTED
~~~

### 6.4 履约与佣金入账

~~~text
支付成功并冻结归因 → 总部待发货
  → 超级管理员录入承运商和运单号
  → 运输中
  → 消费者确认收货 或 总部填写原因兜底完成
  → 订单完成
  → 当前预计佣金转为可提现
~~~

同一订单的“支付成功与最终归因”“订单完成与佣金入账”分别须在同一业务事务或可靠事件处理中实现，重复请求不得重复冻结或重复入账。代理在支付成功后停用，不影响已经冻结的 `EXPECTED`，订单完成时仍正常入账。

### 6.5 售后与佣金冲正

~~~text
消费者选择可退订单项和数量
  → 提交仅退款或退货退款
  → 总部审核并完成 Mock 退款
  → 更新订单项剩余实付
  → 完成前退款：减少预计佣金
  → 完成后退款：新增负向可用佣金流水
  → 重算代理钱包；余额可为负
~~~

原正向佣金流水不得修改或删除。每笔负向流水必须关联退款、订单、订单项和原佣金记录。

分次退款按原订单项支付快照冲正，累计不得超过该订单项原佣金；最后一笔使订单项全额退清时，直接冲减剩余未冲佣金以清除舍入尾差。

### 6.6 提现

~~~text
代理在 AGT-07 选择银行卡并输入金额
  → 校验代理 ACTIVE、无负余额、金额达最低门槛、余额充足
  → 校验无其他 PENDING/APPROVED 提现
  → 提交后：可提现减少，冻结增加，状态 PENDING
  → 超级管理员审核
     → REJECTED：记录原因，可提现恢复，冻结减少
     → APPROVED：等待线下银行转账
  → 总部上传付款凭证并标记 PAID
  → 冻结减少，申请完成
~~~

### 6.7 客户归属转移

~~~text
超级管理员进入客户详情
  → 选择新的 ACTIVE 一级代理或转为直营
  → 查看影响提示并填写原因
  → 二次确认
  → 结束原有效绑定并创建新绑定记录
  → 仅转移后提交的新订单记录新归因候选
  → 写入审计和绑定历史
~~~

原代理的当前客户列表和客户详情立即移除该客户；原代理只可通过历史归属订单查看支付时冻结的脱敏客户快照，不能看到客户后续资料变化。

## 10. 状态模型

### 10.1 订单状态

| 状态 | 含义 | 允许下一状态 |
|---|---|---|
| `PENDING_PAYMENT` | 已锁库存，等待支付 | `PENDING_SHIPMENT`、`CLOSED` |
| `PENDING_SHIPMENT` | 已支付，等待总部发货 | `SHIPPING`、售后子流程 |
| `SHIPPING` | 已发货 | `COMPLETED`、售后子流程 |
| `COMPLETED` | 已确认收货或总部兜底完成 | 售后子流程，不回退主状态 |
| `CLOSED` | 未支付取消或超时关闭 | 终态 |

“退款售后”是售后聚合视图，不用一个状态覆盖订单主状态。

### 10.2 支付与物流状态

支付状态：`UNPAID` → `PAID`；失败或取消保留 `UNPAID`；退款由独立退款记录表示，可为 `NONE`、`PARTIAL`、`FULL`。

物流状态：`NOT_SHIPPED` → `SHIPPED` → `IN_TRANSIT` → `DELIVERED`。首期物流节点由总部手工维护，一个订单仅一个包裹。

### 10.3 售后状态

| 状态 | 含义 |
|---|---|
| `PENDING_REVIEW` | 等待总部审核 |
| `REJECTED` | 审核拒绝，终态 |
| `REFUNDING` | 仅退款已通过，等待退款 |
| `WAITING_RETURN` | 退货退款已通过，等待消费者寄回 |
| `WAITING_RECEIPT` | 已填退货物流，等待总部收货 |
| `REFUNDING_AFTER_RETURN` | 已确认收货，等待退款 |
| `COMPLETED` | 退款成功，终态 |
| `CANCELLED` | 用户在允许阶段取消，终态 |

### 10.4 代理与绑定状态

代理状态：`ACTIVE`、`DISABLED`。停用后禁止登录和新绑定；支付时不得为停用代理冻结新佣金，支付成功前不存在最终佣金快照，支付成功后已冻结的 `EXPECTED` 则继续按订单生命周期处理。

待确认邀请码属于游客会话候选，TTL 30 分钟，同一未绑定游客只保留最后一个有效码。登录后确认成功才创建长期绑定，拒绝或过期即清空。

绑定通过有效期表示为当前长期绑定或已结束历史绑定。代理停用只暂停该绑定的未来归因资格，不结束绑定；重新启用后，未被超级管理员转移的绑定恢复未来归因资格。绑定转移只能由超级管理员执行，且不物理删除历史。

### 10.5 佣金状态与流水

订单项佣金状态；订单层状态与金额由各订单项汇总，不使用一个比例覆盖整单：

| 状态 | 进入条件 | 退出条件 |
|---|---|---|
| `NONE` | 最终为 DIRECT，或归属订单项基数为 0/支付时有效比例为 0% | 终态；0% 订单项仍保留规则来源和比例快照，但不生成正向佣金流水 |
| `EXPECTED` | 支付成功且归因复核通过，最终佣金快照已冻结 | 订单完成转 `AVAILABLE`；完成前部分退款减少预计额；完成前全退转 `CANCELLED` |
| `CANCELLED` | 订单项完成前全额退款，预计佣金归零 | 终态；不产生可提现入账；全单所有有佣订单项均取消时订单汇总为 `CANCELLED` |
| `AVAILABLE` | 订单完成且该订单项佣金已入钱包 | 状态和原正向记录永久保留；完成后退款追加 `REFUND_DEBIT` |

佣金/钱包流水为不可变追加记录，至少区分：`EXPECTED_CREATED`、`EXPECTED_REDUCED`、`EXPECTED_CANCELLED`、`AVAILABLE_CREDIT`、`REFUND_DEBIT`、`WITHDRAWAL_FREEZE`、`WITHDRAWAL_RELEASE`、`WITHDRAWAL_PAID`。任何修正均新增流水，不更新历史金额。

### 10.6 提现状态

| 状态 | 操作者 | 允许下一状态 |
|---|---|---|
| `PENDING` | 代理提交 | `APPROVED`、`REJECTED` |
| `APPROVED` | 超级管理员审核通过 | `PAID` |
| `REJECTED` | 超级管理员拒绝 | 终态，金额已解冻 |
| `PAID` | 超级管理员上传凭证并确认付款 | 终态 |

当前版本不支持代理撤回、部分通过、部分付款或自动打款。

## 11. 业务规则

### 11.1 商品、价格与库存

- 默认分类：护肤品、洗发水、沐浴露、防晒产品、香水、彩妆、男士护理、家庭清洁；总部可新增、排序和停用。
- SKU 零售价为当前唯一成交价，会员价和代理价不展示、不参与计算。
- 服务端重新计价，客户端传入金额不得作为事实。
- 可售库存 = 实物库存 - 锁定库存；加入购物车不锁库存。
- 创建订单增加锁定库存；支付成功同时减少实物与锁定；取消或超时释放锁定。
- 退货不自动回补库存，由总部验货后手工调整并生成流水。

### 11.2 订单归属快照

- 提交订单时读取消费者当前长期绑定和代理状态；有效绑定指向 `ACTIVE` 代理时记录 `AGENT` 归因候选，否则记录 `DIRECT` 候选。
- 归因候选至少记录候选代理、绑定关系和提交时间，但此时不冻结最终渠道、商品佣金规则、比例或金额。
- 支付成功时对提交时的 `AGENT` 候选再次复核同一代理是否 `ACTIVE`。复核通过后，逐订单项解析支付时有效佣金规则、计算基数与金额，并最终冻结渠道、代理及规则版本、命中来源、一级分类、商品、SKU、比例、基数和佣金快照。
- 支付时代理已停用、候选无效或提交时已记录 `DIRECT`，最终渠道均为 `DIRECT`，不产生佣金；重新启用不追溯已经直营支付的订单。
- 归属转移只作用于转移后提交的新订单。支付前转移不替换既有待付款订单的候选；支付后转移、代理停用、分类移动或规则修改不得修改已冻结快照。
- 支付归因快照同时保存供原代理查看的客户昵称、手机号后四位和城市脱敏快照。客户转出后，原代理只能通过这些历史订单快照查看历史信息。
- 订单项保存商品、SKU、名称、规格、单价、数量、净商品实付和可退金额快照；代理订单还保存对应佣金规则快照。

### 11.3 佣金计算

- 所有一级代理共用同一套商品佣金规则，不在代理档案保存独立比例，也不支持“代理 × SKU”规则。
- 比例解析优先级固定为：`SKU 覆盖比例 > 商品一级分类默认比例 > 平台默认比例`。解析到首个非空值即停止。
- SKU 覆盖或分类默认比例为空表示继承；`0%` 是明确无佣金的有效配置，不得继续向下继承。
- 现有商品一级分类直接作为佣金分类来源。一个商品必须且只能归属一个有效一级分类；新增一级分类默认继承平台比例，商品移动分类只影响移动后支付的订单。
- 平台、分类和 SKU 百分比范围均为 0% 至 100%，建议存储四位小数、展示为百分比。当前版本不支持固定金额、销量/金额阶梯或限时活动佣金。
- 佣金基数 = 归属订单项净商品实付金额；首期无运费、优惠券或积分分摊。
- 单个订单项预计佣金 = 该订单项佣金基数 × 支付时有效比例；订单预计佣金 = 各订单项预计佣金之和，不保存或展示虚构的订单平均比例。
- 舍入按订单项执行后汇总，具体金额精度和舍入方式在技术设计固定且全系统一致。
- 支付成功时为每个归属订单项保存：规则版本、命中来源 `SKU`/`CATEGORY`/`PLATFORM`、一级分类、商品、SKU、有效比例、佣金基数和佣金金额。规则版本只追加，不覆盖历史。
- 待付款订单在支付成功时使用当时有效规则；代理推广页展示的比例和金额均为预计值。规则、商品分类或 SKU 配置后续变更只影响未来支付，不追溯历史。
- 支付成功且归因复核通过后创建 `EXPECTED`；支付前候选不向代理展示为订单或预计佣金。
- 消费者确认收货或总部兜底完成后立即入账，不设置额外结算等待期。

### 11.4 退款冲正

- 退款佣金影响基于退款订单项的实际成功退款金额，不以申请金额或审核金额为准。
- 完成前部分退款：按原订单项支付快照比例计算并追加 `EXPECTED_REDUCED`，剩余预计不得低于 0。
- 完成前订单项全额退款：追加 `EXPECTED_CANCELLED`，对应订单项佣金状态转为 `CANCELLED`，不产生可提现入账；全单有佣订单项均取消时订单汇总为 `CANCELLED`。
- 完成后退款：保留原 `AVAILABLE` 和 `AVAILABLE_CREDIT`，追加 `REFUND_DEBIT` 负向可用佣金流水。
- 常规部分退款冲减额 = 本次该订单项实际成功退款金额 × 原订单项支付快照比例，并按统一金额规则舍入。
- 同一订单项累计佣金冲减不得超过该订单项原始佣金。最后一笔使该订单项剩余可退实付归零时，本次冲减额直接取“原订单项佣金 - 该订单项累计已冲减佣金”，清除分次舍入尾差。
- 多 SKU 退款必须逐订单项计算后汇总，不得使用订单总额或平均比例分摊；全单退清后累计冲减必须等于原订单佣金。
- 退款失败不冲正；重试成功后只冲正一次。
- 冲正导致余额为负时保留真实负值，不从历史提现追改；阻止新提现，未来佣金先抵扣。

### 11.5 提现与银行卡

- 默认最低提现金额 100 元，由 ADM-16 业务规则设置配置；修改只影响之后提交的申请，首期手续费为 0。
- 提现金额不得超过可提现余额，余额小于等于 0 时不可提交。
- 每个代理同时最多一笔 `PENDING` 或 `APPROVED` 申请。
- 申请提交时保存代理、金额、银行卡掩码/密文引用和申请时余额快照。
- 银行卡包括开户名、开户银行和卡号；卡号加密存储，保存后的常规读取、页面和日志只返回掩码。
- 只有 `SUPER_ADMIN` 可在 `APPROVED` 待付款详情中发起二次身份验证。验证通过后获得一次性短时授权，可查看或复制该申请冻结的完整收款账号。
- 查看、复制、离页、授权超时和自动重新遮蔽均写入审计；授权不得跨申请复用，其他状态和其他页面不得返回完整账号。
- `PENDING` 通过后保持冻结，拒绝则释放；`PAID` 后扣减冻结并保存付款凭证。
- 付款凭证属于受控文件，只允许相关代理查看摘要、超级管理员查看原件。

### 11.6 代理停用

- 使当前会话失效并阻止新登录。
- 暂停全部邀请码使用，不再建立新绑定；邀请码记录自身启停状态和有效期不被停用动作覆盖。
- 长期绑定不结束，但未来订单提交时只能记录 `DIRECT` 候选；支付前被停用的既有 `AGENT` 候选在支付时转为 `DIRECT`。
- 支付后停用不影响已经冻结的 `EXPECTED`，订单完成时仍正常转为 `AVAILABLE`。
- 重新启用只影响未来提交/支付：未被转移的长期绑定恢复归因资格；只有自身仍启用且未过期的邀请码恢复；停用期已直营支付订单不追溯。
- 历史订单、佣金、负余额和提现永久保留。
- 已提交提现仍可审核；是否通过由总部结合实际结算政策决定。

### 11.7 隐私与审计

- 代理查询由服务端基于登录身份限定代理 ID，列表和详情都需验证。
- 代理手机号只显示后四位，地址只显示城市；完整字段不得先返回前端再遮盖。
- 客户转出后从原代理当前客户列表移除，原代理不得继续访问客户详情或后续资料变化，只能查看历史订单内冻结的脱敏客户快照。
- 密码使用安全哈希，临时密码和重置密码只展示一次。
- 银行卡号使用字段级加密，密钥不得写入数据库或源码；付款短时解密必须采用独立二次验证和最小授权。
- 登录、佣金规则版本、代理状态、归属、退款、佣金、银行卡写入、完整账号查看/复制、业务规则与提现关键动作写入审计。
- 审计和错误日志必须脱敏，不记录密码、完整卡号、完整手机号或详细地址。

### 11.8 售后申请期与佣金关系

- 消费者默认可在确认收货或总部兜底完成后的 7 个自然日内发起售后，具体天数由超级管理员在 ADM-16 配置并在订单完成时确定。
- 售后申请期是消费者申请资格，不是佣金结算等待期；订单完成时佣金立即转为可提现。
- 在有效售后期内退款成功时，系统按 11.4 追加负向佣金流水；不得延迟初始入账来规避冲正。
- 未发货订单仅允许仅退款；已发货或已完成且在有效期内可按规则申请仅退款或退货退款。

### 11.9 代理商品授权

- 新代理默认采用“全部在售商品”模式，自动包含当前和未来新上架商品，无需逐项授权。
- 超级管理员可在 ADM-19 切换为“自定义白名单”；切换后仅白名单中且当前已上架的商品可在代理推广中心展示或生成物料。
- 从白名单移除或商品下架后，既有推广链接不得继续建立商品购买入口，但不影响历史订单和佣金。
- 授权模式切换与白名单增删必须记录操作人、时间和前后值。

### 11.10 销售分析

- ADM-02 通过概览、日销售、月销售、商品排行、客户排行标签承载当前版本销售分析，不新增 Excel 导出。
- 日/月销售报表至少展示周期净销售额、创建订单数、有效支付订单数和退款金额，并支持日期范围切换。
- 商品销量排行以订单项成功支付数量减成功退款数量统计；客户消费排行以客户成功支付金额减成功退款金额统计。
- 报告数据以 Asia/Shanghai 分组，覆盖加载、空、错误和刷新状态；筛选条件返回页面时保留。

## 12. 数据与接口边界（产品级）

### 12.1 核心业务实体

| 领域 | 核心实体 | 产品要求 |
|---|---|---|
| 身份权限 | 超级管理员、一级代理账户、消费者、会话 | 三端登录入口与角色隔离 |
| 商品 | 品牌、一级分类、商品、SKU、素材、推荐位、代理授权模式/白名单 | 总部维护；一级分类同时作为佣金分类来源，代理默认继承全部当前及未来在售商品 |
| 交易 | 购物车、地址、订单、订单项、归因候选、支付归因快照、订单项佣金快照、支付、退款 | 服务端计价、库存事务、提交候选与支付最终冻结分离 |
| 履约售后 | 包裹、物流节点、售后、退货、退款记录 | 总部处理，消费者申请，代理只读进度 |
| 代理 | 代理档案、邀请码、商品授权 | 严格单层，不存在父代理字段业务含义 |
| 归属 | 游客待确认邀请码、消费者长期绑定、绑定变更记录 | 30 分钟候选、明确确认/拒绝、历史不可删除 |
| 佣金 | 平台默认规则、一级分类规则、SKU 覆盖规则、规则版本、订单项佣金快照、佣金流水、钱包余额 | 全代理共用；空值继承、0% 明确无佣金；版本与账本不可变、可复算、支持负数 |
| 提现 | 银行卡、提现申请、二次验证短时查看授权、审核与付款凭证 | 银行卡加密、默认掩码、最小解密授权和线下付款审计 |
| 经营分析 | 日/月销售汇总、商品销量排行、客户消费排行 | 由支付、退款、订单项和客户事实聚合，不可手工编辑 |
| 风控 | 审计日志、幂等记录、文件权限 | 可追溯且敏感信息脱敏 |

### 12.2 数据真相来源

- 商品当前展示以商品/SKU 数据为准；历史成交以订单快照为准。
- 销售额以成功支付与成功退款事实为准。
- 待付款订单的候选以提交时归因候选为准；已支付订单归属以支付成功冻结的代理快照为准，不根据当前绑定反推历史。
- 当前商品预计佣金比例以当前有效佣金规则版本按 `SKU > 一级分类 > 平台默认` 解析；历史佣金比例、来源和金额只以支付成功时的订单项佣金快照为准。
- 佣金以不可变佣金/钱包流水为准，缓存余额仅作加速且必须可复算。
- 提现状态以申请状态和审计事件为准，不以人工备注代替。
- 代理当前客户归属以当前长期绑定和代理 ACTIVE 资格为准；历史订单可见信息以支付时脱敏客户快照为准。
- 日/月报表与排行以支付、退款、订单项和客户事实为准，不以页面缓存或手工汇总为准。

### 12.3 三端接口边界

- 小程序接口只可访问公开商品和当前消费者本人数据。
- 代理接口仅可访问当前登录代理的授权商品、归属数据、账本和提现。
- 总部接口仅 `SUPER_ADMIN` 可访问，承担经营配置、履约、售后、代理和财务写操作；消费者可写本人购物、订单与售后数据，代理可写本人账户、银行卡和提现申请。
- 佣金规则查询接口必须同时返回配置值、有效比例、命中来源和规则版本，并保持 `null`（继承）与 `0`（明确无佣金）的语义差异。
- 佣金规则写接口仅 `SUPER_ADMIN` 可调用，按平台、一级分类或 SKU 目标保存新版本；不得接收代理 ID、固定金额、阶梯或活动条件。保存需幂等并写审计。
- 支付接口内部逐订单项调用规则解析并原子保存订单项佣金快照；代理和小程序传入的比例、来源、版本或佣金金额一律忽略。
- 退款接口必须携带可核验的退款订单项明细，并使用原订单项快照计算冲减；不得读取当前规则反算历史退款佣金。
- 完整收款账号只允许付款专用接口在二次验证短时授权内返回，不得复用常规提现详情接口。
- 每类入口使用独立授权守卫或明确的作用域，禁止仅靠前端隐藏菜单。
- 敏感写操作使用幂等键、状态前置校验和审计上下文。

## 13. 页面与交互规范

### 13.1 统一视觉方向

采用高端、简洁、适合洗化与美妆行业的品牌商城风格。视觉使用白色、炭黑、植物绿、灰蓝、珊瑚和琥珀作为功能色，不使用大面积渐变或装饰性光斑。卡片圆角不超过 8px，状态不仅依赖颜色表达。

### 13.2 小程序

- 商品图与价格优先，首屏不过度解释功能。
- 服务代理确认使用底部弹层，明确“商品价格、发货和售后由总部商城统一负责”，同时提供清晰的确认与拒绝动作；拒绝后清空待确认码。
- 服务代理页只读，不提供改绑、解除或佣金信息。
- 底部购买区尺寸稳定，SKU、数量和加载状态不得导致布局跳动。

### 13.3 一级代理工作台

- 桌面以紧凑侧栏、指标条、筛选表格为主；移动端重排为摘要列表和底部导航。
- 关键金额同时标注口径，预计佣金与可提现余额使用不同标签。
- 负余额使用明确文本和禁用原因，不能只显示红色数字。
- 客户和订单页面始终使用掩码字段，不设计“查看完整信息”按钮。
- 客户转出后不再出现在当前客户列表；历史订单只能展示支付时冻结的脱敏快照。
- 推广中心按 SKU 显示当前有效预计比例和预计佣金，并标注“以支付时规则为准”；`0%` 使用“无佣金”文本，不能表现为加载失败或继承。
- 佣金详情显示订单项支付快照的 SKU、命中来源、比例、基数和金额；多 SKU 订单按项展开，不展示订单平均比例。
- 推广二维码提供复制/下载反馈，不使用装饰性分享卡片替代实际二维码。

### 13.4 总部管理后台

- 列表筛选在返回时保留，分页默认每页 20 条。
- 停用代理、转移归属、拒绝提现、确认付款和退款均二次确认。
- 提现审核与付款分为两个动作，避免“审核通过”等同“已打款”。
- 完整收款账号入口仅在已通过待付款状态出现，二次验证后短时显示，并持续显示自动遮蔽倒计时；复制或离页后仍按授权时限自动恢复掩码。
- ADM-02 使用标签承载概览、日/月销售、商品排行和客户排行，并为每个报告设计加载、空、错误与筛选状态。
- ADM-16 将账户安全和最低提现金额、售后申请天数分区展示；ADM-19 只管理代理资料、状态和商品授权，不出现独立佣金比例。
- ADM-22 顶部展示平台默认比例；分类表展示配置值/继承状态和有效比例；SKU 表支持按分类、商品、SKU 检索并显示覆盖值、有效比例与来源。空值使用“继承”，`0%` 使用“无佣金”。
- 保存佣金规则前展示受影响 SKU 数、未来支付生效提示和二次确认；保存后显示规则版本与审计入口。
- 桌面 1024px 时可折叠侧栏；表格允许局部水平滚动但页面主体不溢出。

## 15. 非功能需求

### 15.1 性能与兼容性

- 设计基线：核心 API 在 50 并发约定负载下 P95 小于 500ms，最终指标需结合真实规模校准。
- 商品列表、订单、客户、佣金和提现均分页，不一次返回全量。
- 图片使用对象存储、缩略图和懒加载；二维码生成失败可重试。
- 代理工作台支持现代 Chrome、Edge、Safari 和微信内置浏览器近两个主版本。

### 15.2 一致性与可靠性

- 库存锁定、支付结转与最终归因、订单完成佣金入账、退款冲正和提现冻结使用事务或可靠事件。
- 支付结转必须在同一一致性边界内读取一个确定的佣金规则版本并保存全部订单项快照，不能在同一订单内混用配置变更前后版本。
- 支付、退款、佣金、提现重复回调不得产生重复结果。
- 定时任务可重入，失败有重试、告警和人工补偿入口。
- 汇总余额、日/月报表和排行必须可由事实流水重建。

### 15.3 安全与隐私

- 密码安全哈希、登录限流、会话过期、敏感操作二次确认。
- 三端角色和数据范围在服务端强制执行。
- 银行卡字段级加密、文件访问鉴权、隐私字段最小化返回；完整收款账号仅允许付款专用接口在二次验证短时授权内返回一次。
- 短时授权与普通登录会话隔离，绑定单个提现申请，超时或离页自动失效；前端不得持久化、缓存或写日志。
- 数据传输使用 HTTPS；生产密钥由安全配置管理，不写入仓库。
- 明确数据保留、删除申请、隐私授权和代理合作方保密义务。

### 15.4 可观测与审计

- 所有请求具备追踪 ID；关键状态变化记录业务对象、操作人和幂等键。完整收款账号的二次验证、查看、复制、超时和遮蔽单独记录安全审计，但绝不记录账号内容。
- 对库存负数、佣金规则解析失败、订单项无规则版本、重复佣金、退款累计冲减超限、负余额异常扩大、提现久未付款和越权拒绝率设置告警。
- 审计日志仅追加，普通业务操作不能删除。

## 16. 错误与边界处理

| 场景 | 系统处理 |
|---|---|
| 新邀请码不存在、过期或代理停用 | 不覆盖仍有效的待确认码；无有效候选时以直营身份继续，不暴露内部状态 |
| 未绑定游客在 30 分钟内打开多个有效代理码 | 最后一个有效码覆盖旧候选，并以新的 30 分钟期限为准 |
| 登录时待确认码已过期或用户拒绝 | 清空候选，不创建绑定，后续订单保持 DIRECT |
| 已绑定用户访问其他代理链接 | 保持原绑定，不出现改绑入口 |
| 提交订单后、支付前候选代理停用 | 支付时最终冻结为 DIRECT，不产生佣金 |
| 支付成功后代理停用 | 已冻结 EXPECTED 保留，订单完成后仍进入 AVAILABLE |
| 代理重新启用 | 未转移绑定仅对未来提交/支付恢复；邀请码需自身有效；停用期 DIRECT 订单不追溯 |
| 平台/分类/SKU 规则在提交订单后、支付前被修改 | 支付成功时读取当时有效规则版本并逐订单项冻结，以服务端结果为准 |
| SKU 覆盖为空或为 0% | 空值继续继承一级分类；0% 立即命中并明确无佣金，不再继承 |
| 商品在提交订单后、支付前移动一级分类 | 支付时使用商品当时所属一级分类解析；支付后移动不改变快照 |
| 支付过程中规则刚好更新 | 单笔支付只使用一个确定的有效规则版本；成功订单不得出现跨版本订单项 |
| 佣金规则解析异常或缺失平台默认 | 支付不得生成不完整代理佣金；记录错误并进入可重试/人工补偿流程，不相信客户端比例 |
| 提交订单后客户被转移 | 已有订单保留提交时候选；转移后提交的新订单使用新归属 |
| 客户已从原代理转出 | 从原代理客户列表/详情移除，仅历史订单返回支付时脱敏快照 |
| 白名单商品被移除或下架 | 代理端不再可生成新物料，既有链接不再进入购买；历史订单不变 |
| 完成后全额退款且余额不足 | 生成负向流水并允许余额为负，冻结新提现 |
| 分次退款最后一笔退清订单项 | 本次冲减原订单项剩余佣金，累计恰好等于原佣金且无舍入尾差 |
| 提现提交与退款并发 | 事务串行校验余额；只允许一个操作基于同一版本成功 |
| 代理重复点击提交提现 | 幂等返回同一申请，不重复冻结余额 |
| 审核时代理已停用 | 历史申请保留，超级管理员可结合政策审核并记录原因 |
| 付款凭证上传失败 | 保持 `APPROVED`，不得标记 `PAID`，允许重试 |
| 越权访问其他代理客户/订单 | 返回统一无权限或不存在响应并记录安全日志 |
| 银行卡解密或二次验证服务不可用 | 禁止完整账号查看与付款确认，不回显密文或降级为明文 |
| 完整账号短时授权过期或离页 | 立即恢复掩码，复制入口失效，再次查看必须重新二次验证 |
| 销售报告加载失败 | 保留筛选条件，显示错误状态和重试，不以旧缓存冒充最新数据 |

### 17.3 归属、佣金与退款

| ID | 场景 | 预期 |
|---|---|---|
| AC-COM-001 | ACTIVE 绑定客户提交订单 | 只记录正确归因候选，不生成代理可见订单或预计佣金 |
| AC-COM-002 | 候选代理在支付时 ACTIVE/已停用 | ACTIVE 时逐订单项冻结支付时规则版本/来源、分类、商品、SKU、比例、基数与佣金；停用时最终 DIRECT 且无佣金 |
| AC-COM-003 | 佣金规则在提交后、支付前修改 | 支付时冻结当时有效规则版本；支付后再修改不影响已冻结订单项 |
| AC-COM-004 | 支付成功但未收货 | 佣金为预计，不进入可提现余额 |
| AC-COM-005 | 确认收货或总部兜底完成 | 佣金仅一次进入可提现余额 |
| AC-COM-006 | 完成前部分退款 | 预计佣金按原订单项支付快照比例和实际成功退款金额减少 |
| AC-COM-007 | 完成后部分退款 | 新增负向流水，原正向流水不变 |
| AC-COM-008 | 冲正导致余额为负 | 显示负余额、禁止提现、后续佣金优先抵扣 |
| AC-COM-009 | 重复退款回调 | 只产生一次退款和佣金冲正 |
| AC-COM-010 | 支付成功后代理停用再完成订单 | 已冻结 EXPECTED 保留并仅一次转为 AVAILABLE |
| AC-COM-011 | 代理重新启用 | 未转移绑定只影响未来业务，停用期 DIRECT 订单不追溯，邀请码需自身有效 |
| AC-COM-012 | 完成前订单全额退款 | EXPECTED 转为 CANCELLED，不产生 AVAILABLE_CREDIT |
| AC-COM-013 | 同一 SKU 同时存在平台、分类和 SKU 比例 | 命中 SKU 覆盖；清空 SKU 覆盖后命中分类；清空分类后命中平台默认 |
| AC-COM-014 | SKU/分类配置分别为空和 0% | 空值正确继承；0% 明确无佣金且不继续继承 |
| AC-COM-015 | 商品移动一级分类 | 移动后支付使用新分类规则；移动前已支付订单项快照不变 |
| AC-COM-016 | 一个代理订单包含不同比例的多个 SKU | 逐订单项计算和展示，订单佣金等于各项之和，不使用平均比例 |
| AC-COM-017 | 同一订单项发生多次部分退款 | 每次按原订单项快照比例冲减，累计不超过原订单项佣金 |
| AC-COM-018 | 最后一笔退款使订单项全额退清 | 本次直接冲减剩余未冲佣金，消除舍入尾差；全单退清时总冲减等于原订单佣金 |
| AC-COM-019 | 不同 ACTIVE 代理在同一规则版本推广相同 SKU | 按同一商品规则计算，不存在代理专属比例差异 |

## 19. 延期需求清单

| 延期能力 | 延期原因 | 当前仅保留的边界 |
|---|---|---|
| 多级/二级代理、团队佣金 | 关系链、合规和结算复杂度显著上升 | 当前代理实体严格无业务父级 |
| 代理进货与独立店铺 | 会改变商户、库存、价格、收款和售后主体 | 当前总部统一经营 |
| 自动打款/微信零钱提现 | 需要支付服务商、实名、税务和风控 | 当前线下银行转账与凭证 |
| 代理专属/代理 × SKU、固定金额、阶梯、活动佣金 | 形成组合爆炸并显著增加结算与合同复杂度 | 当前所有一级代理共用平台/分类/SKU 百分比规则 |
| 会员、优惠券、积分、新人优惠 | 需要定价优先级和分摊规则 | 定价/促销扩展边界 |
| 拼团、秒杀 | 活动库存与高并发状态复杂 | 活动领域扩展边界 |
| 商品视频与 AI 客服 | 媒体、模型、审核和隐私成本 | 文件与客服集成边界 |
| Excel 导出和自定义报表中心 | 需异步任务、权限和隐私水印 | 当前已提供固定日/月销售、商品和客户排行 |
| 真实物流轨迹、多仓、多包裹 | 改变库存与履约模型 | 物流 Provider 与包裹实体边界 |

延期能力不得出现对用户可见但不可用的入口。单层代理是当前业务约束，不是界面文案上的临时隐藏。

- 当前仅完成需求与原型设计，不进行生产发布。

## 22. Definition of Done

需求或原型只有同时满足以下条件才可进入技术设计评审：

- 页面、流程、状态和权限可追溯到 FR 与 AC；
- 三端术语统一，不再出现旧版后台角色或多级代理暗示；
- 代理端所有客户与订单示例均符合脱敏规则；
- 佣金、退款、负余额和提现边界有可演示状态；
- ADM-22 的平台默认、分类继承、SKU 覆盖、0% 无佣金、规则版本和支付快照解释均可追溯到 FR 与 AC；
- 关键页面覆盖默认、加载、空、错误、禁用和成功状态；
- 小程序、代理工作台和总部后台基准视口通过截图检查；
- 延期能力无半成品入口；
- 产品负责人确认 PRD 和原型后，才进入数据库、API 与开发拆分。
