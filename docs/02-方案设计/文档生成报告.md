## 2. 输入依据

本轮文档基于已确认的业务决策更新，不使用未经验证的市场数字：

1. 产品由总部管理后台、一级代理工作台和消费者微信小程序组成。
2. 只有超级管理员、一级代理和消费者三类人员；游客是未登录状态。
3. 代理严格单层，由超级管理员创建，不存在下级代理。
4. 总部统一商品、价格、库存、收款、发货、退款与售后。
5. 一级代理仅推广并只读查看本人脱敏客户、归属订单、佣金和提现。
6. 未绑定游客保存最后一个有效邀请码，TTL 30 分钟；登录后明确确认或拒绝，确认成功才长期绑定。
7. 超级管理员可转移到其他 ACTIVE 代理或 DIRECT，只影响转移后提交的新订单。
8. 提交订单记录归因候选，支付成功时复核代理 ACTIVE，并逐订单项冻结支付时佣金规则版本/来源、分类、商品、SKU、比例、基数和佣金快照。
9. 支付前停用转 DIRECT；支付后停用不影响已冻结 EXPECTED；重启不追溯停用期订单。
10. 确认收货或总部兜底完成后佣金立即 AVAILABLE；完成前全退为 CANCELLED，完成后退款追加 REFUND_DEBIT。
11. 负余额真实保留并阻止提现，后续佣金优先抵扣。
12. 银行卡加密、默认掩码；仅付款环节由超级管理员二次验证后短时一次性查看/复制完整账号并全量审计。
13. 默认最低提现 100 元、售后申请期 7 天，均由 ADM-16 配置；提现无手续费，同一代理最多一笔进行中申请。
14. 所有一级代理共用同一套商品佣金规则，优先级为 `SKU 覆盖 > 商品一级分类默认 > 平台默认`；空值继承，`0%` 明确无佣金。
15. 退款按原订单项支付快照比例冲减；累计不超原订单项佣金，尾笔全退直接冲清剩余金额。
16. 代理默认授权全部当前及未来在售商品，超级管理员可在 ADM-19 切换自定义白名单。
17. 自定义白名单仅限制代理查看和生成推广物料；已绑定客户购买全店任意 SKU 仍按统一商品规则计佣，白名单不进入佣金快照。
18. 购物车、订单项、库存、发货、售后和退款统一以 `sku_id` 为最小单位；提交订单只生成待付款订单、库存预占和 `pay_expires_at`，首次/重试支付才创建或复用唯一 OPEN 支付意图。
19. 超时先关闭支付意图再释放库存；关单后的迟到支付只自动原路退款，失败进入人工财务异常，不恢复履约或佣金。
20. 订单、支付、退款和履约使用独立状态轴；未发货退款成功自动回库，全额退款关闭履约。
21. 售后申请事务性占用可退数量/金额；允许阶段取消或驳回释放，`REFUND_FAILED` 保留占用并支持重试。
22. 客户账户手机号独立、可空且自愿授权，不从地址手机号提取；提供账号删除申请和交易阻断。
23. 邀请码可轮换/停用；品牌、分类、商品和 SKU 软删除；分类存在在售商品时禁止停用。
24. 高风险动作要求原因、影响预览、二次确认、防重复和审计；收款账号采用 60 秒单次授权与失败锁定。
25. ADM-02 纳入日/月销售报表、商品销量排行和客户消费排行；Excel 导出仍延期。
26. 多级代理、代理维度佣金、固定金额/阶梯/活动佣金、代理进货、独立商户、自动打款和复杂营销继续延期。
27. 数据库采用 Supabase 托管 PostgreSQL；Supabase 只承担数据库托管，不采用 Auth/Storage/Realtime，三端不得直连 Data API。
28. NestJS API/Worker 是唯一数据入口；Prisma 7 的 runtime 与 migration 使用独立最小权限角色和连接，Data API 关闭并保留 grants/RLS 默认拒绝。

## 6. 关键决策一致性

- 三端：MVP、PRD、原型方案和变更记录均已覆盖。
- 三类人员：超级管理员、一级代理、消费者统一使用系统角色代码。
- 单层代理：代理仅由总部创建，无下级、团队、采购或独立经营能力。
- 总部统一履约：商品、价格、库存、收款、发货、退款和售后由总部负责。
- 首次绑定：最后有效候选 TTL 30 分钟，登录后确认成功才长期有效；拒绝清空，已绑定忽略新码。
- 归因快照：提交订单只记录候选，支付成功复核 ACTIVE 后逐订单项冻结代理、规则版本/来源、分类、商品、SKU、比例、基数与佣金。
- 统一商品佣金：所有一级代理共用规则，按 `SKU > 一级分类 > 平台默认` 解析；空值继承，0% 明确无佣金。
- 历史隔离：规则、分类或 SKU 配置变化只影响未来支付，历史只读支付订单项快照。
- 生命周期：支付前停用转 DIRECT；支付后停用不影响 EXPECTED；重新启用只影响未来且不追溯。
- 佣金入账：支付后预计，确认收货或总部兜底完成后立即可提现。
- 退款冲正：完成前全退转 CANCELLED；完成后保留 AVAILABLE 并追加 REFUND_DEBIT；逐订单项累计封顶，尾笔全退清除舍入尾差。
- 负余额：真实保留、禁止提现、后续佣金优先抵扣。
- 提现：银行卡默认掩码，付款时二次验证短时一次性查看/复制；四种提现状态与付款凭证完整区分。
- 商品授权：默认全部当前及未来在售商品，可切换为自定义白名单。
- 白名单语义：仅限制推广可见与物料生成；绑定客户购买白名单外 SKU 仍按统一规则计佣，撤权旧链接不再建立候选。
- SKU 交易：购物车、订单、库存、发货、售后和退款以 `sku_id` 为最小单位；同商品不同 SKU 不合并。
- 支付时限：创建订单即形成待付款事实；失败/取消/稍后支付保留订单，超时先关支付意图再释放库存，迟到成功自动退款。
- 独立状态轴：订单、支付、退款和履约分别保存，未发货全额退款关闭订单并取消履约。
- 售后并发：申请时占用可退数量/金额，待处理数量不得发货；允许阶段取消/驳回释放，退款失败保留占用重试。
- 退款库存：未发货退款成功按 SKU 自动回库，部分退款只发剩余数量；已发货退货验货后人工决定回库。
- 佣金不可变：原快照和正向流水永不修改，所有预计减少、取消和完成后冲正均追加流水。
- 销售分析：日/月销售、商品销量和客户消费排行纳入当前版，Excel 导出仍延期。
- 规则配置：最低提现金额和售后申请天数在 ADM-16 管理；商品佣金在 ADM-22 按版本管理并按支付时边界生效。
- 隐私：账户手机号独立、可空、自愿授权，代理只见已验证后四位或“未绑定”；地址手机号不作为账户手机号，历史快照不追溯补写。
- 隐私删除：存在未完成交易时阻断删除；满足条件后撤销会话、结束绑定、去标识化资料并按合规保留事实记录。
- 生命周期治理：邀请码轮换后旧码立即失效；品牌、分类、商品和 SKU 软删除，存在在售商品的分类禁止停用。
- 高风险保护：代理停用、客户转移、售后/提现拒绝、退款、邀请码和佣金规则变更均要求原因、影响、确认、防重复和审计。
- 收款账号：仅 `APPROVED` 提现可在 60 秒单次授权内查看，连续失败 5 次锁定 15 分钟。
- 数据库选型：Supabase 仅托管 PostgreSQL，微信认证、应用 RBAC 和 S3 对象存储保持原边界，三端只访问 NestJS。
- 数据访问：Data API 关闭，`anon`/`authenticated`/`service_role` 不获应用表权限；RLS 作为纵深防护，业务行级授权仍由 NestJS 执行。
- Prisma 连接：Schema 采用 Prisma 7 PostgreSQL/public 口径；runtime 使用 `DATABASE_URL`，CLI/migration 使用 direct `DIRECT_URL`，两套最小权限凭据隔离。
- PostgreSQL 约束：活动记录使用部分唯一索引，金额/计数使用 `CHECK`，时间使用 `TIMESTAMPTZ(3)`，金额使用 `NUMERIC(18,2)`。
- 技术边界：已完成字段级逻辑模型、OpenAPI、事务/幂等约束和部署拓扑；未创建 Supabase 项目、运行数据库或生产代码。
