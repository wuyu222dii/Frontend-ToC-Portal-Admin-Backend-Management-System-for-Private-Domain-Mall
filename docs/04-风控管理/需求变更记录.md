## 三、CH-001 变更详情

### 3.1 变更申请

- **申请日期**：2026-08-10
- **申请来源**：业务负责人明确调整
- **变更类型**：新增需求与原有需求修改
**紧急程度**：高，必须在开发前完成范围纠偏

变更前产品只有消费者小程序和总部管理后台，后台采用两类内部权限，渠道推广与结算能力尚未纳入当前范围。

变更后产品为三个终端和三类人员：

1. 总部管理后台，角色 `SUPER_ADMIN`。
2. 一级代理工作台，角色 `AGENT_ADMIN`，属于外部推广合作方。
3. 消费者微信小程序，角色 `CUSTOMER`。

游客仍为未登录状态，不新增人员角色。原总部最高权限映射为 `SUPER_ADMIN`，原总部内部普通操作角色从当前范围移除。

### 3.2 业务边界

- 代理严格单层，由超级管理员创建，不存在下级代理。
- 总部统一商品、零售价、库存、收款、发货、退款和售后。
- 代理仅推广和只读查看本人脱敏客户、订单、售后进度、佣金与提现。
- 代理不能改价、改库存、代客下单、发货、退款或处理售后。
- 未绑定游客保存最后一个有效邀请码，TTL 30 分钟；登录后确认成功才建立长期绑定，拒绝则清空候选并保持直营。
- 超级管理员可转移到其他 ACTIVE 代理或 DIRECT，但只影响转移后提交的新订单，历史订单与佣金快照不变。
- 提交订单只记录归因候选，支付成功时复核代理 ACTIVE 后最终冻结；支付前停用转 DIRECT，支付后停用不影响已冻结 EXPECTED。
- 佣金按订单项净商品实付金额和代理专属比例计算。
- 确认收货或总部兜底完成后，佣金立即转为可提现，不设置额外等待期。
- 完成前全退将 EXPECTED 标记为 CANCELLED；完成后保留 AVAILABLE 并追加 REFUND_DEBIT；余额可为负并阻止提现。
- 提现由代理申请、总部审核、线下银行转账、上传凭证并标记已支付；完整收款账号默认掩码，仅付款环节二次验证后短时查看/复制并全量审计。
- 代理默认授权全部当前及未来在售商品，超级管理员可切换自定义白名单。
- ADM-16 配置默认 100 元最低提现与默认 7 天售后申请期；ADM-02 纳入日/月销售、商品销量和客户消费排行。

### 3.4 风险评估

| 风险 | 等级 | 控制措施 |
|---|---|---|
| 把“二级代理端”误解为多级代理 | 高 | 统一命名“一级代理工作台”，禁止父子关系和团队页面 |
| 代理越权查看隐私或其他代理数据 | 高 | 服务端行级授权、字段最小化、脱敏和安全测试 |
| 比例或状态变化造成错误归因 | 高 | 提交时记录候选，支付时复核 ACTIVE 并冻结当时比例与佣金快照 |
| 完成后退款导致已提现佣金倒挂 | 高 | 追加负向账本、允许负余额、阻止新提现、未来抵扣 |
| 审核通过被误认为已经打款 | 高 | `APPROVED` 与 `PAID` 分离，付款凭证必填 |
| 付款环节完整收款账号泄露 | 高 | 加密存储、默认掩码、二次验证、短时申请级授权、自动遮蔽与审计 |
| 代理停用影响历史结算 | 中 | 阻止新业务但保留历史账本和已有提现审核 |
| 角色术语残留造成错误开发 | 高 | 对 MVP、PRD、原型和验收进行全文一致性检查 |

### 3.5 变更决策

- **审批结果**：已批准。
- **执行时机**：纳入当前版本，先完成需求与原型设计。
- **审批依据**：业务负责人明确要求三端和三类人员，并确认单层代理、归属、佣金、退款冲正与线下提现规则。

批准条件：

- 不进入多级代理、代理进货、独立商户或自动打款。
- 不复用 `AGENT_ADMIN` 作为总部内部普通员工。
- 设计文档和原型评审通过前不开始生产开发。
- 技术设计不得绕过订单快照、不可变账本、隐私脱敏和审计要求。
- 归因候选、支付最终冻结、停用/重启、商品授权与规则配置必须按 PRD v2.0 修订口径实现。
- 固定销售报表属于当前版本，Excel 导出和自定义报表中心仍延期。
