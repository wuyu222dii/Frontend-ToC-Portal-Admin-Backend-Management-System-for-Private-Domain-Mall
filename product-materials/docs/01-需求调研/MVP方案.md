## 1. MVP 概述

### 1.1 背景

供应商拥有多个品牌和多个洗化品类货源，需要建立自有微信私域交易阵地，并通过外部一级代理扩大私域触达。消费者在微信小程序内完成浏览、下单、履约与售后；一级代理通过独立工作台推广总部商品、查看归属客户与订单、核对佣金并申请提现；总部通过电脑管理后台统一管理商品、价格、库存、收款、发货、售后、代理与财务审核。

本版本不是多商户平台。商品和交易均由总部经营主体统一承接，代理不拥有商品、价格、库存、订单履约或售后处理权。

### 1.2 核心验证目标

1. 私域客户愿意通过供应商自有小程序完成商品浏览和自主下单。
2. 总部能够通过管理后台独立完成商品、库存、订单、履约、售后、代理和提现审核。
3. 一级代理能够使用分享二维码或链接推广商品，并准确查看脱敏的归属客户、归属订单与佣金。
4. 首次确认成功的代理关系能够长期绑定消费者，订单提交记录归因候选，并在支付成功时复核代理状态后，按统一商品佣金规则逐订单项冻结规则来源、比例、基数和金额快照。
5. 系统能够以 SKU 为最小交易单位，可靠完成库存预占、待付款订单、可恢复支付意图、主动取消/超时关单、迟到支付自动退款、售后额度占用、单包裹发货、退货验货、退款回库、佣金入账、退款冲正和线下提现闭环。

### 1.3 北极星指标

北极星指标为“有效支付订单数”：订单至少存在一笔成功支付记录，且当前剩余实付金额大于 0；全额退款订单不计入当前有效支付订单存量。

渠道辅助指标包括：

- 代理归属有效支付订单数；
- 代理归属净销售额；
- 新增绑定客户数；
- 已入账佣金与已支付提现金额。

经营报表按 Asia/Shanghai 自然日或自然月统计，数据库时间统一保存为 UTC。

### 1.4 MVP 原则

- 完整交易和代理佣金闭环优先于复杂营销玩法。
- 总部统一经营权优先于代理自治。
- 单层、可审计的代理归属优先于多级关系链。
- 数据准确、库存一致和账本不可篡改优先于自动化结算。
- 第三方支付、退款、物流和微信正式资质未就绪时，通过 Provider 接口与 Mock 实现保持可演示、可替换。

### 2.2 首期明确不启用

- 多级代理、二级代理、团队关系和上下级分佣；
- 代理自行招募或管理下级代理；
- 代理进货、批发采购、独立店铺或独立商户结算；
- 代理自定义商品、价格、库存、优惠、发货和售后；
- 代理代客下单或查看完整手机号、完整收货地址；
- 每代理独立佣金比例、“代理 × SKU”佣金、固定金额、销量/金额阶梯和限时活动佣金；
- 自动向银行卡或微信零钱打款；
- 多级会员价格、会员等级成长、优惠券、积分和新用户优惠；
- 拼团、秒杀、直播、商品视频和 AI 客服；
- 第三方物流实时轨迹和电子面单；
- Excel 导入导出和自定义报表中心；
- 多商户、多仓库、多包裹、拆单与合单；
- 正式微信支付、退款、真实微信授权登录及真实手机号授权（设计/演示使用 Mock Provider）。
- 消费者订单留言/买家备注；总部内部审计备注不受此项影响。

### 2.3 首期业务边界

- 三端分别为总部管理后台、一级代理工作台、消费者微信小程序。
- 只有三类人员角色：超级管理员、一级代理、消费者；游客属于登录状态，不是人员角色。
- 代理关系严格单层。超级管理员创建所有一级代理，一级代理没有下级。
- 单商户、单仓库、单包裹、全场包邮。
- 单包裹不是“先发一部分、后补一包”：任一未发货订单项存在活动售后占用时整单禁止创建或确认发货；占用全部释放或转为成功退款后，才按最终剩余数量一次发出唯一包裹。
- 总部统一商品、零售价、库存、收款、发货、售后和退款。
- 一个商品可有多个 SKU；成交价格和库存以 SKU 为准。
- 购物车行、订单项、库存锁定、售后数量和退款金额均以 `sku_id` 为最小单位；同一商品不同 SKU 不合并。
- 所有一级代理共用同一套商品佣金规则，比例优先级为 `SKU 覆盖 > 商品一级分类默认 > 平台默认`；空值表示继承，`0%` 表示明确无佣金。
- 代理商品白名单只控制代理端可查看和生成推广物料的范围，不限制消费者在总部商城购买；客户一旦有效绑定代理，其全店任意 SKU 的有效支付订单均按统一商品佣金规则计佣。
- 消费者首次通过有效代理二维码或链接登录后建立长期绑定；已绑定用户访问其他代理链接时不改绑。
- 客户账户手机号为独立、可空的已验证资料，只能由消费者自愿授权；不得从收货地址手机号反推或写入账户手机号。
- 只有超级管理员可转移消费者代理归属；转移只影响未来订单，历史订单快照和佣金不变。
- 未绑定消费者的订单为直营订单 `DIRECT`，不产生代理佣金。
- 每个 SKU 单笔订单购买上限固定为 99 件，实际可购买数量取 `min(99, 服务端可售库存)`，首期不提供后台配置。
- 三端列表和详情采用角色专用投影，不复用会扩大可见范围或混淆统计口径的通用响应：消费者只获得本人交易所需字段，代理只获得当前归属/支付快照的脱敏字段，总部获得经营、履约和审计所需字段。

### 2.4 B7 身份与隐私阶段边界

- B7 公开用户协议、隐私政策、手机号授权说明三份服务端权威快照；登录同意前两份，手机号授权同意第三份。Mock 微信 Provider 建立 Store 会话，token 固定校验 `role=CUSTOMER`、`assurance=WECHAT`、`audience=qingxu-store`，不得与管理端 token 混用；Provider 不是 token claim。
- B7 固定一个消费者微信 AppID，以 `(AppID, openid)` 语义识别消费者；现有 `wechat_open_id` 唯一约束只适用于该 AppID。`wechat_union_id` 仅作可空元数据，不用于登录唯一性或自动合并；未来多 AppID 必须单独变更并迁移。
- profile 和账户手机号写入要求幂等与 `If-Match`；手机号 Provider 由服务端环境选择，客户端只提交凭证与 `PHONE_AUTHORIZATION` 同意。
- 推广候选目标由服务端根据邀请码和推广物料解析，匿名 token 只存用途隔离 HMAC、30 分钟有效；查询不消费，候选替换或登录迁移时原子失效；服务代理只返回代理 ID、展示名和绑定时间。
- 账号注销使用 5 分钟 preview 与同步 confirm。确认时重新检查业务阻断，并在同一事务去标识化、撤销全部会话、结束绑定和匿名化代理历史投影。
- B7 排除收藏、服务端购物车、地址、结算、订单、支付、退款、真实微信和 staging/production；这些入口不得伪造成功。

## 3. 角色与核心任务

| 人员角色 | 系统代码 | 所属端 | 核心目标 | 主要权限 |
|---|---|---|---|---|
| 超级管理员 | `SUPER_ADMIN` | 总部管理后台 | 统一经营商城并管理渠道 | 全部商品、价格、库存、订单、发货、售后、客户、代理、提现、审计和配置 |
| 一级代理 | `AGENT_ADMIN` | 一级代理工作台 | 推广总部商品并核对收益 | 推广授权商品；只读查看本人归属的脱敏客户、订单、佣金；维护本人银行卡；申请提现 |
| 消费者 | `CUSTOMER` | 微信小程序 | 购买商品并跟踪服务 | 浏览、收藏、购物车、地址、订单、支付、物流、售后和只读查看服务代理 |

权限硬边界：一级代理不能登录总部后台；超级管理员不使用代理工作台经营代理业务；消费者不能访问任何经营端。

## 4. 核心用户旅程

### 4.1 代理开通与首次登录

~~~text
超级管理员创建一级代理
  → 设置账号和初始状态；佣金统一继承商品规则
  → 系统生成登录账号、临时密码和唯一邀请码
  → 代理首次登录
  → 强制修改密码
  → 进入工作台并维护银行卡
~~~

### 4.2 代理推广与消费者绑定

~~~text
代理选择授权商品或商城主页
  → 生成带唯一邀请码的二维码/链接
  → 消费者打开小程序
  → 系统暂存 30 分钟有效候选；仅客户端带回旧候选 token 时，新有效码替换该旧候选
  → 消费者登录
  → 未绑定时展示服务关系确认
  → 确认后长期绑定该一级代理；拒绝则清空待确认码并保持直营
  → 已绑定时忽略新的邀请码并显示当前服务代理
~~~

### 4.3 消费者购买与佣金入账

~~~text
消费者浏览并选择 SKU
  → 提交订单，按 SKU 保存订单项快照、记录归因候选并创建 PENDING_PAYMENT 订单
  → 用户可立即支付或稍后支付；支付取消/失败仍保留待付款订单
  → Mock 支付成功时再次校验代理 ACTIVE
  → 校验通过：逐订单项按 SKU、一级分类、平台默认顺序解析有效比例
  → 冻结代理、规则版本/来源、分类、商品、SKU、比例、基数和预计佣金
  → 校验不通过：订单转为 DIRECT，不产生佣金
  → 订单进入待发货，已冻结佣金记为预计
  → 总部发货，消费者确认收货或总部兜底完成
  → 订单完成
  → 佣金立即进入可提现余额
~~~

### 4.4 退款与佣金冲正

~~~text
提交售后
  → 客户端只提交订单项、数量、类型、原因和凭证；服务端按订单项快照计算申请金额
  → 事务性占用订单项可退数量和金额；任一活动占用都阻断整单发货
  → 驳回或允许阶段取消时释放占用；退款失败保留占用供重试

未发货退款成功
  → 自动回补对应 SKU 库存
  → 部分退款只履约剩余数量；全额退款关闭订单履约并显示“退款完成”
  → 按原订单项支付快照比例追加预计佣金减少/取消流水

完成后退款
  → 生成不可篡改的负向佣金流水
  → 可提现余额可能变为负数
  → 负余额期间禁止新提现，后续佣金优先抵扣

已发货退货退款
  → 审核通过时冻结总部退货地址快照
  → 消费者填写退货物流，总部逐项记录实收、批准退款和四类处置数量
  → PASS 仅允许全量实收、全量批准且不退回客户；少件或 0 件进入 ABNORMAL
  → 验货通过后退款；异常时按冻结批准数量继续退款或验货后拒绝
  → 只有回库数量增加库存，其他处置只保留事实流水
  → 发货后全额退款成功时订单以 FULL_REFUND_AFTER_SHIPMENT 原因完成，原履约事实不回退
~~~

### 4.5 代理提现

~~~text
代理选择已绑定银行卡并提交提现
  → 金额从可提现转入冻结
  → 超级管理员审核
  → 拒绝：冻结金额退回可提现
  → 通过：总部线下银行转账
  → 上传付款凭证并标记已支付
  → 提现完成，保留申请和银行卡快照
~~~

## 5. 核心功能集

### 5.1 消费者小程序

1. 首页匿名展示 Banner、一级分类、热销和新品；四个分区分别返回 `READY/UNAVAILABLE`，单区失败只清空该区，四区全部失败才返回整页错误。上限固定为 Banner 10、分类 8、热销 4、新品 4。
2. 搜索关键词仅匹配 trim 后的商品名称，大小写不敏感且长度为 1–200；品牌、分类仍作为独立筛选。消费者目录不返回软删除、内部状态、版本、成本、预占或其他管理字段。
3. 目录只展示生命周期为 `ACTIVE` 的商品及全部 `ACTIVE` SKU。零库存 SKU 保留并返回 `is_salable=false`；全部 SKU 售罄时商品仍可浏览，但加购和立即购买禁用。
4. 商品列表支持综合、热销、新品和价格排序；综合排序固定为 `is_hot DESC,is_new DESC,sales_count DESC,published_at DESC NULLS LAST,product_id ASC`，价格取 ACTIVE SKU 最低价，热销按净销量，新品按首次发布时间。
5. 游客可浏览并维护按 `sku_id` 区分的版本化本地购物车；进入购物车时重新读取公开详情刷新价格、库存和状态，网络失败不得误判下架。收藏、地址、订单、支付和售后需要登录。
6. 首次有效代理邀请码在登录成功后触发绑定确认；价格、支付和售后主体始终为总部商城。
7. 已绑定用户只能查看当前服务代理，不能自行改绑或解除。
8. 创建订单前重新校验商品状态、价格、地址和库存；代理失效只将归因降级为直营，不阻断购买。提交成功即生成待付款订单并锁库存 30 分钟，“稍后支付”和支付取消不丢失订单。
9. 订单列表按本人范围返回商品/SKU 摘要、金额、售后摘要、统一展示状态和当前可用动作；详情同时展示订单、支付、退款进度、退款处理和履约状态轴，并映射为待付款、待发货、运输中、已完成、退款完成等用户状态。
10. 用户可主动取消待付款订单；存在活动支付意图时必须先进入可恢复关闭流程，取消、支付与超时按订单锁串行。
11. 用户可在有效期内发起仅退款或退货退款；客户端只选数量，金额由服务端按快照计算。退货审核通过后展示退货地址快照，并可查看验货异常和处置结果。
12. 用户可自愿授权并管理独立账户手机号；未授权不阻断下单。账号删除必须阻断未结清支付、退款、财务异常、未完成订单和售后，完成后代理侧历史客户快照去标识化。

### 5.2 一级代理工作台

1. 账号由超级管理员创建，使用账号密码登录，首次登录必须修改临时密码。
2. 首页展示本人归属净销售额、有效订单、绑定客户、预计佣金、可提现余额、冻结金额和负余额警示。
3. 推广中心默认展示全部当前及未来在售商品；总部切换为自定义授权时仅展示白名单商品，可复制链接、下载或展示二维码。白名单只限制推广，不限制绑定客户购买全店商品或计佣。
4. 当前客户列表仅查询当前有效绑定且归属本人的客户，并显示服务端生成的脱敏昵称、已验证账户手机号后四位（未授权时显示“未绑定”）、最近归属支付订单城市、绑定时间、当前归属期订单次数和净消费汇总；接口不得通过状态参数返回 `UNBOUND/ENDED` 或已转出客户当前资料。客户转出后从列表移除，代理只可在历史订单中查看支付时冻结的脱敏快照。客户删除账号后，历史快照改为不可逆客户代号且不再返回手机号尾号。
5. 订单列表仅显示支付成功时冻结本人代理快照的归属订单，不显示待付款候选；列表包含商品/SKU 摘要、客户城市、金额、独立状态轴映射、售后进度和查看动作，详情补齐关闭/完成原因、支付处置和时间线，但不展示详细地址或任何履约写操作。
6. 佣金列表区分预计、可提现、退款冲正和提现冻结相关流水，禁止人工编辑。
7. 代理可维护本人银行卡并提交提现申请；保存后银行卡页面和日志只显示掩码。
8. 代理无权更改商品价格、库存、订单状态、物流、退款、售后或客户归属。

### 5.3 总部管理后台

1. 首个超级管理员由受控部署命令创建；超级管理员通过账号密码登录，在 ADM-16 绑定 TOTP 并获得恢复码。密码/TOTP 重置使全部旧会话失效，丢失全部凭据时只能走双人审批的离线恢复流程。
2. 看板分别展示今日创建订单数、今日有效支付订单数、注册客户总数、新增注册客户、新增绑定客户和周期活跃代理，避免把注册与绑定混为同一指标；并提供日/月销售、商品销量和客户消费排行。
3. 商品管理覆盖品牌、分类、商品、图片、SKU、价格、库存、上下架和推荐；商品列表按 SPU 展示 SKU 数、实物/锁定/可售库存摘要，并可下钻每个 SKU 与库存流水。
4. 订单与售后由总部统一处理，代理无履约权限。ADM-16 维护当前退货地址；退货审核通过时保存地址快照，验货结果和回库决定不可用后续配置覆盖。
5. 超级管理员可创建、编辑、启用或停用一级代理，轮换/停用邀请码，并在“全部在售商品”和“自定义白名单”两种推广授权模式间切换；代理列表展示账号/状态、当前客户、归属净销售、钱包余额和创建时间，详情可按目标代理下钻客户、订单、佣金流水、钱包流水、提现和审计日志，代理档案不配置独立佣金比例。
6. 超级管理员可在佣金规则管理中设置平台默认比例、商品一级分类默认比例和 SKU 覆盖比例；页面展示有效比例、继承来源和生效影响。
7. 佣金规则变更只影响之后支付成功的订单，已支付订单继续使用订单项快照。
8. 超级管理员可转移消费者代理归属；所有高风险动作按 PRD 的唯一控制矩阵执行，不再由各页面自行解释原因、预览、二次确认、TOTP、凭证、幂等和审计要求。
9. 提现审核支持通过、拒绝、付款凭证上传和标记已支付；打款由线下银行转账完成。完整收款账号仅在付款环节由超级管理员完成 TOTP 二次验证后一次性短时查看或复制，全部留痕并在超时后自动遮蔽。
10. 账户与业务规则设置提供最低提现金额和售后申请天数配置；修改只影响后续新申请或后续完成订单，不回写历史事实。

## 6. 关键业务规则

### 6.1 代理归属

- 每个一级代理拥有唯一邀请码；邀请码同时具有独立启停/有效期，代理停用时不可使用。
- 超级管理员可轮换或单独停用邀请码；轮换后旧码立即失效，但已有长期绑定、历史订单和佣金不变。
- 未登录且未绑定用户暂存 30 分钟有效候选；只有客户端携带有效旧候选 token 时，新有效码才替换该候选，未携带时服务端不得关联匿名事实，旧候选自然过期。
- 登录后用户必须明确确认或拒绝：确认成功才创建长期绑定；拒绝立即清空待确认码并保持 `DIRECT`。
- 已有长期绑定的消费者忽略所有新邀请码；消费者无权自行改绑。
- 已绑定用户访问其他代理链接时保持原绑定，不覆盖、不提示改绑。
- 已登录但未绑定用户打开有效代理链接时立即显示服务关系确认，并在确认或拒绝后返回原页面。
- 同一消费者并发确认两个代理时，以绑定记录上的事务锁/版本号串行，首个提交成功的绑定胜出；后到请求返回当前已绑定代理，不覆盖、不重复建历史。
- 超级管理员转移归属只影响后续创建的订单；历史订单和佣金账本不可回写。
- 客户转移与订单提交按同一绑定记录锁/版本号串行：先提交订单则该订单保留提交时归因候选，先完成转移则后续订单使用新代理；两者均保存裁决版本和审计。
- 代理停用后禁止登录和新绑定。订单提交仅记录归因候选，支付成功时再次复核代理 `ACTIVE`；支付前停用则最终按 `DIRECT` 处理且无佣金。
- 代理停用与支付确认按代理状态行/版本号串行：支付先提交则冻结当时有效代理快照，停用先提交则该次支付归因降级为 `DIRECT`；代理失效从不阻断消费者支付或购买。
- 支付成功后才冻结订单代理与佣金快照；支付后停用不影响已冻结的 `EXPECTED`，订单完成时仍正常进入可提现。
- 重新启用只影响未来业务：未被转移的长期绑定恢复归因资格；邀请码仅在自身仍启用且未过期时恢复；停用期间已经按 `DIRECT` 支付的订单不追溯。

### 6.2 佣金

- 所有一级代理共用同一套佣金规则；代理档案不保存独立佣金比例。
- 有效比例解析优先级固定为 `SKU 覆盖比例 > 商品一级分类默认比例 > 平台默认比例`。
- SKU/分类比例为空表示继续继承；`0%` 是有效显式值并立即终止继承。比例范围固定为 `0.0000%` 至 `100.0000%`（含边界），数据库使用 `DECIMAL(7,4)`，超范围值必须拒绝。
- 现有商品一级分类作为佣金分类来源。商品必须且只能归属一个有效一级分类；变更商品分类只影响变更后支付订单。
- 佣金基数为归属订单项的净商品实付金额，不含运费；首期运费为 0。
- 订单提交时记录归因候选；支付成功时复核代理 `ACTIVE`，逐订单项解析有效比例并冻结代理 ID、规则版本、命中来源、一级分类、商品、SKU、比例、佣金基数和预计佣金快照。
- 佣金计算公式为 `订单项净商品实付金额 × 支付时有效比例 / 100`；每个订单项独立按 `HALF_UP` 保留两位，再汇总订单总佣金，不能使用订单平均比例反算。
- 支付后的规则修改、分类移动或 SKU 覆盖清空均不追溯已冻结快照。
- 支付成功后佣金进入 `EXPECTED`；确认收货或总部兜底完成后立即转为 `AVAILABLE`。
- 完成前部分退款按原订单项快照比例减少预计佣金；完成前全额退款将 `EXPECTED` 标记为 `CANCELLED`。
- 完成后退款保留原 `AVAILABLE` 记录并追加 `REFUND_DEBIT` 负向佣金流水，不删除、不覆盖原入账记录。
- 分次退款累计冲减不得超过该订单项原佣金；最后一笔使该订单项全额退清时，直接冲减剩余佣金，消除逐笔舍入尾差。
- 订单完成与退款成功并发时按订单项佣金快照行锁/版本号串行：退款先提交则完成仅结转退款后的剩余预计佣金，完成先提交则退款追加 `REFUND_DEBIT`；两种顺序的净结果一致且不得重复入账。
- 负余额阻止新提现；未来佣金先抵扣负余额后再形成可提现余额。
- 当前版本不支持代理维度覆盖、“代理 × SKU”、固定金额、阶梯或限时活动佣金。
- 自定义商品白名单只决定代理可见及可生成推广物料的商品；已绑定客户购买白名单外 SKU 仍按本节统一规则计佣，白名单状态不进入佣金快照。

### 6.3 提现

- 提现最低金额默认 100 元，由总部业务规则设置配置；修改仅影响之后提交的申请，首期不收手续费。
- 同一代理同一时间最多存在一笔待审核或已通过待付款的提现申请。
- 提交提现时校验可提现余额、负余额、银行卡和代理状态，并将金额转入冻结。
- 审核拒绝必须填写原因，冻结金额退回可提现余额。
- 审核通过后不可由代理撤回；总部完成线下银行转账后上传付款凭证并标记已支付。
- 提现记录保存银行卡快照；银行卡号加密存储，默认界面、接口响应和日志均掩码显示。
- 只有 `SUPER_ADMIN` 在已通过待付款的提现详情中可使用本人 TOTP 二次验证；验证成功签发绑定“当前管理员 + 当前提现单”的 60 秒单次授权。完整账号仅可查看或复制一次，离页、使用或超时立即清除明文；连续失败 5 次锁定 15 分钟，查看、复制、失败、锁定和清除均记录审计。

### 6.4 价格、库存、订单与售后

- SKU 零售价是首期唯一成交价，服务端是最终计价来源。
- 金额使用精确十进制保存，API 以十进制字符串返回。
- 可售库存 = 实物库存 - 锁定库存，且始终满足 `实物库存 >= 锁定库存 >= 0`；创建订单锁定，支付后由预占转为已售，取消或确认关单后释放。库存调整必须预览调整后余额并以条件更新拒绝破坏该不变量的操作。
- 购物车和订单均以 `sku_id` 为行键；订单保存商品、SKU、规格、单价和数量快照，代理归因候选在提交时记录，最终代理与逐订单项佣金规则快照在支付成功时冻结。
- 提交订单即创建 `PENDING_PAYMENT` 并返回 `pay_expires_at`；数据库固定生成 `pay_expires_at = created_at + 30 分钟`，创建后任何角色和普通配置均不可修改。支付失败、取消或“稍后支付”均保留订单，可在有效期内继续支付。
- 每张订单同一时刻最多一个活动支付意图。支付意图使用稳定唯一的 `intent_no`，状态至少包含 `CREATING`、`OPEN`、`CLOSE_PENDING`、`CLOSED`、`SUCCEEDED`、`FAILED`、`CANCELLED`、`EXPIRED`；其中 `CREATING/OPEN/CLOSE_PENDING` 均视为活动状态。
- 调用支付 Provider 前先落库 `CREATING + intent_no`。创建结果未知时必须按该 `intent_no` 查询恢复，不得直接新建支付意图；关闭结果未知时保持 `CLOSE_PENDING` 和库存预占，由任务查询/重试，确认 Provider 不可支付后才关单并释放库存。
- 用户主动取消、支付确认和超时任务使用同一订单锁/版本号串行。支付先提交则取消/超时失败；关单先提交则后到支付成功进入迟到支付退款，不得恢复订单。活动支付意图未确认关闭前，取消/超时不得释放库存。
- 支付回调收件箱和定时对账必须扫描长期 `CREATING/OPEN/CLOSE_PENDING`、缺失回调和 Provider/本地状态差异，自动查询、补记或补偿；无法自动收敛时进入可审计的人工财务异常。
- 订单、支付、退款进度、退款处理和履约采用独立状态轴。退款进度固定为 `NONE/PARTIAL/FULL`，仅由已成功退款累计结果派生；退款处理固定为 `IDLE/REFUNDING/FAILED`，处理中或失败不伪装为已退款，`FAILED` 在展示状态中优先提示人工处理。
- 未发货全额退款成功时订单 `CLOSED`、关闭原因 `FULL_REFUND_BEFORE_SHIPMENT`、履约 `CANCELLED`，用户侧显示“退款完成”。已发货全额退款成功时订单保持/进入 `COMPLETED`、完成原因 `FULL_REFUND_AFTER_SHIPMENT`，已发货、物流和签收事实不得回退或改写为 `CANCELLED`。
- 用户只可取消待付款订单；已支付订单必须走售后流程。后台兜底完成原因至少区分 `CUSTOMER_CONFIRMED`、`ADMIN_FORCED`、`FULL_REFUND_AFTER_SHIPMENT`。
- 发货必须录入承运商和运单号；确认收货后订单完成。
- 后台兜底完成必须填写原因并记录审计。
- 售后申请期默认 7 个自然日，由总部业务规则设置配置并在订单完成时确定；该期限不延迟佣金入账。
- 商品售后客户端只提交订单项、申请数量、售后类型、原因、说明和凭证，不接收用户填写的退款金额。服务端按订单项成交与优惠分摊快照、已成功退款和活动占用计算本次金额；尾笔退清该订单项时用剩余可退金额消除舍入尾差。
- 纯金额补偿使用后台专属 `AMOUNT_COMPENSATION` 类型，与商品数量售后分离：不占用可退数量、不回库，但必须占用剩余可退金额，退款成功后按原订单项快照冲正佣金。
- 售后提交时事务性占用订单项剩余可退数量和金额；并发申请不得超退。首期为单包裹，任一未发货订单项存在活动售后占用时整单禁止创建或确认发货，不允许绕过占用先发其他商品。
- 用户只可在 `PENDING_REVIEW`，或尚未填写退货物流的 `WAITING_RETURN` 阶段取消；驳回或允许阶段取消时释放占用。退款失败进入 `REFUND_FAILED`，保留占用供总部幂等重试。
- 退货审核通过时从 ADM-16 当前有效总部退货地址生成不可变快照；消费者按快照退回并填写承运商/运单号。总部验货请求一次精确覆盖全部售后项，逐项记录实收、批准退款、验货结果 `PASS/ABNORMAL`、异常说明/凭证及回库、损坏、报废、退回客户四类处置数量；必须满足“批准退款 + 退回客户 = 实收”和“批准退款 = 回库 + 损坏 + 报废”。`PASS` 必须全量实收、全量批准且不退回客户，可提交零份证据；少件、0 件或不符必须 `ABNORMAL` 且至少一份证据。两类结论的证据清单均在提交时按文件 ID 封存，之后不可增删、替换或改绑。异常只允许一次类型化解决为 `CONTINUE_REFUND` 或 `REJECT_AFTER_RETURN`；继续退款原因必填且只能使用冻结批准数量，拒绝仍按高风险矩阵填写原因，解决类型、原因和时间不可改写，终态释放未实收/退回客户占用，所有处置留痕。
- 未发货退款成功自动回补对应 SKU 库存；部分退款待占用全部解决后，仅按最终剩余数量创建唯一包裹，全额退款终止履约。已发货退货仅按验货决定回库并生成库存流水。
- 退款金额不得超过订单项剩余可退实付金额，佣金按同一订单项退款事实以新增流水冲正，原始佣金快照永不修改。
- 退款成功与订单完成按同一订单/订单项锁和幂等键串行，确保退款进度、完成原因、佣金结转/冲正和库存流水只执行一次。
- 品牌、分类、商品和 SKU 均软删除。存在在售商品的分类或品牌禁止停用；必须先迁移或下架商品。商品/SKU 存在活动库存预占时禁止软删除；普通下架只阻止新加购和新结算，已有合法预占的待付款订单仍可在 `pay_expires_at` 前付款。历史订单、佣金规则版本和交易快照永久保留。
- 品牌和一级分类只能以 `DRAFT` 创建，列表固定按 `sort_order ASC,id ASC`。非删除记录只允许 `DRAFT/INACTIVE -> ACTIVE`、`ACTIVE -> INACTIVE`，以及 `DRAFT/INACTIVE -> ARCHIVED + deleted_at`；ACTIVE 不得直接软删除。生命周期启用、停用和软删除均先预览再确认；恢复只针对软删除 ARCHIVED，固定回到 DRAFT，之后须另行启用。默认列表排除归档，显式归档筛选和按 ID 详情支持恢复操作。
- 商品固定以 `DRAFT` 创建，SKU 固定以 `INACTIVE` 创建。两者均通过独立的 ACTIVATE/DEACTIVATE/SOFT_DELETE preview-confirm 上下架或归档；Product 恢复为 DRAFT，SKU 恢复为 INACTIVE，任何状态变化均不级联修改子记录。商品启用要求 ACTIVE 品牌/分类、至少一张 READY/PUBLIC 商品图和至少一个 ACTIVE SKU；商品软删除要求没有 ACTIVE SKU 和活动库存预占，SKU 软删除要求没有活动库存预占。
- SPU/SKU code 创建后永不可改且软删除后保留。商品图集最多 8 张并按 `sort_order,id` 排序；SKU 创建同时生成物理/锁定库存均为 0 的余额。商品列表固定 `published_at DESC NULLS LAST,id DESC`，首次启用写 `published_at` 且重新启用不覆盖；没有 ACTIVE SKU 时最低活动价为 `null`。商品详情返回全部 SKU，包括 ARCHIVED，并按 `created_at,id` 排序。
- 七类文件统一只接受 JPEG/PNG 且最大 5 MiB。上传意图必须声明 64 位小写 SHA-256；完成时由服务端复核 MIME、魔数、大小和哈希。上传签名 15 分钟、私有下载签名 5 分钟，满 24 小时的 PENDING/staging 才可进入清理候选；bucket 默认私有，仅 `public/*` 允许匿名 GET，私有素材固定使用 `private/*`。
- 所有列表/详情响应按消费者、代理、总部专用投影返回；同名业务字段也必须明确本人范围、当前归属期或全生命周期口径，禁止前端接收超范围字段后再隐藏。
- 临时密码、TOTP 绑定 URI/恢复码、邀请码明文、银行卡查看授权、预览/确认能力令牌和签名文件 URL 等短时凭据/能力响应均使用 `Cache-Control: no-store`，仅在签发当次展示；页面刷新、离页、消费或到期后不得从缓存或普通详情接口再次取得。
- 完整地址仅允许在最小授权场景返回：消费者查看本人收货地址/订单、消费者查看本人已通过退货审核的总部退货地址快照，以及总部用途绑定的履约地址读取；三类响应均禁止缓存。代理端、列表、日志、错误、审计摘要和自动化截图不得出现详细地址或完整手机号。

## 10. 风险与应对

| 风险 | 影响 | MVP 应对 |
|---|---|---|
| 代理被误解为多级或独立商户 | 范围膨胀、账务复杂 | 文档、页面和权限统一使用“一级代理”，禁止下级和独立经营 |
| 归属候选被错误覆盖或过期 | 渠道争议 | TTL 30 分钟、仅凭有效旧候选 token 替换、不采集设备标识、明确确认/拒绝、支付时最终复核 |
| 代理越权访问客户或订单 | 隐私泄露 | 服务端按代理归属过滤，字段脱敏，禁止相信前端筛选条件 |
| 退款后佣金已被提现 | 平台形成应收 | 负向账本、允许负余额、冻结新提现、未来佣金抵扣 |
| 线下打款凭证缺失 | 财务难审计 | 审核与付款分状态，标记已支付必须上传凭证 |
| 代理停用后的存量订单争议 | 佣金口径不一致 | 支付时最终复核；支付后停用不影响已冻结佣金；重启不追溯停用期订单 |
| 分类或 SKU 规则修改污染历史 | 渠道对账争议 | 支付时逐订单项冻结规则版本、命中来源和金额，规则版本只追加、不追溯 |
| 分次退款产生舍入尾差 | 冲正后账实不平 | 累计冲减封顶原订单项佣金，尾笔全退直接冲清剩余金额 |
| 并发售后导致超数量或超金额退款 | 财务、库存和履约不一致 | 客户端不提交金额；服务端按快照计算并事务占用额度；活动占用阻断整单发货 |
| 支付 Provider 返回未知或超时关单后成功 | 重复扣款、重复意图或无货发货 | 稳定 `intent_no` 查询恢复，`CLOSE_PENDING` 不释放库存，对账补偿；迟到成功只退款 |
| 未发货退款后库存或履约未同步 | 库存虚减或误发 | 成功退款自动按 SKU 回库；全额退款关闭履约，部分退款在全部活动占用解决后只发最终剩余数量 |
| 付款环节完整卡号泄露 | 财务与隐私风险 | 默认掩码、本人 TOTP、短时一次性查看/复制、使用/离页/超时清除和全量审计 |
| 并发下单导致超卖 | 财务与履约损失 | 事务、条件更新、锁库存、幂等和并发测试 |
| 管理员凭据或 TOTP 丢失 | 无法运维或被绕过二次验证 | 受控首个管理员、一次性恢复码、全部凭据丢失时双人离线恢复、重置后撤销全部会话 |
| 微信资质未提供 | 无法真实登录和支付 | Provider 隔离，设计阶段和演示环境使用 Mock |
| 协议版本由客户端伪造或重复提交 | 无法证明有效同意 | 服务端发布三份权威文档快照；登录严格校验前两份类型唯一、accepted 和当前版本，手机号单独校验第三份 |
| Store/Admin token 跨端接受 | 身份越权 | 固定 role/assurance/audience 并在守卫中拒绝跨端 token；Provider 只在服务端 Adapter 边界使用 |
| 注销只完成部分去标识化 | 隐私与审计不一致 | 5 分钟 preview、确认时重检、单事务去标识化与全部会话撤销，失败整体回滚 |

## 11. MVP 完成标准

1. 三端页面和权限与 PRD 页面编号一致。
2. 超级管理员可创建一级代理、停用账号并查看审计；代理档案无独立佣金比例。
3. 代理首次登录必须改密，且只能查看本人归属的脱敏客户和订单。
4. 未绑定游客的最后有效邀请码按 30 分钟 TTL 覆盖，登录后可确认或拒绝；已绑定用户不会被其他链接覆盖。
5. 购物车、订单项、库存和售后均以 `sku_id` 为最小单位；同商品不同 SKU 可独立加购、结算、退款和回库。
6. 订单提交即生成待付款订单，数据库固定 `pay_expires_at=created_at+30 分钟` 且不可修改；每单最多一个活动支付意图，稳定 `intent_no` 可查询/关闭恢复，`CREATING/OPEN/CLOSE_PENDING`、对账补偿、主动取消/超时/支付串行和迟到支付自动退款均可验证。
7. 订单提交记录归因候选，支付成功复核代理状态后按 `SKU > 一级分类 > 平台默认` 解析，并逐订单项冻结规则版本/来源、分类、商品、SKU、比例、基数和金额；支付前停用转为直营。
8. 支付后停用不影响已冻结预计佣金；收货后进入可提现，完成前退款通过追加预计减少/取消流水处理，完成后退款追加 `REFUND_DEBIT`，原佣金快照不变。
9. 商品售后客户端只提交数量，服务端按订单项快照计算金额并事务性占用数量/金额；纯金额补偿使用独立类型，并发不得超退，允许阶段取消可释放，`REFUND_FAILED` 可重试。
10. 代理白名单仅限制推广物料；绑定客户购买白名单外 SKU 仍按统一规则计佣，撤权旧链接可打开普通商品页但不建立新候选。

12. 负余额阻止提现，后续正向佣金可自动抵扣负余额。
13. 提现可完成提交、审核、TOTP 二次验证 60 秒单次查看/复制收款账号、拒绝退回、线下付款、凭证和已支付闭环；连续验证失败 5 次锁定 15 分钟。
14. 总部可配置统一佣金规则、代理推广授权模式、邀请码轮换、最低提现金额和售后申请天数，并保留变更审计；空值继承与 `0%` 明确无佣金可正确区分。
15. 品牌、分类、商品和 SKU 的上下架/停用/软删除规则可验证；品牌/分类和 Product 创建固定 DRAFT，SKU 创建固定 INACTIVE；Product/SKU 三动作均预览确认，Product 恢复 DRAFT、SKU 恢复 INACTIVE；商品启用校验 ACTIVE 品牌/分类、公开主图和 ACTIVE SKU，ACTIVE SKU/活动预占按 CH-010 阻断软删除，已预占订单可在期限内继续支付，历史快照不丢失。
16. 总部可查看日/月销售报表、商品销量排行和客户消费排行，不依赖 Excel 导出。
17. 总部可完成商品、库存、订单、单包裹发货门禁、退货地址、验货处置、售后和客户管理；商品库存摘要可下钻复算，PASS 可零证据、ABNORMAL 至少一份且两类均封存，异常解决类型/原因不可变；任一活动售后占用必须阻断整单发货，代理无经营或履约写权限。
18. 消费者可完成浏览、购物车/立即购买、待付款订单、Mock 支付、物流、确认收货、两类商品售后、退货异常查看和账户隐私流程；当前 MVP 不出现买家备注。
19. 代理工作台在 390px、1024px 和 1440px，后台在 1024px 和 1440px，小程序在 375px 和 414px 无关键遮挡或横向溢出。
20. 绑定/转移/停用/支付、订单完成/退款等并发顺序均得到相同净结果且不会重复冻结、入账、冲正、回库或释放。
21. 首个超级管理员创建、TOTP 绑定/恢复码、失败锁定、双人离线恢复和会话撤销可验证；所有高风险动作只按 PRD 唯一控制矩阵执行并可审计。
22. 今日订单、有效支付订单、客户、绑定和活跃代理等看板指标按本文件定义核对通过；每个 SKU 单笔上限为 `min(99, 可售库存)`。
