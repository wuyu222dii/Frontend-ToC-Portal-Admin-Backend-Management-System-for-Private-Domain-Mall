# B3.3 功能细节拆解

> 范围：ADM-05 品牌管理、ADM-06 分类管理；基线：v2.4.1 / CH-006；日期：2026-08-14；当前状态：本地验收通过并暂停，结论 `GO`。

本文将已冻结的 PRD、OpenAPI 和静态原型拆成 B3.3 可实施任务。不新增页面 ID、字段、状态或 API，不开放 B4 及后续批次导航。

## 1. 功能总览

| 功能 | 用户价值 | 前置条件 | 完成事实 |
|---|---|---|---|
| 列表与筛选 | 按稳定顺序查找可维护或可恢复的主数据 | SUPER_ADMIN + MFA 会话 | `sort_order,id` 顺序的当前页数据 |
| 创建与编辑 | 维护名称、素材和排序，不绕过生命周期 | 合法表单；可选 READY 公开素材 | 创建固定 DRAFT；编辑按 `If-Match` 更新 |
| 生命周期 | 在知道影响后启用、停用或软删除 | 原因、preview、二次确认、新幂等键 | 一次状态迁移、版本和审计事实 |
| 归档恢复 | 找回软删除原记录而不自动上线 | 显式 ARCHIVED 筛选、原因、`If-Match` | 原 ID 恢复为 DRAFT，如需上线再单独启用 |

## 2. 主流程与分支

### 2.1 列表、筛选与记录绑定

1. 会话守卫确认 `SUPER_ADMIN / MFA / NONE`。
2. 进入页面后加载第 1 页，默认不携带 `status`，因此排除 ARCHIVED。
3. 用户可按名称关键词、状态、页码和每页数查询。
4. 新请求替换旧请求的显示权；迟到的旧响应不得覆盖新筛选或新记录。
5. 用户点击行动作时，弹层、请求 ID、版本和预览事实绑定同一行。

分支：加载中显示表格骨架；零结果显示可重置筛选的空状态；403 显示权限拒绝；500/网络失败保留筛选并提供重试。

### 2.2 创建、编辑与文件上传

1. 品牌输入名称、可选描述、排序和可选 Logo；分类仅输入名称、排序和可选图标。
2. 创建时 `initial_status` 由界面固定为 `DRAFT`，不显示状态选择器。
3. 素材只接受 JPEG/PNG、1..5 MiB；浏览器计算小写 SHA-256。
4. 以独立幂等键创建 upload intent，使用服务端返回的闭合 headers 直传，再以同一 size/hash complete。
5. PUT 不携带 access token/cookie；upload URL、File 与本地 object URL 只存在当前内存流程。
6. 上传完成后表单只保留 `file_id` 和安全公开预览 URL。
7. 创建使用新幂等键；编辑还携带当前版本的引号 `If-Match`。

分支：前端类型/大小不合法时不创建 intent；上传或 complete 失败时保留其他表单值并可重试；409 时关闭编辑层、重载最新记录，禁止自动覆盖。

### 2.3 生命周期 preview-confirm

1. 按状态只显示合法动作：DRAFT/INACTIVE 可启用，ACTIVE 可停用，DRAFT/INACTIVE 可软删除。
2. 用户填写 2..500 字符原因后，以独立幂等键请求 preview。
3. 弹层显示 `affected_count`、metrics、warnings、版本与到期时间。
4. 用户确认时携带相同 action/reason、preview token、confirmation hash、preview resource ETag 和全新幂等键。
5. pending 期间禁用重复提交；成功后清理 preview 内存态并重载列表。

分支：活动商品依赖在 preview 仍是 200，允许用户提交确认；confirm 返回 422 后显示先迁移/下架的提示，不误报成功。409 必须清空旧 preview、刷新记录并要求重新预览。

### 2.4 归档恢复

1. 只有显式 `status=ARCHIVED` 列表显示恢复动作。
2. 用户填写 2..500 字符原因，请求携带新幂等键和当前 `If-Match`。
3. 成功后记录离开 ARCHIVED 列表并以 DRAFT 出现在默认列表。
4. 界面不串联自动启用；如需上线，用户再独立执行 ACTIVATE preview-confirm。

## 3. 数据与权限边界

- 品牌字段：`name`、`description|null`、`logo_file_id|null`、`sort_order`、`status`、`version`。
- 分类字段：`name`、`icon_file_id|null`、`sort_order`、`status`、`version`。
- 不展示或构造编码、分类说明、佣金、商品/SKU 数量或普通编辑状态下拉。
- 客户端路由守卫只是交互边界；真实授权继续由 NestJS `SUPER_ADMIN` guard 和当前数据库会话执行。
- localStorage 仍只允许已记住的登录名；会话 token、幂等键、签名 URL、preview 能力和文件明文均不持久化。

## 4. 界面与状态

- 桌面 1024/1440：紧凑工作台、筛选工具条、稳定宽度列表、行动作和右侧抽屉/对话框。
- 移动 375/390/414：品牌、分类、账户安全三项底部导航；工具条换行；数据以紧凑行或组件内滚动呈现，不产生页面级横向溢出。
- 所有图标按钮有可读名称/提示，图片有 alt，状态不仅依赖颜色。
- 请求 pending 不改变布局尺寸，最长文案在弹层和窄视口可换行。

## 5. 验收与任务

| 层级 | 必要验收 |
|---|---|
| 请求层 | 闭合 body、安全 URL、SHA-256、PUT 无 bearer/cookie、401 单飞刷新、写重试复用幂等键 |
| 功能 | 创建 DRAFT、素材上传、编辑排序、三种 lifecycle、归档筛选、restore-to-DRAFT |
| 异常 | loading、empty、500、403、409、422、重复点击、迟到响应、上传失败可重试 |
| 安全 | 浏览器存储/控制台不含 token、签名 URL 或 preview 能力；离页清理内存和 object URL |
| 响应式 | 375/390/414/1024/1440 非空白，无遮挡、不可点击或页面级横向溢出 |
| 回归 | B2 密码/TOTP/恢复码/绑定/账户安全流程；admin-web typecheck/build；workspace `check` |

开发任务分为：共享管理端请求层、catalog 类型/服务、文件上传组件、参数化主数据页、路由导航、B2 回归、B3.3 五视口 E2E 和交付文档。B3.3 本地验收后暂停，不自动进入 B4；B3 整体完成仍受 CH-007 远端证据门禁限制。
