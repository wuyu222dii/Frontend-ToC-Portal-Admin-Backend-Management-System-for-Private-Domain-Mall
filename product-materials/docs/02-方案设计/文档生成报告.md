## 2. 当前业务基线

1. 总部统一管理商品、SKU 价格、库存、收款、发货、退款、售后、代理和提现。
2. 代理严格单层，由总部创建；代理不改价、不持有库存、不发货、不处理售后。
3. 所有一级代理共用平台默认、一级分类默认、SKU 覆盖的百分比佣金规则，优先级为 SKU > 分类 > 平台。
4. 推广白名单只限制代理推广权限；已绑定客户购买全店任意 SKU 仍按统一规则计佣。
5. 订单项、购物车、库存、发货、售后、退款和佣金均以 sku_id 为最小事实单位。
6. 订单、支付、退款进度、退款处理和履约状态分轴保存，display_status 由服务端按唯一优先级计算。
7. 支付意图使用稳定 intent_no 和可恢复状态；主动取消与超时关单确认不可支付后才释放库存。
8. 售后金额由服务端按订单项快照计算；申请事务性占用数量和金额，退款失败保留占用供重试。
9. MVP 每单唯一包裹；存在有效售后占用时整单禁止发货。
10. 佣金快照与正向流水不可变，退款只追加减少、取消或 REFUND_DEBIT 流水。
11. 管理员采用 TOTP、恢复码和双人离线恢复；完整收款账号仅在批准提现下短时单次展示。
12. 三端只能访问 NestJS HTTPS API，不使用 Supabase Auth、Storage、Realtime 或 Data API 直连业务表。
13. 品牌/分类创建固定 DRAFT，按 `sort_order,id` 排序；启用、停用、软删除均预览确认，恢复 ARCHIVED 固定回 DRAFT。
14. 七类文件仅 JPEG/PNG、最大 5 MiB，上传前声明 SHA-256；签名、对象分区、24 小时清理候选和完成幂等边界按 CH-006 执行。
15. Product/SKU 固定 DRAFT/INACTIVE 创建，使用专用三动作生命周期并分别恢复 DRAFT/INACTIVE；Product 发布校验品牌、分类、公开商品图和 ACTIVE SKU，状态变化不级联。
16. Product 列表使用 null-last 发布时间排序和 nullable 最低活动价；详情包含归档 SKU，图集最多 8 张；SKU 创建同步零库存余额，SPU/SKU code 永不可改或复用。
17. Banner 创建 DRAFT、资料编辑不改状态、ACTIVE 不得直接归档、恢复回 DRAFT；公开投影按状态、有效窗口、公开文件和有效 target 联合过滤，HTTPS URL 必须命中 origin allowlist。
18. 库存固定 `available=physical-locked`，不提供低库存阈值；人工调整使用非零 int32 delta、HR-07 preview-confirm、版本/幂等和只追加闭合流水，失败不消费 preview。
19. 匿名目录返回全部 ACTIVE SKU，零库存使用布尔 `is_salable=false`；全 SKU 售罄时 Product 仍可浏览。
20. Store 商品默认 COMPREHENSIVE，并支持 HOT/NEWEST/PRICE_ASC/PRICE_DESC；搜索仅匹配 trim 后 1-200 字符的商品名，大小写不敏感。
21. 公开品牌/分类无分页，返回全部 ACTIVE 记录；首页四区使用 `READY|UNAVAILABLE`，单区失败降级为空数组，全部失败才返回 500。
22. 5 个匿名 Store GET 共享 Redis 固定窗口，每 HMAC 来源 IP 每 60 秒 120 次；不保存原始 IP，超限返回 429 和准确 `Retry-After`，Redis 异常不得绕过。
23. API 默认不信任代理头；只有 `API_TRUSTED_PROXY_CIDRS` 显式数字 IP/CIDR 才作为直接可信代理，IPv4-mapped IPv6 归一化为 IPv4，未经信任的 `X-Forwarded-For` 不影响限流来源。
24. B7 法律文本由服务端发布当前用户协议、隐私政策、手机号授权说明三份快照；登录同意前两份、手机号授权同意第三份。Store token 固定 `role=CUSTOMER`、`assurance=WECHAT`、`audience=qingxu-store`，管理端 audience 保持 `qingxu-admin-web`；Provider 不属于 token claim。
25. profile/手机号写入使用 If-Match 与幂等；客户端不能选 Provider。归因目标服务端解析，candidate token 只存哈希、30 分钟有效，查询不消费、替换或登录迁移时原子失效，服务代理使用三字段最小投影。
26. 账号注销使用 5 分钟 preview 与同步 confirm；不合格预览不签发能力，确认重检并在单事务完成去标识化和全部会话撤销。
27. 登录后收藏保留失效商品并使用独立三状态投影；服务端购物车懒创建、持久化 selected、五状态实时投影，游客 merge 使用固定 journal/幂等键且全成全败。
28. 收货地址列表只返回脱敏摘要，详情限本人；手机号/详情使用 AES-256-GCM 与字段 AAD，默认地址、If-Match、HASH_ONLY、no-store 和 CUSTOMER+IP fail-closed 限流按 CH-018 执行。
29. B9 报价统一覆盖 CART 与 BUY_NOW；CART 必须精确匹配服务端当前已选项，BUY_NOW 必须恰好一个 SKU，阻断报价仍返回 200 但不签发确认能力。
30. 可提交报价使用 5 分钟无状态 HMAC，绑定客户、会话、规范请求、地址版本、商品/SKU/库存版本、价格和过期时间；token/hash 不落数据库、Redis、日志或审计。
31. 下单在 Serializable 事务中按 customer/cart/address/catalog→SKU/balance→insert order/reservation 重验报价与当前事实，写入待付款订单、订单项、重新加密地址快照、归因候选、ACTIVE 预占、唯一 `ORDER_RESERVE` 流水、审计、Outbox 和 HASH_ONLY 幂等事实。
32. 候选 reservation/SKU ID 只允许无锁定位；主动取消和超时 Worker 共用 `idempotency（Worker 跳过） -> order -> payment_intent -> SKU ASC -> balance ASC -> reservation ASC -> ledger -> audit/outbox` 原子关闭流程，禁止与首次下单锁序混用或让 reservation 先于 SKU/balance。
33. CH-020 允许新增 `0002_b9_inventory_fact_indexes` 前向索引迁移；两份 `0001_initial` 逐字节不变，代码回退保留加法索引，不执行数据库降级。
34. CH-022 的支付 Provider 由服务端配置；Mock 结果只允许 SUCCEEDED/FAILED/CANCELLED，结果先写 Inbox 再由 Worker 收敛，客户端不得提交 Provider、交易号或迟到状态。
35. 支付成功原子结算订单、消耗预占、同时扣减实物/锁定库存并冻结归因/佣金；活动意图关单结果 UNKNOWN 时保持库存锁定并进入对账。
36. 已关闭订单的迟到成功不复活订单、库存、履约、归因或佣金，只创建唯一全额 LATE_PAYMENT 退款；失败/未知进入 MANUAL_REQUIRED。
37. CH-022 允许新增 `0003_b10_payment_fact_indexes`，仅增加 intent 成功事实与订单迟到退款两个条件唯一索引；既有迁移逐字节不变。
38. CH-024 将 B11 限定为已支付订单的一单一包裹履约：总部读取订单与用途绑定的履约地址，录入承运商/运单号后一次发货并人工维护物流节点。
39. Store 只查看本人订单物流并在服务端允许时确认收货；SUPER_ADMIN 可填写原因兜底完成，AGENT_ADMIN 继续只读且没有履约写权限。
40. 首次完成将订单 `EXPECTED` 佣金一次性转为 `AVAILABLE`；重复、并发完成及重复消息不得重复入账，也不得回写支付、库存或归因快照。
41. B11 零迁移，复用冻结 Schema 与 `0001→0004` 迁移链；普通售后、第三方物流、自动确认、多包裹、真实支付、staging/production 均排除。
