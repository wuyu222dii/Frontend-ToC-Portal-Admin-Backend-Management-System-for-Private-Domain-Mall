# 青序生活私域商城 · 腾讯云部署方案

> 适用仓库：本 monorepo（消费者小程序、一级代理工作台、总部后台、NestJS API、NestJS Worker）。  
> 当前基线：产品/API 以仓库根 `README.md` 为准；B16/B17 staging 证据未闭合前，**staging / production / 真实客户数据 / 真实资金仍为 `NO-GO`**。  
> 本文是运维操作手册，不替代 [技术架构说明](技术架构说明.md)、[B0 工程与数据库](../05-开发管理/B0-工程与Supabase.md)、[B16.3 安全与环境准入清单](../05-开发管理/B16.3-安全与环境准入清单.md)、[B16.2 备份恢复回滚演练](../05-开发管理/B16.2-备份恢复回滚演练.md)。

## 1. 文档目的与边界

本文给出**可以按步骤在腾讯云落地**的首期部署方案：把 API、Worker、Redis、对象存储、静态站、HTTPS 入口放到国内腾讯云，方便微信小程序访问与备案域名接入。

必须同时遵守现有代码门禁，不能为了“上云方便”改坏安全边界：

| 约束 | 现状 | 对腾讯云的含义 |
|---|---|---|
| 三端只调 NestJS HTTPS | 禁止前端持有数据库连接或 `service_role` 密钥 | 小程序 / 后台 / 代理只配置 HTTPS API 域名 |
| `DATABASE_URL` 必须是 `mall_runtime` | `packages/config` 校验角色名 | 运行容器不得持有 `postgres` / `mall_migrator` |
| 远端库主机必须是已批准的托管 PostgreSQL | `DATABASE_PROVIDER=tencentdb` 时只接受 `*.sql.tencentcdb.com` / `*.postgres.tencentcdb.com` / `*.pg.tencentcdb.com`，`sslmode=verify-full` + 显式 CA，角色仅 `mall_runtime` / `mall_migrator` | 运行库用 TencentDB 内网域名，不要填内网 IP |
| 远端 Redis 必须 `rediss://` | 非 loopback 禁止明文 `redis://` | 必须开腾讯云 Redis 的 TLS |
| 远端对象存储必须 HTTPS | `S3_ENDPOINT` 只能是源站 origin（无 path）；`S3_PUBLIC_BASE_URL` 的 path 必须恰好是 `/<bucket>` | COS 必须用 path-style 公网基址，例如 `https://cos.ap-guangzhou.myqcloud.com/mall-staging` |
| 运行账号 ≠ 存储根账号 | `S3_ACCESS_KEY` 不得等于 root | COS 用子用户密钥，不要用主账号密钥 |
| production 禁止 Mock | `STORE_*_PROVIDER=MOCK` 在 production 启动失败 | 真实微信 / 真实支付未演练前不要把 `NODE_ENV` 设为 `production` |
| 代理头默认不信任 | `API_TRUSTED_PROXY_CIDRS` 留空则 `trust proxy=false` | Nginx 本机反代时只登记 `127.0.0.1/32` |

**本期推荐拓扑：**

- 计算、Redis、COS、CLB、CDN、证书、域名、PostgreSQL：全部腾讯云国内地域
- PostgreSQL：TencentDB for PostgreSQL，与 CVM 同 VPC；staging / production 各一个实例，禁止复用 development。进程拒绝任何 `SUPABASE_*` 变量和 `*.supabase.co` / `*.supabase.com` 主机。

**不要做的事：**

- 不要在腾讯云上用 Docker Compose 把 development 的 Redis/MinIO 端口暴露到公网
- 不要把 `.env`、密钥、CA、恢复码写进镜像层、Git、工单正文或截图
- 不要在 B17 外部复核完成前写入真实手机号、地址、银行卡或打开真实微信支付
- 不要对业务库执行 `prisma migrate reset` 或 `docker compose down -v`

## 2. 目标拓扑

```text
微信小程序 ──HTTPS──► api.<你的备案域名> ──CLB 443──► CVM Nginx ──127.0.0.1:3000──► NestJS API
总部后台    ──HTTPS──► admin.<你的备案域名> ──CDN──► COS 静态桶
代理工作台  ──HTTPS──► agent.<你的备案域名> ──CDN──► COS 静态桶
                                                         │
NestJS API / Worker ──TLS──► 腾讯云 TencentDB PostgreSQL（mall_runtime / mall_migrator，内网）
NestJS API / Worker ──TLS──► 腾讯云 Redis（rediss）
NestJS API / Worker ──HTTPS──► 腾讯云 COS（S3 兼容，path-style）
```

建议域名（全部先完成 ICP 备案，再解析到腾讯云）：

| 用途 | 示例 | 解析 |
|---|---|---|
| 统一 API | `https://api.example.com` | CLB |
| 总部后台 | `https://admin.example.com` | CDN |
| 代理工作台 | `https://agent.example.com` | CDN |
| 公开商品图 | `https://cdn.example.com/<bucket>` 或 COS path-style 源站 | CDN / COS |
| 法律文本 | `https://legal.example.com/...` | COS 或独立静态站，必须 HTTPS |

小程序只访问 `api` 与已登记的 `downloadFile` / `uploadFile` 域名，不访问 admin / agent。

## 3. 资源清单与规格

以下按**脱敏 staging 演练**给出起步规格。生产在 B17 `GO` 且真实支付演练通过后再升配、拆分 Worker。

| 产品 | 建议规格 | 数量 | 备注 |
|---|---|---|---|
| CVM | Ubuntu 22.04 LTS，4 核 8 GB，系统盘 50 GB SSD | staging 1 台；production 至少 2 台 API + 1 台 Worker | 时区 `Asia/Shanghai` |
| 云数据库 Redis | Redis 7.x，1 GB，**开启加密传输** | 每环境 1 套 | 仅 VPC 内网，不要开公网 |
| COS | 标准存储，默认私有桶 | 每环境 1 个业务桶 + 1 个静态站桶 | 业务桶禁止整桶公有读 |
| CLB | 应用型负载均衡，HTTPS:443 | 每环境 1 个 | 后端只打 CVM 的 80 |
| SSL 证书 | 腾讯云免费 DV 或已上传证书 | api / admin / agent 各一张或通配符 | 微信要求可信 CA |
| CDN | 静态加速 | admin、agent、公开图 | 回源 COS |
| 密钥管理 / SSM | 密钥管理系统或凭据管理系统 | 每环境独立 | 不要把密钥只放在个人电脑备忘录 |
| 云监控 + CLS | 基础监控 + 日志主题 | API/Worker 各一套 | 禁止日志落密码、token、卡号、明文手机号 |
| 安全组 | 见第 5 节 | 1 组 | 最小端口 |
| 堡垒 / 运维跳板 | 可选轻量 CVM | 1 台 | 仅该机器能 SSH 业务 CVM |

预估费用随账号折扣变化，下单前在控制台费用中心确认；本文不写死金额。

## 4. 前置条件

在点「新建」之前，逐项完成：

1. 腾讯云账号已完成实名认证，并开通 CVM、CLB、COS、Redis、CDN、SSL 证书、云数据库 PostgreSQL。
2. 域名已完成 **ICP 备案**（微信小程序 request 合法域名要求国内已备案 HTTPS）。未备案不要把解析切到国内 CVM。
3. 已准备独立邮箱 / 手机号，用于证书验证、微信公众平台管理员。
4. 本机已安装：Node.js `22.23.1`（见仓库 `.nvmrc`）、pnpm `10.34.5`、Git、`psql`（仅迁移机需要）。
5. 已从批准的 Secret Store 取出 **目标环境** 的全部密钥，而不是复制 development `.env`。
6. 已冻结要发布的 Git SHA，并在该 SHA 上完成本地 `pnpm config:check`（用目标环境变量，不要用 development 值）。
7. 已阅读 B16.3 清单；任一项未勾选，停止切流。
8. 若目标是 staging：必须同时满足 `NODE_ENV=staging`、`STAGING_DEIDENTIFIED_MOCK_ACK=true`，且只使用虚构数据。环境中不得残留任何 `SUPABASE_*`。
9. 若目标是 production：必须关闭全部 Mock Provider，并已完成真实微信登录、支付验签、退款、对账演练。当前仓库状态不满足时，**不要创建 production 环境**。

## 5. 账号、CAM 与网络

### 5.1 子用户，不要用主账号登录业务机

1. 打开 [访问管理 CAM](https://console.cloud.tencent.com/cam)。
2. 新建用户组 `qingxu-ops`，授予：CVM、CLB、VPC、安全组、Redis、TencentDB PostgreSQL、COS、CDN、SSL 证书、云监控、CLS 的日常运维权限。
3. 新建用户组 `qingxu-cos-runtime`，**只**授予目标业务桶 `mall-<env>` 的对象读写删和 `ListBucket`，对应前缀 `public/*`、`private/*`、`staging/*`。
4. 为运行时新建子用户 `qingxu-cos-runtime-<env>`，**只加入** `qingxu-cos-runtime`，勾选「编程访问」，保存 `SecretId` / `SecretKey` 到 Secret Store。  
   - `SecretId` 即 `S3_ACCESS_KEY`，须满足配置校验：以字母或数字开头、长度至少 16。  
   - 不要把主账号密钥配进 API。
5. 运维人员使用自己的子用户 + MFA 登录控制台。

### 5.2 建 VPC

1. 打开 [私有网络](https://console.cloud.tencent.com/vpc)。
2. 地域选 **广州** 或 **上海**（与 COS、Redis、CVM 必须同一地域）。微信用户延迟要实测后再锁生产地域。
3. 新建 VPC：`qingxu-<env>-vpc`，网段例如 `10.20.0.0/16`。
4. 新建子网：
   - `qingxu-<env>-app`：`10.20.1.0/24`（CVM）
   - `qingxu-<env>-data`：`10.20.2.0/24`（Redis、TencentDB）
5. 默认路由走腾讯云网关即可。CVM 需要出网访问 COS（`443`）和微信 API，PostgreSQL 走 VPC 内网，不必对海外 `5432` 开口：
   - staging 可用 CVM 固定公网 IP 出网；
   - production 建议无公网 IP + NAT 网关，入站只走 CLB。

### 5.3 安全组（最小端口）

新建安全组 `qingxu-<env>-sg`，入站：

| 来源 | 端口 | 用途 |
|---|---|---|
| 运维出口 IP 或堡垒机 | TCP 22 | SSH |
| CLB 所在网段 / 本安全组 | TCP 80 | Nginx 给 CLB |
| 本安全组 | TCP 3000 / 3001 | 仅排障，生产可不开放 |

出站：

| 目的 | 端口 | 用途 |
|---|---|---|
| `0.0.0.0/0` | TCP 443 | COS、微信 API、法律文本、包管理（可再收紧） |
| TencentDB 内网地址 | TCP 5432 | PostgreSQL TLS，仅 VPC |
| Redis 内网地址 | TCP 6379 | 仅 VPC |

不要把 3000、5432、6379、9000 对 `0.0.0.0/0` 开放。

## 6. 云数据库 Redis

1. 打开 [云数据库 Redis](https://console.cloud.tencent.com/redis)。
2. 新建实例：
   - 地域 / VPC / 子网：与第 5 节相同，子网选 `qingxu-<env>-data`
   - 版本：Redis 7.x
   - 架构：标准架构即可
   - **密码认证：开启**，密码至少 24 位，写入 Secret Store，不要写进工单
   - **加密传输：开启**（对应 `rediss://`）
   - 下载并保存 Redis CA（若控制台提供）
3. 白名单只加 `qingxu-<env>-app` 子网，不要 `0.0.0.0/0`。
4. 记录内网地址，例如 `10.20.2.12`。
5. 在运维机（能进 VPC 的跳板或 CVM）验证：

```bash
# 密码从 Secret Store 注入，不要出现在 shell history 的明文命令里
redis-cli --tls -h '<redis内网地址>' -p 6379 -a "$REDIS_PASSWORD" ping
```

应返回 `PONG`。失败时先查安全组、TLS 开关、密码，不要改成明文 `redis://` 凑合。

运行时连接串形态：

```text
rediss://:<url编码后的密码>@<redis内网地址>:6379/0
```

密码含 `@` `#` `:` 等字符时必须 URL 编码。

## 7. 对象存储 COS

### 7.1 业务桶（商品图、售后证据、推广码）

1. 打开 [对象存储](https://console.cloud.tencent.com/cos)。
2. 新建桶 `mall-<env>`（全局唯一，只能小写字母、数字、连字符）。
3. 访问权限：**私有读写**。不要选「公有读」。
4. 版本控制：staging / production **开启**，便于误删恢复。
5. 打开「安全管理 → 跨域访问 CORS」，增加：

| 字段 | 值 |
|---|---|
| 来源 | `https://admin.example.com`、`https://agent.example.com` |
| 操作 | GET, PUT, POST, HEAD |
| Allow-Headers | `*` |
| 超时 | `600` |

小程序若直传 COS，再把小程序合法 upload 域名加进来源；当前实现是浏览器走签名 URL，后台/代理域名必须在列表中。

6. 打开「权限管理 → 策略权限」，给第 5.1 节子用户授予与仓库 `scripts/storage/minio-runtime-policy.json` 等价的权限：`ListBucket`，以及 `public/*`、`private/*`、`staging/*` 的 Get/Put/Delete。不要授予整账号 `AdministratorAccess`。
7. 打开「权限管理 → 存储桶策略 / 匿名访问」，**只**允许匿名 `GetObject` 且 Resource 仅 `mall-<env>/public/*`。`private/*`、`staging/*` 保持私有，只能走 NestJS 重新鉴权后的短时签名下载。
8. 记下：
   - 地域：`ap-guangzhou`（示例，写入 `S3_REGION`）
   - 源站：`https://cos.ap-guangzhou.myqcloud.com`（写入 `S3_ENDPOINT`，**不要带 path**）
   - 公开基址：`https://cos.ap-guangzhou.myqcloud.com/mall-<env>`（写入 `S3_PUBLIC_BASE_URL`，path 必须正好是 `/mall-<env>`）
   - `S3_FORCE_PATH_STYLE=true`

虚拟主机形式 `https://mall-<env>.cos.ap-guangzhou.myqcloud.com` 的 path 是 `/`，**过不了当前配置校验**。

9. 用子用户密钥做一次探活（在 CVM 上，密钥来自环境变量）：

```bash
# 仅验证桶存在，不要把密钥打到终端
curl -I "https://cos.ap-guangzhou.myqcloud.com/${S3_BUCKET}"
```

应用启动后还会对桶做 `HeadBucket`；失败时 `/internal/health` 的 storage 为非 `ok`。

### 7.2 静态站桶（admin / agent）

1. 再新建两个私有桶，或一个桶两个前缀：`qingxu-static-<env>`。
2. 不要对整个静态桶开放匿名写。
3. 后面用 CDN 回源该桶，CDN 鉴权用防盗链 / Token，源站保持私有。

## 8. PostgreSQL（国内用 TencentDB）

运行库只使用腾讯云 TencentDB PostgreSQL。仓库里的 Prisma、角色、RLS 和 7 条迁移不变；冻结首迁移里的无登录 `anon` / `authenticated` / `service_role` 只作拒绝面，不表示还在使用海外托管库。

### 8.1 购买实例

1. 打开 [云数据库 PostgreSQL](https://console.cloud.tencent.com/postgres)。
2. 与 CVM / Redis / COS **同一地域、同一 VPC**，子网选 `qingxu-<env>-data`。
3. 引擎选 PostgreSQL，版本选控制台当前最高稳定版（16 或 17 即可）。本地 CI 回放用 18.3，不要求云上必须 18。
4. 规格：staging 先 2 核 4 GB；production 按压测后再升。
5. **关闭外网地址**。只使用内网。
6. 初始化账号：记下你设置的实例管理员用户名和密码，只放进 Secret Store，这是 `DATABASE_OWNER_URL` 的角色。
7. 库名保持 `postgres`，或另建 `mall`；`DATABASE_URL` / `DIRECT_URL` / `DATABASE_OWNER_URL` 的库名必须一致。
8. 参数：开启 SSL。下载 CA 证书到运维机绝对路径，例如 `/etc/qingxu/certs/tencent-postgres-ca.crt`，权限 `0644`。
9. 备份：开启自动备份和日志备份 / PITR（控制台名称以当前产品为准），保留至少 7 天。
10. 安全组只放行 `qingxu-<env>-app` 子网的 `5432`，不要对 `0.0.0.0/0` 开放。
11. 记录**内网域名**（`*.sql.tencentcdb.com` 或 `*.postgres.tencentcdb.com`）。`verify-full` 必须用域名，不要填内网 IP。

### 8.2 空库初始化

1. 生成互相独立的 `MALL_RUNTIME_PASSWORD`、`MALL_MIGRATOR_PASSWORD`（各不少于 24 位）。
2. 在 CVM 或堡垒机注入：

```bash
export DATABASE_PROVIDER=tencentdb
export DATABASE_OWNER_URL='postgresql://<实例管理员>:<管理员密码>@<内网域名>:5432/postgres?sslmode=verify-full&sslrootcert=/etc/qingxu/certs/tencent-postgres-ca.crt'
export DIRECT_URL='postgresql://mall_migrator:<迁移密码>@<内网域名>:5432/postgres?sslmode=verify-full&sslrootcert=/etc/qingxu/certs/tencent-postgres-ca.crt'
export DATABASE_URL='postgresql://mall_runtime:<运行密码>@<内网域名>:5432/postgres?sslmode=verify-full&sslrootcert=/etc/qingxu/certs/tencent-postgres-ca.crt'
export MALL_MIGRATOR_PASSWORD='<与 DIRECT_URL 相同>'
export MALL_RUNTIME_PASSWORD='<与 DATABASE_URL 相同>'
export PGSSLROOTCERT=/etc/qingxu/certs/tencent-postgres-ca.crt
export DATABASE_BOOTSTRAP_CONFIRM=BOOTSTRAP_EMPTY_DEV_DATABASE
```

3. 空库初始化只允许：

```bash
pnpm db:bootstrap
node scripts/db/verify.mjs
node scripts/db/check-drift.mjs
```

确认短语以仓库 `scripts/db/README.md` 为准。`public` 里已有业务表时立即停止，禁止 reset。环境中不得残留任何 `SUPABASE_*`。

4. 初始化成功后立刻从运行环境删除 `DATABASE_OWNER_URL` 和实例管理员密码。
5. 运行时只保留：
   - `DATABASE_PROVIDER=tencentdb`
   - `DATABASE_URL`：`mall_runtime` + `sslmode=verify-full` + `sslrootcert=<CA绝对路径>`
   - `DIRECT_URL`：只放在执行迁移的运维会话，不放进 API/Worker 的 systemd 环境文件
6. CVM 上验证（密码走环境变量）：

```bash
psql "$DATABASE_URL" -c 'select current_user, inet_server_addr();'
```

`current_user` 必须是 `mall_runtime`。再开一个一次性会话用 `DIRECT_URL` 查 `_prisma_migrations`，应看到 `0001` 至 `0007` 共 7 行。

## 9. 购买并初始化 CVM

### 9.1 控制台创建

1. 打开 [云服务器](https://console.cloud.tencent.com/cvm)。
2. 与 Redis/COS 同一地域、同一 VPC、子网 `qingxu-<env>-app`。
3. 镜像：Ubuntu Server 22.04 LTS 64 位。
4. 登录方式：**密钥对**，禁用密码登录。
5. 绑定第 5.3 节安全组。
6. 主机名：`qingxu-<env>-api-01`。
7. 建好后记录内网 IP。production 第二台 `api-02`、Worker `worker-01` 同样步骤。

### 9.2 首次登录与基础加固

用密钥从堡垒机登录：

```bash
ssh -i ~/.ssh/qingxu_ops ubuntu@<CVM内网或经堡垒转发的地址>
sudo timedatectl set-timezone Asia/Shanghai
sudo apt-get update
sudo apt-get install -y nginx ca-certificates curl git unzip
sudo systemctl enable --now nginx
```

建议：

```bash
sudo apt-get install -y unattended-upgrades
sudo dpkg-reconfigure --priority=low unattended-upgrades
```

只保留密钥登录：确认 `/etc/ssh/sshd_config` 中 `PasswordAuthentication no`，然后 `sudo systemctl reload ssh`。

### 9.3 安装 Node.js 22.23.1 与 pnpm 10.34.5

```bash
sudo mkdir -p /opt/qingxu
sudo chown ubuntu:ubuntu /opt/qingxu
```

## 10. SSL 证书与 CLB

### 10.1 申请证书

1. 打开 [SSL 证书](https://console.cloud.tencent.com/ssl)。
2. 申请免费 DV 证书，域名填 `api.example.com`（admin / agent 同样各申请，或一张 `*.example.com`）。
3. 按控制台要求做 DNS 验证。
4. 签发后下载 Nginx 格式，或直接在 CLB 里选择该证书。

### 10.2 配置 CLB

1. 打开 [负载均衡](https://console.cloud.tencent.com/clb)。
2. 新建应用型 CLB，地域 / VPC 与 CVM 相同。
3. 监听器：
   - 前端：HTTPS `443`，选择刚签发的证书
   - HTTP `80`：只做 301 跳到 HTTPS
   - 后端：CVM 内网 IP，端口 `80`，协议 HTTP
4. 健康检查：
   - 检查路径：`/internal/health`
   - 协议：HTTP
   - 期望：HTTP 200
   - 间隔 5 秒，不健康阈值 3
5. 安全组允许 CLB 访问 CVM:80。
6. 在域名 DNS（建议腾讯云 DNSPod）添加：

```text
api    A / CNAME    <CLB 的 VIP 或 CNAME>
```

解析生效前不要在微信后台提交该域名。

## 11. Nginx（CVM 本机）

API 与静态站分离：本机 Nginx 只反代 API，并给 CLB 做健康检查。admin / agent 走 CDN，不放在这台 Nginx，除非演练阶段临时托管。

创建 `/etc/nginx/sites-available/qingxu-api`：

```nginx
upstream qingxu_api {
    server 127.0.0.1:3000;
    keepalive 16;
}

server {
    listen 80;
    server_name api.example.com;

    # CLB 健康检查与浏览器都打这里
    location = /internal/health {
        proxy_pass http://qingxu_api;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto https;
        proxy_set_header Connection "";
    }

    location /api/v1/ {
        proxy_pass http://qingxu_api;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto https;
        proxy_set_header Connection "";
        client_max_body_size 6m;
        proxy_read_timeout 60s;
    }

    location / {
        return 404;
    }
}
```

微信支付回调若走同一主机，必须保证 **Nginx 不缓冲、不改写原始 body**（验签读 raw body）。需要时为回调 path 增加：

```nginx
proxy_request_buffering off;
proxy_buffering off;
```

启用站点：

```bash
sudo ln -s /etc/nginx/sites-available/qingxu-api /etc/nginx/sites-enabled/qingxu-api
sudo nginx -t
sudo systemctl reload nginx
```

此时 `API_TRUSTED_PROXY_CIDRS=127.0.0.1/32`。不要填 `0.0.0.0/0`。

## 14. 总部后台与代理工作台（COS + CDN）

admin / agent 构建产物默认请求同源 `/api/v1`（见 `apps/admin-web/src/services/admin-api.ts`、`apps/agent-web/src/services/agent-api.ts`）。生产静态站域名与 API 域名不同，因此必须在 CDN / Nginx 把 `/api/v1` **反代到 API**，或给静态站加一层同域网关。

**推荐：每个静态域名在 CDN 配两条回源。**

| 路径 | 回源 |
|---|---|
| `/api/v1/*`、`/internal/health` | `https://api.example.com` |
| 其余 | COS 静态桶 |

控制台操作：

1. 本地构建（在已安装依赖的发布目录）：

```bash
cd /opt/qingxu/app
pnpm --filter @qingxu/admin-web build
pnpm --filter @qingxu/agent-web build
```

产物一般在 `apps/admin-web/dist`、`apps/agent-web/dist`。

2. 用 COSCLI 或控制台上传（密钥用静态发布子用户，不要用 runtime 对象读写账号）：

```bash
# 示例：安装 coscli 后
coscli sync apps/admin-web/dist/ cos://qingxu-static-<env>/admin/ \
  --region ap-guangzhou
coscli sync apps/agent-web/dist/ cos://qingxu-static-<env>/agent/ \
  --region ap-guangzhou
```

3. 打开 [CDN](https://console.cloud.tencent.com/cdn)，分别添加 `admin.example.com`、`agent.example.com`：
   - 源站：COS 对应前缀
   - 证书：第 10 节证书
   - 缓存：`index.html` 不缓存或缓存 0；带 hash 的 js/css 长缓存
   - 回源改写：`/` 回源 `/admin/index.html`（admin）
4. 在同一 CDN 或前面再加一层「混合源」把 `/api/v1` 指到 CLB。若 CDN 不便做分流，可在 admin/agent 各用一台极小 CVM / 轻量 Nginx 做同域反代（静态文件仍回 COS）。

5. 浏览器验证（用无痕窗口）：
   - 打开 `https://admin.example.com`，应看到登录页，无混合内容告警
   - 登录接口应是 `https://admin.example.com/api/v1/admin/auth/...` 且证书有效
   - 代理端同样验证 `https://agent.example.com/api/v1/agent/auth/login`

## 18. 日常发布（不停库热更新）

1. 在 `/opt/qingxu/releases` clone 新 SHA，`pnpm install --frozen-lockfile` 并构建。  
2. `sudo systemctl stop qingxu-worker`（先停消费，避免新旧代码抢 Outbox）。  
3. `ln -sfn /opt/qingxu/releases/sha-<新SHA> /opt/qingxu/app`  
4. `sudo systemctl restart qingxu-api`  
5. 连续 3 次 `curl` health 为 200 后 `sudo systemctl start qingxu-worker`  
6. 静态站 `coscli sync` 新 `dist`，必要时刷新 CDN 目录  
7. 小程序如有前端变更，另走微信上传，不要和 API 混成一次「随手发」  

数据库迁移**单独窗口**：先停写入，用只含 `DIRECT_URL` 的运维会话按仓库受控 migration 流程执行，成功并核对 `_prisma_migrations` 后再启 Worker。禁止 API 进程带 migrator 密码。

## 19. 回滚

- **应用回滚**：把 `/opt/qingxu/app` 指回上一 SHA，restart API 再 start Worker。不回滚已部署的加法迁移。  
- **静态站回滚**：COS 版本回退或重新 sync 旧 `dist`，刷新 CDN。  
- **小程序回滚**：微信公众平台回退上一体验版 / 正式版。  
- **数据回滚**：按 B16.2 恢复到记录的 PITR 时间点，在**新库**上验证后再切 `DATABASE_URL`，不要在原库 `reset`。  
- 失败时保持只读，不删订单、支付、佣金、钱包、审计、Outbox。

1. 控制台确认自动备份和日志备份 / PITR 已开，保留期写入 runbook。  
2. 在 staging 按 [B16.2](../05-开发管理/B16.2-备份恢复回滚演练.md) 做一次完整恢复演练：恢复到**新实例**，核对 `_prisma_migrations` 和抽查表后再切 `DATABASE_URL`。  
3. 不要在原库执行 `prisma migrate reset` 或删除业务表。  
4. 外部复核通过前，不切生产、不迁真实 PII。
