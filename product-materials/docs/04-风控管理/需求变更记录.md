## 三、CH-001 变更详情

### 3.1 变更申请

- **申请日期**：2026-08-10
- **申请来源**：业务负责人明确调整
- **变更类型**：新增需求与原有需求修改
- **紧急程度**：高，必须在开发前完成范围纠偏

变更前产品只有消费者小程序和总部管理后台，后台采用两类内部权限，渠道推广与结算能力尚未纳入当前范围。

变更后产品为三个终端和三类人员：

1. 总部管理后台，角色 `SUPER_ADMIN`。
2. 一级代理工作台，角色 `AGENT_ADMIN`，属于外部推广合作方。
3. 消费者微信小程序，角色 `CUSTOMER`。

游客仍为未登录状态，不新增人员角色。原总部最高权限映射为 `SUPER_ADMIN`，原总部内部普通操作角色从当前范围移除。

### 3.2 业务边界

- 代理严格单层，由超级管理员创建，不存在下级代理。
- 总部统一商品、零售价、库存、收款、发货、退款和售后。
- 代理仅推广和只读查看本人脱敏客户、订单、售后进度、佣金与提现。
- 代理不能改价、改库存、代客下单、发货、退款或处理售后。
- 未绑定游客保存最后一个有效邀请码，TTL 30 分钟；登录后确认成功才建立长期绑定，拒绝则清空候选并保持直营。
- 超级管理员可转移到其他 ACTIVE 代理或 DIRECT，但只影响转移后提交的新订单，历史订单与佣金快照不变。
- 提交订单只记录归因候选，支付成功时复核代理 ACTIVE 后最终冻结；支付前停用转 DIRECT，支付后停用不影响已冻结 EXPECTED。
- 佣金按订单项净商品实付金额和支付时有效比例计算；具体比例来源由后续已批准的 CH-002 统一商品规则定义。
- 确认收货或总部兜底完成后，佣金立即转为可提现，不设置额外等待期。
- 完成前全退将 EXPECTED 标记为 CANCELLED；完成后保留 AVAILABLE 并追加 REFUND_DEBIT；余额可为负并阻止提现。
- 提现由代理申请、总部审核、线下银行转账、上传凭证并标记已支付；完整收款账号默认掩码，仅付款环节二次验证后短时查看/复制并全量审计。
- 代理默认授权全部当前及未来在售商品，超级管理员可切换自定义白名单。
- ADM-16 配置默认 100 元最低提现与默认 7 天售后申请期；ADM-02 纳入日/月销售、商品销量和客户消费排行。

## 四、CH-002 变更详情

### 4.1 变更申请

- **申请日期**：2026-08-11
- **申请来源**：用户明确提出并批准的业务规则调整
- **变更类型**：修改现有佣金配置与计算需求
- **影响程度**：重大
- **执行时机**：设计阶段立即实施，开发前完成基线替换

变更前，佣金比例配置在代理档案上，同一个代理推广的全部商品使用同一比例。这不能表达不同品类、商品规格的毛利和推广策略差异。

变更后，所有一级代理共用一套由商品维度决定的百分比佣金规则：

1. 平台默认比例提供兜底。
2. 商品所属一级分类可配置分类默认比例。
3. SKU 可配置覆盖比例。
4. 解析优先级固定为 `SKU 覆盖 > 商品一级分类默认 > 平台默认`。
5. 空值表示继承，`0%` 表示明确无佣金并终止继承。
6. 现有商品一级分类直接作为佣金分类来源，不另建运营分类体系。
7. 不再在代理档案维护佣金比例，所有一级代理在同一规则版本下推广相同 SKU 时采用相同比例。

### 4.2 业务边界

- 佣金基数继续使用订单项净商品实付金额，首期不含运费。
- 单个订单项佣金 = `订单项净商品实付金额 × 支付时有效比例 / 100`；订单佣金为各订单项逐项舍入后的金额之和。
- 支付成功时逐订单项冻结规则版本、命中来源、一级分类、商品、SKU、比例、基数和佣金金额。
- 待付款订单按支付成功时有效规则结算；规则修改、商品移动分类或 SKU 覆盖清空不追溯已支付订单。
- 常规退款按原订单项支付快照比例和实际成功退款金额冲减。
- 同一订单项累计冲减不得超过原佣金；最后一笔使订单项全额退清时，直接冲减剩余佣金以消除舍入尾差。
- 保留 `EXPECTED`、`CANCELLED`、`AVAILABLE`、`REFUND_DEBIT` 生命周期，以及不可变流水、负余额、提现限制和线下付款规则。
- 当前版本排除代理专属比例、“代理 × SKU”、固定金额、销量/金额阶梯和限时活动佣金。

| 产品规则 | 重大 | 佣金从代理维度改为平台/分类/SKU 商品维度，并增加继承和 0% 语义 |
| 信息架构 | 重大 | 总部新增 ADM-22 佣金规则管理，代理页面移除独立比例并增加 SKU 预计佣金/订单项快照 |
| 数据概念 | 重大 | 新增规则版本、规则目标、命中来源和订单项佣金快照；代理档案不再承担比例真相 |
| API 边界 | 重大 | 新增规则查询/写入/版本解释；支付与退款必须逐订单项使用快照，拒绝客户端比例 |

用户将本次整改视为重大修改并批准立即执行，要求先修订需求文档和原型规范，再同步接口与数据库，仍不得进入生产代码开发。

### 7.2 已冻结业务决策

1. 首期严格单商户、单仓、单包裹。任一未发货订单项存在活动售后占用，整单不得创建或确认发货；全部占用释放或成功退款后，仅按最终剩余数量创建唯一包裹。
2. 商品售后客户端只提交订单项、数量、类型、原因、说明和凭证，不提交金额。服务端按订单项成交/优惠分摊快照、成功退款和活动占用计算金额；尾笔使用剩余可退金额清尾差。纯金额补偿使用总部专属 `AMOUNT_COMPENSATION`，不占数量、不回库但占金额并冲正佣金。
3. 佣金公式固定为 `基数 × 比例 / 100`，按订单项 `HALF_UP` 保留两位后汇总；比例使用 `DECIMAL(7,4)`，范围 `0.0000%-100.0000%`（含边界），超范围拒绝。
4. 支付意图先落库稳定 `intent_no + CREATING` 再调用 Provider；`CREATING/OPEN/CLOSE_PENDING` 视为活动状态且每单最多一个。创建/关闭结果未知按 intent_no 查询恢复，不得盲目新建或提前释放库存；对账任务负责补记、关闭、补偿和人工财务异常升级。
5. 用户主动取消、超时任务和支付确认使用同一订单锁/版本号串行。支付先提交则关单失败；关单先提交则后到成功为迟到支付并自动退款。活动意图未确认不可支付前不得释放库存。
6. 退款拆为 `refund_progress_status=NONE/PARTIAL/FULL` 与 `refund_processing_status=IDLE/REFUNDING/FAILED`。前者仅按成功退款派生，后者表达处理/异常；允许 `PARTIAL + FAILED` 并优先提示失败。
7. ADM-16 维护唯一当前总部退货地址，审核通过时保存不可变地址快照。总部验货请求一次精确覆盖全部售后项，逐项记录退货物流、实收、批准退款数量、验货结果 `PASS/ABNORMAL`、证据，以及回库、损坏、报废、退回客户四类处置；逐项满足“批准退款 + 退回客户 = 实收”“批准退款 = 回库 + 损坏 + 报废”。`PASS` 仅允许全量实收/全量批准且不退回客户，可零证据；少件、0 件或不符必须 `ABNORMAL` 且至少一份证据，两类证据清单均在提交时封存。异常只允许一次把类型化 `resolution` 写为 `CONTINUE_REFUND` 或 `REJECT_AFTER_RETURN`，继续退款原因必填且只能使用冻结批准数量，解决事实不可改写。已发货全额退款以 `COMPLETED + completion_reason=FULL_REFUND_AFTER_SHIPMENT` 结束，原包裹、物流和签收事实不回退。
8. 并发裁决固定为：两个绑定确认首个提交胜出；客户转移与订单提交按绑定版本先提交者决定候选；代理停用与支付按代理版本先提交者决定 `AGENT/DIRECT`；订单完成与退款按订单项佣金快照串行并保证两种顺序净结果一致。
9. 邀请码、代理或候选失效时只把归因降级为 `DIRECT`，不得阻断消费者浏览、下单或支付。撤权旧推广链接不再建候选，但可作为普通商品链接打开。
10. 账号删除除未完成订单/售后外，还阻断未结清支付、退款和财务异常；完成后撤销会话、结束绑定/候选，清空微信主体与资料，硬删除手机号验证、地址、收藏和购物车项的密文/HMAC/尾号/密钥标识，代理投影仅留不可逆代号；交易与审计事实按外部合规策略保留且不再通过当前资料接口关联原主体。
11. 品牌、分类、商品和 SKU 软删除。存在在售商品的品牌/分类禁止停用；商品/SKU 存在活动预占时禁止软删除。普通下架阻止新加购/结算，但下架前合法预占订单可在 `pay_expires_at` 前支付；库存始终满足 `实物 >= 锁定 >= 0`。
12. 代理端昵称只使用服务端脱敏值；当前城市取最近一笔本人归属已支付订单，无订单显示“暂无”。历史订单使用支付时订单城市快照，账号删除后显示不可逆客户代号且无手机号尾号。
13. 首个超级管理员只由受控部署命令创建。管理员使用 30 秒 TOTP，允许前后各一个时间步并防重放；连续失败 5 次锁定 15 分钟，恢复码一次一用且只保存哈希。密码/TOTP 重置撤销全部会话；全凭据丢失只允许双人审批离线恢复。
14. PRD 13.4 的 `HR-01` 至 `HR-15` 为唯一高风险操作矩阵，分别定义原因、影响预览/二次确认、TOTP/凭证、版本、幂等和审计；不再把同一组要求一刀切到所有动作。
15. 当前 MVP 删除消费者订单留言/买家备注；总部内部审计备注不受影响。
16. 每 SKU 单笔订单上限固定为 `min(99, 服务端可售库存)`。看板明确区分今日创建订单/今日有效支付订单、客户总数/新增注册/新增绑定和周期活跃代理，全部按 Asia/Shanghai 与事实流水复算。
17. 页面数量保持 `21 MP + 9 AGT + 22 ADM`。退货地址与 TOTP 放入 ADM-16，退货验货/金额补偿放入 ADM-13；不新增页面。代表性 Loading、Empty、网络错误、403、409、重复提交和 Success 必须连接真实操作。
18. v4 仅澄清既有范围的角色投影，不新增页面或功能：Store、Agent、Admin 的列表/详情使用角色专用 DTO，不以宽字段通用响应交由前端隐藏。Store 目录只含 `ACTIVE` 商品/SKU 和消费者字段；Store 订单列表含商品/SKU、售后摘要与服务端可用动作；Agent 客户仅当前有效绑定和当前归属期口径，订单仅支付成功时冻结本人快照并含商品/城市/售后/完整只读状态轴。
19. ADM-03 商品列表增加既有库存能力的 SPU 聚合展示，含 SKU 数和实物/锁定/可售摘要并下钻 SKU 流水；ADM-18/19 代理列表/详情展示当前客户、归属净销售、余额和创建时间，并可按目标代理下钻客户、支付归属订单、佣金流水、钱包流水、提现与目标审计，不增加新的经营权限。
20. `pay_expires_at` 由数据库固定为订单 `created_at + 30 分钟` 并在创建后不可修改；ADM-16 只读展示，任何角色或配置均不能延长/缩短既有订单期限。
21. 临时密码、TOTP 绑定 URI/恢复码、邀请码明文、银行卡查看授权、预览/确认能力令牌和签名文件 URL 均为一次展示的短时响应，统一 `Cache-Control: no-store`；刷新、离页、消费或到期后不得从缓存或普通详情接口恢复。
22. 消费者在本人已通过退货审核的售后详情读取总部退货地址快照，属于售后履约所需的授权地址例外，与消费者本人收货地址/订单和总部用途绑定履约地址并列；授权响应禁止缓存，代理端、列表、日志、错误、审计摘要和自动化截图仍不得出现详细地址。
