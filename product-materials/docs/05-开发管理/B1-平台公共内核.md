## 2. 已实现能力

### 2.1 公共契约与 HTTP

- OpenAPI 继续作为唯一业务接口真相源，生成产物必须确定且无 Git 漂移；金额和佣金比例格式不在 B1 改写。
- `/api/v1` 业务响应使用统一成功/错误包络；未知异常和所有 5xx 响应不返回堆栈、内部消息或原始详情，`204` 与内部健康检查不被业务包络改写。
- 客户端 `X-Request-Id` 只接受 `trace_` 加 32 位小写十六进制；其他值一律替换为不可预测的服务端 `req_` ID。同一请求上下文贯穿响应与白名单访问日志。
- 日志和审计采用字段白名单，拒绝记录请求体、Authorization、数据库连接串、JWT、OTP、手机号、银行卡及其他未知字段。
- RBAC 默认拒绝：只有显式公共路由可匿名访问；受保护路由按角色和权限元数据校验。B1 不签发或解析业务 access token。
- `If-Match` 只接受强引用、双引号包裹的正整数版本；缺失、弱 ETag、非法或陈旧版本均失败关闭。

### 2.2 配置、数据库与加密

- API/Worker 启动时严格验证 Node 环境、服务端口、连接池、Worker 重试参数、独立 32 字节加密/HMAC 密钥及密钥版本；幂等配置包含 1 把 current 和最多 3 把 previous，ID/密钥不得重复或跨用途复用。
- 日常数据库连接只接受审批项目的 `mall_runtime` direct/session 5432 连接并强制可信 CA 校验；本地 PostgreSQL 仅允许在显式 CI 临时测试环境使用。
- API/Worker 使用 Prisma 7.9.1、`@prisma/adapter-pg` 和受限连接池；启动连接失败时只输出固定错误，不泄露配置名、连接串或堆栈。
- AES-256-GCM 信封包含密钥 ID、随机 nonce 和认证标签，并强制使用 `table:row-id:field` 形式的非空认证上下文，防止密文跨记录/字段替换；IP 只保存独立密钥计算的 HMAC，不保存可逆明文。
- 可序列化事务仅对 PostgreSQL serialization/deadlock 错误做有界重试，其他错误不被误重试。

### 2.3 幂等、审计与可靠消息

- 幂等键使用 UUID；持久 scope 由 HTTP method 与规范 route template 的非密钥 SHA-256 稳定派生，actor 与 key 继续参与唯一键和 advisory lock。完整 method/route/path/body 规范请求使用独立密钥 HMAC-SHA-256，避免凭据类请求被离线猜测。
- 幂等 HMAC 配置包含带 ID 的 current/previous 密钥环。新写入只使用 current，读取会尝试全部活动密钥；轮换必须先部署“新 current + 旧 previous”，旧钥至少保留 24 小时。错误移除旧钥只会返回冲突，不会把旧记录当作新请求再次执行。
- `CACHEABLE` 仅允许闭合 `CommandResponse`，重放前再次验证响应 HMAC、HTTP 状态和 `resource_id` 一致性；敏感/一次性响应使用 `HASH_ONLY`，不保存响应体。仓储使用内部时钟固定 24 小时，调用方不能传 scope、摘要或过期时间。
- 成功审计与业务事实同事务写入；元数据、reason code 和 before/after 摘要使用仓储拥有的闭合 typed policy（当前仅 `NONE`、`STATUS_VERSION`），IP 在仓储内 HMAC。数据库继续保持审计记录不可更新、不可删除。
- Callback 必须在 Inbox 写入前完成验签；`WECHAT` 只持久化 timestamp/nonce/serial/signature，`MOCK` 只持久化 mock timestamp/signature，Authorization、Cookie 和未知头失败关闭。Inbox 以 provider/event ID 去重，Worker 只领取已注册 provider/event type，失败按有界规则重试并记录注册的安全错误码。
- Outbox 事件与业务事实可在同一事务写入；多个 Worker 通过 PostgreSQL advisory lock 竞争，成功只标记一次，失败按指数退避进入重试或终态。
- Worker 当前不注册任何业务事件处理器，因此不会提前消费 B13 或其他后续批次事件；B13 业务事件须在所属批次通过治理和契约门禁后再注册。

## 3. 数据模型与迁移

B1 不新增表、字段、索引、约束、RLS、触发器或迁移，只复用冻结首迁移中的四个模型：

| 模型 | B1 用途 | 迁移变化 |
|---|---|---|
| `IdempotencyRecord` | 完成结果、带密钥请求/响应摘要与结果重放；并发占用使用事务 advisory lock，不写不完整占位行 | 无 |
| `AuditLog` | 不可变、白名单化操作审计 | 无 |
| `CallbackInbox` | Provider 回调去重与处理状态 | 无 |
| `OutboxEvent` | 事务事件、重试和发布状态 | 无 |

根 `prisma/schema.prisma`、冻结 schema 与 `0001_initial` 必须保持逐字节一致；Prisma Client 的构建派生文件不得反写冻结模型或迁移。

## 5. 验收命令与门禁

验收已在 Node.js 22 与冻结 pnpm 版本下执行；CI/受保护环境继续使用同一入口。

```bash
pnpm install --offline --frozen-lockfile
pnpm config:check
pnpm lint
pnpm typecheck
pnpm contracts:lint
pnpm contracts:generate
pnpm prisma:validate
pnpm db:check-frozen
pnpm db:migrate:baseline
pnpm db:test-permissions
pnpm db:test-b1
pnpm db:diff
pnpm test
pnpm build
pnpm build:miniapp
pnpm scan:sensitive
pnpm e2e
```

验收必须同时确认：

1. OpenAPI 生成产物、Prisma schema 和冻结迁移均无漂移。
2. 单元与 Supertest 覆盖错误包络、request-id、日志脱敏、RBAC 默认拒绝、`If-Match`、配置、加密、事务重试及 Worker 注册边界。
3. 临时 PostgreSQL 覆盖同键并发单次副作用、同键异参冲突、跨密钥轮换回放/错误移钥冲突、过期重用、事务整体回滚、Inbox 去重、双 Worker 竞争、重试终态和 advisory lock 异常释放。
4. Supabase development 使用 `mall_runtime` 执行同一公共内核烟测；测试必须位于显式事务中并最终 `ROLLBACK`，执行后复核无测试数据残留、无 DDL、无权限变化。
5. 凭据、PII、银行卡、固定测试凭据和日志扫描无新增泄露；失败输出不得包含连接串、密钥、请求体或堆栈。

本地门禁结果：配置 19、platform-core 79、database 105、API 61、Worker 11 条测试通过；PostgreSQL 18 full 集成 13 条通过，Supabase rollback-only 1 条通过；五应用、H5 和 MP-Weixin 构建通过；375/390/414/1024/1440 五视口 E2E 通过。OpenAPI、Prisma、冻结迁移、权限故障注入、敏感扫描与生成漂移均通过。

## 6. Supabase rollback-only 规则

- 只使用新加坡 development 项目和 `mall_runtime`，不得使用 project-owner、`service_role` 或生产数据。
- 运行前验证 project ref、5432 direct/session 端点、角色和可信 CA；禁止为通过测试关闭证书校验。
- 测试数据使用显式合成 ULID/UUID 与非真实内容，并在一个顶层事务内执行。
- 脚本无论成功或失败都必须请求 `ROLLBACK`；连接中断时再以只读查询核对测试标识不存在。
- smoke 不创建、删除或修复数据库对象，不修改 migration history，也不替代临时 PostgreSQL 的完整并发验收。
