## 3. 契约决策

- 五个读接口均只允许已认证 `SUPER_ADMIN`，使用现有 Admin Bearer realm、统一错误包络和私有缓存头；Agent/Store token 必须拒绝。
- 所有金额延用契约 decimal string，净值可为负；前端不用浮点数重算。五个响应都返回 `timezone=Asia/Shanghai` 与 `as_of`，四类报表另返回 `data_freshness=REALTIME`。
- 日/月报保留可加指标与不可相加快照的区分：仅 `GLOBAL` 返回实际 `new_registration_count`、`active_agent_count` 和 `customer_total_snapshot`，其他范围固定为 0；活跃代理按区间事实去重，客户总量取区间结束时最近快照，二者均不累加日报。
- `scope=AGENT` 且省略 `agent_id` 时汇总全部代理渠道，传入时限定指定代理且未知代理返回 404；`GLOBAL`/`DIRECT` 不接受 `agent_id`。归属按支付时冻结快照，不按客户当前绑定回写历史。
- 日期或月份起止边界必须成对传入或同时省略；默认值、最大跨度、倒置区间与未来区间拒绝必须在 B14.0 的 OpenAPI 中闭合，B14.1 不得自行推导。
- 排行固定按净值降序、资源 ID 升序收口，分页时排名在全量结果上确定。客户排行只返回 alias 和契约允许的脱敏昵称，不返回手机号或地址。

## 4. 查询与一致性决策

- 首期在单次只读 `REPEATABLE READ` 视图内直接聚合已冻结事实，所有分区共享一个 `as_of`；请求不写表、不发 Outbox、不依赖 Worker。
- 创建订单按 `sales_order.created_at` 统计全部状态；支付按首次成功事实所在日期统计；退款按成功退款事实所在日期统计。有效支付订单必须当前剩余实付大于 0。
- 商品排行按支付时 Product/SKU 快照聚合成功支付数量减成功退款数量；客户排行按成功支付金额减成功退款金额。集中退款周期允许净销售、净件数或净消费为负。
- 注册历史不因后续注销回写；`GLOBAL` 客户总数按 `as_of` 时当前未注销消费者统计，新增注册与新增绑定分开统计；`GLOBAL` 活跃代理是当前 `ACTIVE` 且区间内至少有一笔成功归属支付的代理去重数。`DIRECT/AGENT` 不复制这三项全局指标。
- 既有 `sales_daily_aggregate` 只是可重建缓存，B14 不增加其刷新者，不以其存在或完整作为返回前置。若事实查询出现具体慢查询证据，再单独走变更评估索引或汇总机制。

## 5. Admin Web 决策

- ADM-02 使用单一总部看板页和五个清晰标签视图；登录后默认进入概览，不建营销落地页。
- 概览使用紧凑指标带、待办和商品排行表；报表使用日期/范围筛选、数据表和分页。不用装饰卡片、嵌套卡片或图表依赖。
- 筛选状态通过路由 query 保留，只保存非敏感条件；返回页面时可恢复，无效 query 回到契约默认。
- 每个视图必须有稳定的 loading、empty、error/retry 和分页状态；401 走既有会话处理，403/404/422/429/500 使用服务端错误包络，不显示伪造的零值或旧数据。
- 下钻只导航到已实现的商品、客户、代理、订单和提现资源；不在前端重算指标或修正服务端排名。
