# B16.2 备份、恢复与回滚演练 Runbook

> 状态：runbook 已完成；实际 clone/PITR 恢复证据由 B17.2 执行并绑定唯一候选 SHA。未取得完整记录前不得标记 staging-ready。

> 适用环境：脱敏 development 或一次性 PostgreSQL；禁止 production、真实客户、真实支付和真实银行卡数据。

## 目标

验证在迁移或依赖故障时可以停止切流、恢复数据库与对象存储，并保留审计、Outbox、钱包和提现事实。该 runbook 不执行自动删除或在线回滚迁移。

## 演练前检查

1. 记录候选提交 SHA、迁移历史、服务版本、数据库连接项目和 `as_of` 时间。
2. 确认 `DATABASE_URL` 仅为 `mall_runtime`，`DIRECT_URL` 仅为 `mall_migrator`；禁止把 URL、密码或密钥写入命令参数和日志。
3. 在 Supabase 控制台确认 PITR/备份保留策略；导出恢复时间点和快照标识。
4. 记录 MinIO bucket、对象版本/数量和 Redis AOF 快照时间；演练使用独立 bucket 与 Redis DB。
5. 暂停写入和 Worker，确认没有进行中的迁移或资金命令。

## 恢复步骤

1. 使用一次性数据库项目恢复到记录的 PITR 时间点，不覆盖原项目。
2. 以 `mall_migrator` 运行只读迁移历史、权限、RLS、`migration diff=0` 和冻结指纹检查；不得手工插入 `_prisma_migrations`。
3. 以 `mall_runtime` 运行应用级只读 smoke，确认订单、支付、退款、佣金、钱包、提现、审计和 Outbox 事实可读。
4. 在独立 MinIO bucket 恢复 staging/public/private 对象，核对对象键前缀、数量和敏感对象的非公开访问。
5. 恢复 Redis AOF/快照后，仅验证幂等/限流临时状态；不得把 Redis 当作数据库事实来源。
6. 启动 API/Worker，等待 `/internal/health` 返回 `status=ok` 且三项检查均为 `ok`，再恢复 Worker 和受控写入。

## 回滚判定

- 任一迁移历史、权限、RLS、对象数量、审计/Outbox 或资金事实不一致：立即停止切流，保持原环境只读并重新恢复。
- 应用回退仅通过关闭新路由/导航和使用兼容字段完成；不删除账户、钱包、提现、佣金、审计、Outbox 或迁移事实。
- 迁移失败必须保留错误和目标 SHA，按批准的 Prisma recovery procedure 处理；禁止 `reset`、手工编辑迁移历史或盲目重跑。

## 退出记录

记录恢复时间、目标 SHA、快照/PITR 标识、迁移历史摘要、readiness 响应、smoke 结果、对象/Redis 清理结果、未验证项和复核人。没有完整记录不得标记演练通过。
