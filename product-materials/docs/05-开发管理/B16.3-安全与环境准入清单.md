# B16.3 安全与环境准入清单

> 目标：staging-ready；仅使用脱敏配置和虚构数据。任何未勾选项目都阻断 staging 切流。

## 环境与密钥

- [ ] `pnpm config:check` 在目标环境通过，所有必需变量由 Secret Manager 注入，不写入仓库、镜像层、命令参数或日志。
- [ ] staging 使用独立的 Supabase project、`SUPABASE_PROJECT_REF`、数据库角色密码、Redis、S3 bucket、JWT audience/issuer 和全部 key ring。
- [ ] `DATABASE_URL` 仅为 `mall_runtime`；`DIRECT_URL` 仅为 `mall_migrator`。运行时容器不持有 owner 或 migrator 凭据。
- [ ] S3 运行账号与 MinIO/S3 root 账号不同，仅授予目标 bucket 的 `ListBucket` 与 staging/public/private 对象读写删除权限。
- [ ] `AUTH_*`、`AGENT_*`、`STORE_*` audience 互不相同；staging 还必须使用不同于 development/test 默认值的 issuer/audience；production 禁止 `MOCK` Provider，staging 仅在 `STAGING_DEIDENTIFIED_MOCK_ACK=true` 的脱敏演练中固定使用 `MOCK`。
- [ ] 密钥轮换保留仍可能验证未过期数据所需的 previous key，轮换后执行登录、签名、地址、银行卡 HMAC、幂等和文件下载 smoke。
- [ ] 首次启动后移除 bootstrap-only 的 `SUPABASE_OWNER_URL`、管理 token 和初始化密码变量。

## 数据库与对象安全

- [ ] Supabase Data API 已关闭；前端只能访问 NestJS API。
- [ ] `mall_runtime` 表权限、函数权限、RLS/default grants 与冻结基线一致；迁移只由受控 `mall_migrator` 执行。
- [ ] 数据库 TLS 使用 `verify-full` 和批准 CA；远程 Redis 使用 `rediss://`；远程 S3、法律文档和推广 URL 使用 HTTPS。
- [ ] 日志、审计、Outbox、缓存和浏览器存储扫描无密码、token、银行卡明文、Provider payload 或客户 PII。
- [ ] MinIO bucket 默认非公开；PRIVATE 文件只能通过重新鉴权的签名下载访问。

## 故障处置

- [ ] `/internal/health` 返回 `200` 且 database/redis/storage 均为 `ok`；任一依赖异常必须返回 `503`。
- [ ] 配置校验失败时 API/Worker 不监听业务端口，并输出脱敏 `service_startup_failed` 事件。
- [ ] 登录 401/403/429、数据库/Redis/MinIO 不可用、密钥失效和 Worker 重启均有对应 runbook；异常时停止切流，不绕过限流或权限。
- [ ] 恢复后执行 B16.2 runbook，确认迁移历史、权限/RLS、资金事实、审计/Outbox、对象和 readiness，再恢复写入。

## 证据与责任

记录目标环境、候选 SHA、配置检查时间、密钥版本、权限查询摘要、readiness 响应、敏感扫描结果、故障演练结果和未验证项。staging 首次切流前必须由外部独立人员复核数据库、权限、安全和恢复证据。
