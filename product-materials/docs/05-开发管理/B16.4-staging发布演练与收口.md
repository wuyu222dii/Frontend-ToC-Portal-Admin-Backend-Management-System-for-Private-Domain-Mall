# B16.4 staging 发布演练与收口

> 当前结论：发布演练清单完成；实际 staging 执行、外部独立复核和最终 `staging-ready` 尚未取得证据。

## 发布前冻结

- [ ] 冻结唯一候选 SHA，并确认工作树干净、构建产物来自该 SHA。
- [ ] 由 Secret Manager 注入 staging 专用数据库、Redis、S3、JWT、加密和 Provider 配置；不复用 development 密钥或数据。
- [ ] 完成 [B16.2 备份恢复回滚演练](B16.2-备份恢复回滚演练.md) 和 [B16.3 安全准入清单](B16.3-安全与环境准入清单.md)。
- [ ] 迁移前记录 PITR/快照、迁移历史、对象数量、候选 SHA 和停止切流联系人。

## Dry-run 顺序

1. 以 `mall_migrator` 执行受控 migration dry-run、冻结检查和 `migration diff=0`；禁止 runtime 角色执行 DDL。
2. 启动 API 与 Worker，等待 `/internal/health` 返回 `200`，且 database/redis/storage 均为 `ok`。
3. 执行一次最小核心 smoke：Admin 登录、Agent 登录、Store 脱敏登录、商品读取、订单只读；不得创建真实支付、退款或提现事实。
4. 注入 Redis、数据库或 MinIO 单项故障，确认 readiness 返回 `503`、业务写入停止且日志不泄露敏感信息；恢复依赖后再次确认 `200`。
5. 验证日志、审计、Outbox、对象存储和数据库无测试残留；Redis 临时键和测试 bucket 必须精确清理。

## 回滚与 Go/No-Go

- 迁移、权限、RLS、readiness、smoke、残留清理或敏感扫描任一失败：立即 `NO-GO`，停止切流，按 B16.2 恢复，不删除业务事实。
- 应用回退通过停止 B16 新增 readiness/导航依赖并运行兼容版本完成；不得删除迁移、账户、钱包、提现、佣金、审计或 Outbox 数据。
- 只有 dry-run、核心 smoke、依赖故障、恢复验证、敏感扫描和外部独立复审全部有记录，才可标记 B16 staging-ready。

## 证据模板

记录：候选 SHA、迁移 run/时间、快照或 PITR 标识、readiness 响应、smoke 摘要、故障注入结果、残留扫描、回滚结果、P0/P1 清单、外部复核人和未验证项。缺少 staging 项目或权限时，明确记录阻塞原因和最小手工步骤，不得记为通过。
