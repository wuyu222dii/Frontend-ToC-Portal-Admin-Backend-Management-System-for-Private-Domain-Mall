## 最小人工核对

仅使用已存在的脱敏 development 账号；本批没有修改正在使用的管理员或外部数据库。

1. 启动 API 和 Admin Web，在账户安全页先只生成预览：此时不应出现密码/MFA 输入；继续确认后才输入当前凭据。确认成功后旧会话失效，密码-only 可用原 TOTP 登录，TOTP 重置应进入重新绑定流程。
2. 预览后离页再返回：密码、MFA 和预览不得残留。确认时断网：页面应提示重新登录核对，不自动 refresh、重试或重复提交。该检查会改变选定测试账号的凭据，须先保留可用恢复路径。
3. CLI 使用目标、申请人、审批人 A、审批人 B 四个不同账号；申请人可执行，但不能审批。若需拒绝已经由 A/B 批准的工单，需要另一个尚未决定的合格管理员。

CLI 在仓库根目录执行，自动加载根 `.env`；环境必须明确指向脱敏 development。先完成一次受影响包构建，CLI 本身不再每次重复构建全仓 packages：

全新检出首次启动仍需按 README 完成依赖安装及 `pnpm build:packages`；下面命令用于已有工作环境的本批增量构建。

```sh
pnpm --filter @qingxu/database build
pnpm --filter @qingxu/api build
pnpm admin:offline-recovery request TARGET_ID REQUESTER_ID "Synthetic recovery" RECOVERY_CODE
pnpm admin:offline-recovery approve RECOVERY_ID APPROVER_A_ID "Synthetic approval" RECOVERY_CODE
pnpm admin:offline-recovery approve RECOVERY_ID APPROVER_B_ID "Synthetic approval" RECOVERY_CODE
pnpm admin:offline-recovery execute RECOVERY_ID REQUESTER_ID 3 RECOVERY_CODE
```

`3` 是示例工单版本，必须使用最后一次已提交输出中的 `version`，不能使用目标账号版本。省略最后一个参数默认 TOTP；每次认证都需新的时间步/恢复码。正常输出仅有结果码、工单 ID、状态、version/ETag 和到期时间，终态重试不得再次更改目标凭据。

非交互输入只接受 `OFFLINE_RECOVERY_OPERATOR_PASSWORD_FILE`、`OFFLINE_RECOVERY_OPERATOR_TOTP_FILE` 或 `OFFLINE_RECOVERY_OPERATOR_RECOVERY_CODE_FILE`，以及执行时的 `OFFLINE_RECOVERY_NEW_PASSWORD_FILE`。值只能是私有文件路径；文件须属于当前用户、为非符号链接的单硬链接常规文件，权限 `0600` 或更严格。不得把密码/MFA 放到命令参数、普通环境变量、reason 或日志中。

浏览器实际交互及隐藏 TTY 输入尚未执行，原因是未指定可供人工重置的现有脱敏账号及其凭据。第一批复审通过前不进入第二批；此处所有结果不改变 B16/B17 和 staging/production 的 `NO-GO`。
