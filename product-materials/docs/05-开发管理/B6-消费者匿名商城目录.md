## 3. CH-014 公开目录契约

### 3.1 公开资源边界

- B6 实现 5 个已有公开 GET：`/store/home`、`/store/categories`、`/store/brands`、`/store/products`、`/store/products/{product_id}`。
- 只返回 ACTIVE Product、Brand、Category 和 ACTIVE SKU。Product 须同时关联 ACTIVE Brand/Category 且至少有一个 ACTIVE SKU；SKU 零库存不隐藏。
- `StoreSkuView.is_salable` 为布尔值，`available_stock > 0` 才为 true；商品摘要同步返回 `is_salable`，任一 ACTIVE SKU 可售时才为 true。全 SKU 售罄的商品仍可浏览。
- 只有 READY/PUBLIC 且 purpose 符合使用场景的文件可进入投影。响应不得包含 `file_id`、管理 `status/version`、DRAFT/INACTIVE/ARCHIVED 记录、physical/locked 库存或其他管理字段。
- Banner PRODUCT target 必须仍能解析为当前公开 Product；失效 target 不修改 Banner 事实，只从首页公开投影排除。

### 3.2 查询与排序

- `/store/products.keyword` 只对 trim 后的 Product 名称进行大小写不敏感匹配，长度 1-200；不搜 SPU code、SKU code、品牌或分类名。
- 默认 `COMPREHENSIVE`：`is_hot DESC,is_new DESC,sales_count DESC,published_at DESC NULLS LAST,product_id ASC`。
- `HOT`：全生命周期支付成功数量减成功退款数量的净销量 DESC，`product_id ASC`。`NEWEST`：首次 `published_at DESC NULLS LAST`，`product_id ASC`。
- `PRICE_ASC/PRICE_DESC`：取公开 ACTIVE SKU 最低 `retail_price`，以 `product_id ASC` 打破平局。
- `/store/brands` 和 `/store/categories` 不接受 pagination，返回全部 ACTIVE 记录，固定 `sort_order ASC,id ASC`。

### 3.3 首页分区

`/store/home` 返回 `banners/categories/hot_products/new_products` 四个数组，以及对应的 `READY|UNAVAILABLE` 闭合分区状态。单区失败时该数组固定为空且总体响应仍为 200；四区全失败时才返回 500。

| 分区 | 上限 | 选取与排序 |
|---|---:|---|
| Banner | 10 | 当前有效公开投影，`sort_order ASC,id ASC` |
| 分类 | 8 | ACTIVE，`sort_order ASC,id ASC` |
| 热销 | 4 | 公开且 `is_hot=true`，净销量 DESC，`product_id ASC` |
| 新品 | 4 | 公开且 `is_new=true`，`published_at DESC NULLS LAST,product_id ASC` |

### 3.4 匿名限流

- 5 个 Store 公开 GET 共享 Redis 固定窗口：每个 HMAC 来源 IP 每 60 秒 120 次。
- 只保存不可逆 IP HMAC，不保存、记录或追踪原始 IP。
- 超限返回 429 和精确整数秒 `Retry-After`；Redis 超时、断连或脚本错误时 fail closed，不得降级为不限流。

## 5. 后续实施约束

- 使用独立 `StoreCatalogRepository`，不向管理端 `ProductCatalogRepository`、Banner 或 Inventory repository 混入公开投影逻辑。
- 同一请求在 Repeatable Read 快照中参数化查询分页、最低价和稳定排序，再批量装配图片、SKU、库存、品牌与分类，不使用 N+1。
- 库存与价格必须来自同一快照。缺失 `inventory_balance` 时 fail safe 为不可售，不将缺失记录当作无限库存或虚构 0/0 事实。
- H5 使用 `/api/v1` 代理；MP-Weixin 使用可选 `VITE_MINIAPP_API_BASE_URL`，非本地地址强制 HTTPS。
- 本地购物车以 `sku_id` 合并，数量上限 `min(99, available_stock)`；售罄/失效项不计入合计，结算只提示登录并保留购物车。

## 6. 验收与风险

### 6.1 必测矩阵

- API：公开访问、未知参数、非法 ULID、搜索 1/200 边界、五种排序、分页稳定、售罄商品、隐藏状态、文件失效、Banner 时窗/target、分区失败和 429。

- 前端：375/390/414/1024/1440，loading、empty、404、429、500、局部失败、慢请求、重复点击、图片解码和无横向溢出。
- 纵向：真实 H5 browser -> Nest -> PostgreSQL/MinIO，公开图片必须可读/可解码，结束后精确清理 fixture、对象与精确 Redis key。

### 6.2 保留风险

- 搜索模糊匹配和价格排序索引作为 staging 数量级 EXPLAIN 后的 P2；B6 不为此新增迁移。
- B5-C09 的 `inventory_reservation_item` 缺 SKU 前导索引与 ledger `business_id` 非唯一风险保留至订单/交易域，B6 只读不放大该风险。
- 无业务引用 READY/PUBLIC 素材回收与 storage origin allowlist 配置化仍为 P2；公开目录只使用当前有效关系，不按前缀盲删对象。
