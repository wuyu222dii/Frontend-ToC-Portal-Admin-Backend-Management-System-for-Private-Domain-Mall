## 4. CH-016 冻结契约

### 4.1 法律文本与登录

- 新增匿名 `GET /store/legal-documents`，服务端返回当前 `USER_AGREEMENT`、`PRIVACY_POLICY`、`PHONE_AUTHORIZATION` 三份必填权威版本快照。登录只提交前两份；手机号授权单独匹配第三份。响应为 `no-store`，并使用独立的每 HMAC 来源 IP 每分钟 120 次 Redis 固定窗口；Redis 异常 fail closed。
- 微信登录只接受服务端当前两份文档的精确同意元组：类型各出现一次、`accepted=true`、版本完全匹配。旧版本、缺项、重复项或未知版本不得创建账户、资料、协议记录或会话，返回 `CONSENT_VERSION_MISMATCH` 409。
- `code` 长度为 1-512，`candidate_token` 长度为 32-512，二者均为 write-only；不得进入日志、审计摘要、追踪、截图或幂等响应体。
- Store token 固定校验 `role=CUSTOMER`、`assurance=WECHAT`、`audience=qingxu-store`；管理员 token 继续校验 `role=SUPER_ADMIN`、`assurance=MFA`、`audience=qingxu-admin-web`，不得跨端接受。Provider 不进入 token claim，只用于服务端 code/手机号 Adapter 选择及持久化来源。
- B7 固定使用一个消费者微信 AppID，以 `(AppID, openid)` 作为身份语义。现有 `account.wechat_open_id` 的非空唯一约束只在该单 AppID 范围内成立；`wechat_union_id` 仅作可空元数据，不是唯一登录键，也不得据此自动合并账户。未来支持多个 AppID 必须另行登记变更并新增迁移，禁止复用当前唯一约束冒充复合身份键。
- access/refresh token、登录和 refresh 响应均 `Cache-Control: no-store, private` 与 `Pragma: no-cache`；refresh 必须轮换，旧 token 重放按公共会话安全规则撤销对应 session family。
- 登录、refresh、logout 等携带敏感凭据的写操作使用 `HASH_ONLY` 幂等，不缓存或重放 token 明文。

### 4.2 资料与账户手机号

- profile 查询只返回本人最小资料、掩码手机号状态和资源版本；profile、手机号及令牌响应统一禁止缓存。
- profile PATCH 和手机号授权/撤回均要求新的 `Idempotency-Key` 与 `If-Match`；版本冲突返回 409，不自动覆盖。
- 手机号请求只接受 `provider_credential` 与 `PHONE_AUTHORIZATION` 同意记录，客户端不得选择 Provider。服务端按环境选择 Provider，Mock 只允许 development/test。
- 账户手机号继续独立于地址手机号，可空且自愿授权；保存加密值、HMAC、尾号、服务端 Provider 来源、验证时间和协议版本。撤回或重新授权不改写历史订单/代理快照。

### 4.3 归因候选与服务代理

- 候选创建只接收 `invite_code + promotion_asset_id`；`invite_code` 长度固定 1-128，`promotion_asset_id` 必须是符合 Crockford ULID pattern 的 26 字符值。目标类型、目标 ID 和公开跳转由服务端从仍有效且匹配该邀请码/代理的推广物料解析，拒绝客户端覆盖。
- 有效候选必须返回 `public_target_url`。候选创建响应使用闭合三选一：未绑定时返回 candidate；已绑定时不创建候选并返回当前最小 service_agent；推广已不可归因但公开目标仍有效时返回 `attribution_eligible=false + public_target_url` 的 public_fallback。有效 candidate 分支中，无凭据匿名请求和 candidate-token 请求必须签发新的非空 32-512 字符 token，bearer 请求必须返回 null；已有绑定与 fallback 分支 token 始终为 null。
- 匿名 candidate token 只在创建当次返回，服务端仅保存用途隔离的 HMAC/哈希，且与幂等键、来源 IP 使用不同 domain/scope；TTL 固定 30 分钟并绑定候选事实。GET 查询不消费 token；新匿名候选仅能通过可选 `X-Candidate-Token` 定位并原子失效旧 token hash，登录迁移也原子失效 token hash，确认/拒绝消费迁移后的候选事实。未携带旧 token 时不采集设备标识强行关联，旧候选按 TTL 自然过期；绑定不匹配返回 `ATTRIBUTION_CANDIDATE_MISMATCH` 409。
- 候选创建和查询的可选认证严格 fail closed：同时携带 bearer 与候选 token 返回 `INVALID_ARGUMENT` 400；存在 Authorization 时只校验 `qingxu-store/CUSTOMER/WECHAT` bearer，否则存在候选 token 时必须校验该 token，任一无效或过期凭据均返回 401，禁止降级到另一凭据或匿名分支。仅创建接口在无凭据时走匿名分支；查询接口无凭据返回 401。
- 登录携带候选 token 时，在 `customer_profile/version` 串行根下把候选迁移到当前 CUSTOMER，并原子失效 token hash；同一客户并发候选最多保留一个有效事实。
- 确认和拒绝使用当前登录客户的有效候选并要求幂等；已存在长期绑定时不得覆盖。服务代理响应使用独立最小投影，仅返回 `agent_id/display_name/bound_at`，不得复用包含 customer/binding/version 的内部绑定 DTO。只要长期绑定仍为 `BOUND` 且未结束，即使代理已停用也继续返回该三字段而不暴露内部状态；停用仅阻止新候选、新绑定和未来订单归因，只有绑定结束或不存在时才返回 null。

### 4.4 同步账号注销

- 删除流程改为 `POST /store/privacy/deletion-requests/preview` 短时预览，加保留的 `POST /store/privacy/deletion-requests` 同步确认；删除旧 `GET /store/privacy/deletion-requests/current`，不再保留异步删除申请查询。
- preview 请求固定 `{acknowledged:true}`，始终以 200 返回同形的 `eligible/blockers/impacts/preview_token/confirmation_hash/expires_at/account_version`。`eligible=false` 时 token/hash/expiry 均为 null，不签发确认能力；只有 `eligible=true` 才返回空 blockers、32-512 字符 token、64 位小写十六进制 confirmation hash 和 5 分钟 expiry。blocker 类型闭合为 ORDER/AFTERSALE/PAYMENT/REFUND/FINANCIAL_ANOMALY，impact 类型闭合为撤销全部会话、结束服务代理绑定、使候选失效、匿名化账户资料、删除非交易 PII、匿名化代理历史和保留必要交易事实七类。
- confirm 请求固定为 `acknowledged=true + preview_token + confirmation_hash`，要求完全匹配的预览能力、新 `Idempotency-Key` 和 `If-Match`。确认事务重新检查未完成订单/售后、未结清支付/退款和财务异常；存在阻断时返回 `ACCOUNT_DELETION_BLOCKED` 422，且不消费成功事实、不部分注销。
- 无阻断时在同一事务完成账号去标识化、微信登录主体/凭据清除、账户手机号及允许硬删的个人数据清理、全部 session/refresh 撤销、候选失效、长期绑定结束、代理历史隐私投影匿名化和审计/幂等事实。交易、财务、协议与审计事实只按外部合规策略保留。
- confirm 使用 `HASH_ONLY`，成功只返回当次完成态和必要时间，不缓存、不重放完成响应，也不返回新的 token。旧 access/refresh 在事务提交后立即无效；重复请求只返回认证失效或已完成冲突，不提供 current 查询绕过重新鉴权。

### 4.6 运行时配置

- 现有 `AUTH_TOKEN_AUDIENCE=qingxu-admin-web` 继续只服务 B2 管理端；B7.1 新增 `STORE_AUTH_TOKEN_AUDIENCE=qingxu-store`，两个 audience 不得合并或互相接受。
- `STORE_IDENTITY_PROVIDER=MOCK|WECHAT` 和 `STORE_PHONE_PROVIDER=MOCK|WECHAT` 分别选择登录和手机号 Provider；`MOCK` 仅允许 test/development。production 选择 WECHAT 时缺少正式凭据必须启动失败，禁止回退 Mock。
- 单一消费者微信应用使用 `STORE_WECHAT_APP_ID` 和 `STORE_WECHAT_APP_SECRET`；WECHAT Provider 启用时二者必填，且 `STORE_WECHAT_APP_ID` 即 `(AppID, openid)` 身份语义中的固定 AppID。
- 用户协议使用 `STORE_USER_AGREEMENT_VERSION`、`STORE_USER_AGREEMENT_TITLE`、`STORE_USER_AGREEMENT_URL`；隐私政策使用 `STORE_PRIVACY_POLICY_VERSION`、`STORE_PRIVACY_POLICY_TITLE`、`STORE_PRIVACY_POLICY_URL`；手机号授权说明使用 `STORE_PHONE_AUTHORIZATION_VERSION`、`STORE_PHONE_AUTHORIZATION_TITLE`、`STORE_PHONE_AUTHORIZATION_URL`。三项 URL 均必须是 HTTPS。服务端据此生成 `/store/legal-documents` 快照，登录校验前两份，手机号授权校验第三份，客户端不得提供另一组“当前版本”。
- 法律文本限流固定为 `STORE_LEGAL_RATE_LIMIT_MAX=120`、`STORE_LEGAL_RATE_LIMIT_WINDOW_SECONDS=60`；登录限流固定为 `STORE_LOGIN_RATE_LIMIT_MAX=10`、`STORE_LOGIN_RATE_LIMIT_WINDOW_SECONDS=900`。两者均按 HMAC 来源 IP 使用 Redis 服务端时间，Redis 异常 fail closed。

## 7. 锁序、失败与回退

- 登录/候选迁移使用 identity/account -> customer profile -> candidate -> consent -> session -> audit/idempotency 的固定锁序；Provider 调用不得持有数据库锁。
- 资料与手机号写入使用 idempotency -> account/customer profile -> active phone -> consent -> audit 的固定顺序，并以 profile/account version 完成乐观锁。
- 候选确认使用 idempotency -> customer profile -> candidate -> current binding -> agent/invite/promotion validity -> audit/outbox；总部未来客户转移和订单归因继续以 customer profile 为串行根。
- 删除确认使用 idempotency/preview -> account/customer profile -> active business blocker facts -> sessions/identity/phone/candidate/binding/privacy projection -> audit/outbox；任何步骤失败整体回滚。该命令为 `HASH_ONLY`，不得缓存或重放成功响应。
- CH-016 尚未进入 B7.1 业务实现时，可整体回退文档、OpenAPI、生成 contracts、专项检查和静态原型；进入 B7.1 后只关闭对应 Store 身份/资料/归因/隐私路由和小程序导航，不执行数据库降级。
- 当前 Mock identity code 可重入；正式微信一次性 code Provider 准入前，必须在兑换前增加同幂等键 owner lease 或等效单所有者收敛，并补并发兑换测试。该 P2 不扩大 B7.1 的 Mock-only 边界。
