## 4. CH-020 冻结契约

### 4.1 版本、operation 与数据库

- 产品/PRD 基线：`v2.4.7 / CH-020`；OpenAPI：`2.4.7-ch020`。
- CH-020 专项实测为 173 paths / 198 operations / 198 unique operationId / 325 schemas / 703 schema refs / 2,665 local refs / 0 dangling refs，Redocly 0 warning。
- 保留既有 `POST /store/checkout/quotes`、`POST/GET /store/orders`、`GET /store/orders/{order_id}` 和 `POST /store/orders/{order_id}/cancel`；不在 B9 实现其后支付、物流或售后 operation。
- 两份 `0001_initial` 必须逐字节不变；新增 `0002_b9_inventory_fact_indexes`，不改变表、列、枚举、RLS 或权限边界。

### 4.2 报价请求与拒绝契约

- `CheckoutQuoteRequest` 必填 `source`、ULID `address_id` 和 1-100 个不重复 SKU；数量 1-99。`BUY_NOW` 必须恰好一项，`CART` 必须精确匹配当前服务端购物车的已选项。
- 报价批量投影脱敏地址摘要、商品/SKU/公开图片、价格、可售库存、行金额和总额；使用 Decimal 计算，B9 运费固定为 `0.00`。
- blocker 闭合为 `CART_SELECTION_CHANGED | ITEM_UNAVAILABLE | INSUFFICIENT_STOCK`。已知不可提交事实返回 HTTP 200 与 `can_submit=false`，但 `quote_token`、`confirmation_hash` 和 `expires_at` 均为 null；地址不存在或跨客户统一 404。
- 可提交报价签发 5 分钟无状态 HMAC 凭证，使用现有幂等密钥环按 `qingxu:store-checkout-quote:v1` 域派生，绑定 CUSTOMER、auth session、规范请求、地址版本、商品/SKU/价格/库存事实、quote ID 和过期时间。
- 报价 token、confirmation hash 与报价正文不得落数据库、Redis、日志、审计、Outbox 或幂等响应缓存。Quote 不使用幂等键。

### 4.3 下单、幂等和库存预占

- `OrderSubmitRequest` 重复与报价精确相同的 source/address/items，并必填 ULID `quote_id`、`quote_token` 和 64 位小写十六进制 `confirmation_hash`。
- 下单在 Serializable 事务中重验 token、地址、购物车、品牌/分类/商品/SKU、公开主图、价格和库存。任一事实漂移返回 409，不创建任何订单或预占事实。
- 首次下单没有既有 order 且 B9 不创建 payment intent，锁序固定为 `idempotency -> account/customer -> CART/cart items（仅 CART）-> address -> binding/agent -> brand -> category -> product -> SKU ID ASC -> inventory_balance ID ASC -> insert order/reservation/snapshots -> ledger -> audit/outbox`。候选 SKU ID 可无锁预读但只用于定位；锁内必须按序重验状态、版本和归属，全部共享前级事实通过后才插入订单与预占。
- 订单号固定为 `QX` + order ULID。创建保存订单项快照，将 B8 地址明文以订单地址快照独立 AAD 重新加密，写归因候选但不冻结最终代理/佣金。
- 事务以数据库时间创建 ACTIVE reservation/items，原子增加 `inventory_balance.locked_qty`，写入 `business_id=reservation_id` 的唯一 `ORDER_RESERVE` 流水。数据库保持 `pay_expires_at=created_at+30 分钟`。
- CART 成功后只删除本次提交的已选项，保留未选项；BUY_NOW 不修改购物车。
- 创建返回 201，创建/取消使用 `HASH_ONLY`。完整幂等重放先于 token 过期或 `If-Match` 验证，重新鉴权后返回同一资源的当前投影，不缓存 PII 响应。

### 4.4 查询、取消与超时释放

- 列表与详情仅允许订单所有者读取，跨客户统一 404；列表按 `created_at DESC,id DESC` 稳定分页。B9 只返回 `CANCEL` 动作，支付、物流、退款和售后集合为空。
- 取消必须携带 `If-Match` 和幂等键，不携带原因请求体。仅未过期、待付款且无任何 payment intent 的订单可取消；已用户取消的新键重复请求返回当前投影，其他状态返回 `ORDER_NOT_CANCELLABLE` 409。
- 主动取消将 reservation 置为 `RELEASED`，订单置为 `CLOSED/USER_CANCELLED`；超时 Worker 将 reservation 置为 `EXPIRED`，订单置为 `CLOSED/PAYMENT_TIMEOUT`。B9 关单不推进履约轴，`fulfillment_status` 必须保持 `NOT_STARTED`，不得改为 `CANCELLED`。
- 两条路径使用同一原子关闭逻辑。无锁预读 reservation/SKU ID 后，严格按 `idempotency（Worker 跳过） -> order -> payment_intent -> SKU ID ASC -> inventory_balance ID ASC -> inventory_reservation ID ASC -> ledger -> audit/outbox` 加锁与重验，再减少 `locked_qty`、写唯一 `ORDER_RELEASE` 流水、audit 和 `order.closed` Outbox；不得先锁 reservation 再回头锁 SKU/balance。
- Worker 使用数据库当前时间与 `FOR UPDATE SKIP LOCKED`领取到期订单，复用现有 poll/batch/retry 配置，不增加 Redis lease。发现任何 payment intent 时不释放库存，留给 B10 对账/关闭逻辑。

### 4.5 错误、缓存、限流与敏感数据

- 新增 `CHECKOUT_QUOTE_EXPIRED`、`CHECKOUT_QUOTE_MISMATCH`、`CHECKOUT_REQUOTE_REQUIRED`、`ORDER_NOT_CANCELLABLE`，均为 HTTP 409。
- 五个 B9 operation 均要求 CUSTOMER 鉴权，共享 B8 的 CUSTOMER+来源 IP HMAC 120/60 固定窗口限流；Redis 异常必须 fail closed。
- 个性化成功与 JSON 错误均设置 `Cache-Control: no-store, private` 与 `Pragma: no-cache`。
- 姓名、手机号、地址、报价 token/hash 不得进入日志、审计、幂等响应正文或 Outbox；审计仅记录主体、资源 ID、版本、状态和金额摘要。

## 5. B5-C09 和前向迁移

- 新增 `inventory_reservation_item(sku_id,reservation_id)` 普通索引，保证按 SKU 查找活动预占时不扫描无关预占项。
- 新增 `inventory_ledger(business_id,sku_id,ledger_type) WHERE business_id IS NOT NULL` 条件唯一索引，保证同一 reservation/SKU/流水类型只能应用一次；`ORDER_RESERVE` 和 `ORDER_RELEASE` 可共用 business ID，但 ledger type 不同。
